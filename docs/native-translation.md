# 말한 뜻을 유지하는 자연스러운 번역 받아쓰기

받아쓰기 출력 언어를 **영어·일본어·한국어**로 고르면 평소 받아쓰기 단축키로 말한 내용이 선택한 언어로 입력됩니다. 기본값 **말한 언어 유지**는 기존처럼 말한 언어로 문장만 정리합니다. 기존 번역 단축키와 그 단축키의 번역 언어 설정은 따로 유지합니다.

**설정 → 입력·단축키 → 받아쓰기 출력 언어 → 언어 선택·예시 보기…**에서 원문과 고정 번역 예시를 비교하고 **적용**을 누르세요. 예시 언어를 둘러보거나 닫기·취소·Escape로 나오는 동안 설정은 바뀌지 않습니다. 예시는 녹음·AI 호출 없이 보여 주는 합성 문장입니다.

적용한 언어는 다음 녹음부터 사용합니다. 이미 시작한 녹음은 시작할 때 선택한 언어·모델·사전·말투를 끝까지 사용합니다. 화면 언어, 음성 인식 언어, 출력 언어는 각각 독립입니다.

## 번역 방향

단어 순서를 옮기는 대신, 누가 무엇을 요청하거나 주장하는지와 조건·뉘앙스를 파악한 뒤 목표 언어의 자연스러운 문장으로 표현하도록 요청합니다. 예를 들어 “혹시 시간 괜찮으시면 이 부분 좀 봐주실 수 있을까요? 급한 건 아니에요.”는 영어로 “Could you take a look at this when you get a chance? There's no rush.”, 일본어로 “お時間があるときに、こちらを確認していただけますか。急ぎではありません。”처럼 전달하는 방향입니다. 이것들은 작성한 참고 예시이며 유일한 정답 문장은 아닙니다.

번역은 서로 다른 모든 정보를 유지하도록 설계했습니다. 숫자·날짜·단위·이름·조건·예외·부정·미확정·약속의 강도를 보존하고, 모호한 주어·관계·성별을 추정하지 않도록 요청합니다. “가능할 것 같아요”를 “반드시 하겠습니다”로 바꾸거나, “승인 전에는 공유하지 마세요”에서 금지를 없애는 변경은 허용하지 않습니다. 일반 대사 인용은 발화자와 요청·질문의 종류를 유지해 목표 언어로 옮기도록 요청합니다. 코드 식별자·URL·그대로 보존하라고 지정한 이름이나 표기는 정확히 유지하며, 인용부호만으로 일반 대사를 복사하지 않도록 구별합니다.

사람이 한 말을 따옴표로 인용하면 그 대사를 번역하고, 프로그램에 넣을 상수 문자열의 글자를 그대로 두라고 지정하면 그 문자열을 보존합니다. 두 경우 모두 주변 문장은 목표 언어로 옮기도록 요청합니다. 인용 속 화자의 말투도 이야기하는 사람의 말투와 구분해 유지하도록 요청합니다.

말투 기본값은 말한 반말·존댓말의 관계와 공손함을 자연스럽게 전달하도록 요청합니다. 일본어에서는 한국어의 조사·주어·존대 구조를 기계적으로 옮기거나, 말하지 않은 상하 관계를 가정해 과한 경어를 추가하지 않도록 요청합니다. 사용자가 앱별 말투에서 반말·존댓말·격식을 명시적으로 선택하면 해당 설정을 적용하되, 요청·제안·약속의 종류와 강도는 유지하도록 요청합니다.

번역에서는 받아쓰기의 **요약·창작·편집 강도**를 적용하지 않습니다. 자연스러운 의역이 내용을 줄이거나 사실을 추가하는 권한으로 사용되지 않도록 분리했습니다. 이미 목표 언어로 말한 내용은 같은 의미·말투를 유지해 자연스럽게 정리합니다.

## 처리와 복구

음성을 글로 인식한 뒤 기존 문장 처리 요청 한 번으로 번역합니다. 번역만을 위한 별도 정리 요청이나 자동 평가 요청을 추가하지 않습니다. 로컬 음성 인식을 켜도 번역 단계는 선택한 클라우드 문장 제공자를 사용합니다.

음성 인식 제공자와 문장 처리 제공자는 각각 설정할 수 있습니다. 예를 들어 Groq로 음성을 인식하고 OpenRouter로 번역할 수 있습니다. 문장 제공자·모델을 바꾸면 번역뿐 아니라 일반 받아쓰기 정리와 선택 문장 수정에도 적용됩니다. 제공자를 바꾼 뒤 사용할 문장 모델도 확인하세요. 모델 안내의 이전 합성 받아쓰기 비교 결과는 번역 품질 통과를 뜻하지 않습니다.

번역 요청이 실패하거나 빈 결과가 돌아오면 인식 원문을 대신 자동 입력하지 않습니다. 기존 실패 녹음 보관 정책에 따라 다시 처리할 수 있습니다. **같은 설정으로 다시 처리**하면 당시 출력 언어를 사용합니다. **현재 설정으로 복구**하면 받아쓰기 녹음은 현재 받아쓰기 출력 언어를, 별도 번역 단축키의 녹음은 현재 번역할 언어를 사용합니다. 복구한 결과는 확인한 뒤 원하는 입력창에 복사합니다.

**최근 결과**에는 번역이 끝났을 때의 출력 언어를 표시합니다. 이후 설정에서 언어를 바꿔도 이미 만든 결과의 언어 표시는 바뀌지 않습니다. **인식 원문과 비교**로 발화와 결과를 함께 보거나 **최근 결과를 Jev로 검토…**로 직접 검토를 요청할 수 있습니다.

기록에는 당시 출력 언어와 목표 언어를 보관합니다. 기록의 **다시 처리**는 현재 언어·모델·사전·말투로 새 미리보기를 만들며, 저장된 원문과 결과는 유지합니다. 받아쓰기 번역과 별도 번역 단축키의 기록 모두 **보관된 결과를 Jev로 검토…**로 당시 언어에 맞게 검토할 수 있습니다. 당시 언어 정보가 없거나 확인할 수 없는 번역 기록은 언어를 추정하지 않으며, 현재 설정으로 다시 처리한 미리보기를 검토할 수 있습니다.

자동 Jev 검토·교정과 교정 학습은 말한 언어 유지 받아쓰기에 적용하며, 번역에는 직접 검토를 사용합니다. 출력 언어 표시와 직접 검토 기능은 결과를 확인하는 수단이며 모델의 번역 품질이나 의미 보존을 보장하지 않습니다.

직접 검토는 원문과 번역을 비교한 평가를 보여 줍니다. 번역문을 자동으로 수정·입력하거나 보관된 결과를 덮어쓰지 않습니다.

## 품질 확인 범위

[16개 번역 명세](fixtures/native-translation.json)는 한국어→영어·일본어, 영어→한국어, 이미 목표 언어인 문장, 완곡한 요청, 일본어 말투, 숫자·조건·부정·식별자와 지시문처럼 들리는 발화의 사례입니다. 원문과 참고 번역은 Codex가 작성한 합성 참고 예문이며, 실제 모델 호출 결과나 원어민 사람의 검수·판정 결과가 아닙니다. 자연스러움은 여러 문장이 정답일 수 있으므로 참고 문장과 글자 일치로 평가하지 않습니다.

2026-10-05의 이전 코드 `2efd5e8` / Groq `openai/gpt-oss-120b` / `medium` 실제 호출에서는 기존 19개와 새 합성 사례 3개, 총 22개 모두 HTTP 200 및 JSON 파싱에 성공했습니다. 첫 HTTP 503 두 건은 재시도로 복구했습니다. **파싱 성공은 번역 품질 통과를 뜻하지 않습니다.** Codex의 독립 판독에서 원문에 없는 수행 주체·오전/오후·변수명 문자 변경 등 의미 보존 실패 6개가 확인됐고, 일본어 직역 표현도 남았습니다.

같은 입력·모델·프롬프트의 선별 10개를 별도 `high` 후보로 비교했습니다. 모두 파싱 성공했고 같은 10개에서 명확한 의미 실패는 `medium` 5개, `high` 2개였습니다. 그러나 생략 주체 추정이 남았고 다른 사례에 오후 추정이 새로 생겼습니다. 제품은 `medium`을 유지합니다. 이 판독은 합성 문장·각 1회 결과에 대한 Codex 검토이며 원어민 사람의 검수가 아닙니다.

후속 구현은 생략된 수행자와 화자의 판단을 구별하는 번역 지침을 보강하고, 명확한 코드 표기 손상과 제한된 오전·오후 추가를 입력 전에 거부합니다. 일반 인용문 번역과 정상 시각 표기를 허용하며 모든 의미 오류를 검출한다고 주장하지 않습니다. 검사의 구체적 범위와 전체 처리 구조는 [기능 설계](native-translation-design.md)에 기록했습니다. 새 구현의 실제 출력·차단 수와 언어별 품질은 이전 실측과 구분하여 기능 PR의 검증 결과에 기록합니다.

인용 정책 수정 전 소스 `0ed0594`의 후속 합성 텍스트 32개는 모두 한 번의 HTTP 200 응답을 받았고, 29개가 반환됐으며 원문에 없는 오전·오후를 추가한 것으로 검사된 3개가 입력 전에 차단됐습니다. 반환 출력에서 수행자 추가 2개·일반 대사 미번역 1개가 확인됐고, 최종 정정 값은 맞지만 말실수 흔적을 남긴 사례 1개도 있었습니다. 합성 음성 3개는 실제 음성 인식→번역 API를 완료하고 주요 내용·수치·부정을 유지했습니다. 실제 마이크·대상 앱 입력·원어민 검수와는 별도 근거입니다. 세부 분류와 후속 후보 상태는 [실측 기록](native-translation-evaluation.md)에 있습니다.

여러 지침을 함께 바꾼 후보 v5 전체는 채택하지 않았고, 일반 대사와 명시 리터럴의 보호 범위만 구별한 수정 v6를 채택했습니다. 같은 모델·`medium`의 알려진 합성 회귀 6개 반환에서 일반 대사는 일본어로 번역되고 명시 코드 문자열은 유지되는 경계를 관측했습니다. 다만 GC401의 캐주얼 대사는 공손하게 바뀌었고, GC404는 최종 코드 값만 정확히 남겼지만 원문에 근거한 정정 설명은 남았습니다. 새 합성 대조 2개 중 하나는 HTTP 429 두 차례로 출력이 없었고 다른 하나는 호출되지 않아 품질을 평가하지 못했습니다. 이 수정으로 수행자 추정이 해결됐거나 전체 번역이 자연스러움·의미 보존을 통과했다고 주장하지 않습니다.

화면 검증은 별도 합성 미리보기 런타임에서 진행했습니다. 로컬 Debug 앱에서는 설정 적용·취소 경계와 결과 언어·기록의 검토 확인창을 확인했고, `0ed0594` CI 개발 앱에서는 당시 언어와 원문·번역 표시를 확인했습니다. 실제 마이크 녹음·대상 앱 입력·Jev 요청 실행의 검증은 아닙니다. 검증 당시 개발 앱은 0.2.1(build29)이었고 설치본 0.1.26(build28)은 교체하지 않았습니다.

[추가 회귀 명세 10개](fixtures/native-translation-regression.json)는 일반 대사와 정확한 코드 문자열, 미지정·명시된 수행자, 허가 질문, 날짜 역할, 자기정정을 구별합니다. 고정 정답 문장이나 실제 모델의 품질 통과 결과가 아니라 보존해야 할 조건을 기록한 합성 명세입니다.

2026-10-06에는 같은 합성 입력 26개로 제품 지침과 compact 후보를 OpenRouter에서 비교하고 Groq에서도 비교를 시도했습니다. Luna 후보는 일부 표기·의미 보존을 개선했지만 수행자 추정과 정정 흔적이 남아 채택하지 않았습니다. Groq 후보는 API 제한으로 출력이 없어 품질 미평가입니다. 번역에만 추론을 켜는 추가 후보는 인증 시간 초과로 아직 실제 호출되지 않았습니다. 현재까지의 반환·차단·미호출과 다음 검증 범위는 [실측 기록](native-translation-evaluation.md)에 구별해 기록했습니다.

실제 프로덕션 프롬프트를 API 호출 없이 내보내려면 다음을 사용합니다.

```sh
python3 scripts/export-cleanup-prompts.py \
  --fixtures docs/fixtures/native-translation.json \
  --output build/native-translation-prompts.json
```

이 검사는 실제 Swift 소스로 요청을 구성하고 인식 원문·출력 언어·프로필 경계를 확인할 수 있게 합니다. API 키·마이크·사용자의 실제 녹음은 사용하지 않습니다. 자동 테스트 통과나 프롬프트의 지시 자체가 모델의 모든 출력에서 자연스러움·의미 보존을 보장하는 것은 아닙니다.

실제 모델 비교에서는 동일한 합성 발화와 설정을 사용하고 목표 언어 원어민이 다음 항목을 함께 판단해야 합니다.

- 숫자·이름·시점·부정·조건·미확정이 모두 남아 있는지.
- 요청·희망·제안·약속의 종류와 강도가 같은지.
- 목표 언어의 문장 순서·관용 표현·말투가 자연스러운지.
- 불필요한 직역, 없는 사실·인사말·서명·관계가 추가되지 않았는지.
- 인식 오류가 번역 오류로 이어졌는지, 원어민이 말하는 자연 발화에서도 같은 기준을 만족하는지.

프로덕션 통합 XCTest는 XCTest를 제공하는 전체 Xcode 환경에서 실행해야 합니다. Command Line Tools만 설치된 환경의 Swift 구문 검사·프롬프트 내보내기는 통합 테스트와 별도의 근거입니다. 실제 마이크와 대상 앱 삽입 검증, 원어민 자연스러움 검토도 별도로 기록합니다.
