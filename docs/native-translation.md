# 말한 뜻을 유지하는 자연스러운 번역 받아쓰기

받아쓰기 출력 언어를 **영어·일본어·한국어**로 고르면 평소 받아쓰기 단축키로 말한 내용이 선택한 언어로 입력됩니다. 기본값 **말한 언어 유지**는 기존처럼 말한 언어로 문장만 정리합니다. 기존 번역 단축키와 그 단축키의 번역 언어 설정은 따로 유지합니다.

**설정 → 입력·단축키 → 받아쓰기 출력 언어 → 언어 선택·예시 보기…**에서 원문과 고정 번역 예시를 비교하고 **적용**을 누르세요. 예시 언어를 둘러보거나 닫기·취소·Escape로 나오는 동안 설정은 바뀌지 않습니다. 예시는 녹음·AI 호출 없이 보여 주는 합성 문장입니다.

적용한 언어는 다음 녹음부터 사용합니다. 이미 시작한 녹음은 시작할 때 선택한 언어·모델·사전·말투를 끝까지 사용합니다. 화면 언어, 음성 인식 언어, 출력 언어는 각각 독립입니다.

## 번역 방향

단어 순서를 옮기는 대신, 누가 무엇을 요청하거나 주장하는지와 조건·뉘앙스를 파악한 뒤 목표 언어의 자연스러운 문장으로 표현하도록 요청합니다. 예를 들어 “혹시 시간 괜찮으시면 이 부분 좀 봐주실 수 있을까요? 급한 건 아니에요.”는 영어로 “Could you take a look at this when you get a chance? There's no rush.”, 일본어로 “お時間があるときに、こちらを確認していただけますか。急ぎではありません。”처럼 전달하는 방향입니다. 이것들은 작성한 참고 예시이며 유일한 정답 문장은 아닙니다.

번역은 서로 다른 모든 정보를 유지하도록 설계했습니다. 숫자·날짜·단위·이름·조건·예외·부정·미확정·약속의 강도를 보존하고, 모호한 주어·관계·성별을 추정하지 않도록 요청합니다. “가능할 것 같아요”를 “반드시 하겠습니다”로 바꾸거나, “승인 전에는 공유하지 마세요”에서 금지를 없애는 변경은 허용하지 않습니다. 일반 대사 인용은 발화자와 요청·질문의 종류를 유지해 목표 언어로 옮기도록 요청합니다. 코드 식별자·URL·그대로 보존하라고 지정한 이름이나 표기는 정확히 유지하며, 인용부호만으로 일반 대사를 복사하지 않도록 구별합니다.

사람이 한 말을 따옴표로 인용하면 그 대사를 번역하고, 프로그램에 넣을 상수 문자열의 글자를 그대로 두라고 지정하면 그 문자열을 보존합니다. 두 경우 모두 주변 문장은 목표 언어로 옮기도록 요청합니다. 인용 속 화자의 말투도 이야기하는 사람의 말투와 구분해 유지하도록 요청합니다.

말투 기본값은 말한 반말·존댓말의 관계와 공손함을 자연스럽게 전달하도록 요청합니다. 일본어에서는 한국어의 조사·주어·존대 구조를 기계적으로 옮기거나, 말하지 않은 상하 관계를 가정해 과한 경어를 추가하지 않도록 요청합니다. 사용자가 앱별 말투에서 반말·존댓말·격식을 명시적으로 선택하면 해당 설정을 적용하되, 요청·제안·약속의 종류와 강도는 유지하도록 요청합니다.

번역에서는 받아쓰기의 **요약·창작·편집 강도**를 적용하지 않습니다. 자연스러운 의역이 내용을 줄이거나 사실을 추가하는 권한으로 사용되지 않도록 분리했습니다. 이미 목표 언어로 말한 내용은 같은 의미·말투를 유지해 자연스럽게 정리합니다.

## 처리와 복구

음성을 글로 인식한 뒤 기존 문장 처리 요청 한 번으로 번역합니다. 번역만을 위한 별도 정리 요청이나 자동 평가 요청을 추가하지 않습니다. 뜻을 자동으로 교정하기 위한 재번역 요청도 추가하지 않습니다. 로컬 음성 인식을 켜도 번역 단계는 선택한 클라우드 문장 제공자를 사용합니다.

음성 인식 제공자와 문장 처리 제공자는 각각 설정할 수 있습니다. 예를 들어 Groq로 음성을 인식하고 OpenRouter로 번역할 수 있습니다. 문장 제공자·모델을 바꾸면 번역뿐 아니라 일반 받아쓰기 정리와 선택 문장 수정에도 적용됩니다. 제공자를 바꾼 뒤 사용할 문장 모델도 확인하세요. 모델 안내의 이전 합성 받아쓰기 비교 결과는 번역 품질 통과를 뜻하지 않습니다. 이번 지침 보강은 기본 제공자·모델이나 이미 선택한 사용자 설정을 자동으로 바꾸지 않습니다. 제공자와 모델에 따라 표현·처리 시간·비용이 달라질 수 있습니다.

OpenRouter에서 Luna (`openai/gpt-6-luna`)를 직접 선택한 경우 번역 요청에만 `medium` 추론이 적용되며, 같은 모델의 일반 받아쓰기·선택 문장 수정은 기존 `none`을 유지합니다. 추론으로 처리 시간과 비용이 늘어날 수 있습니다.

번역 요청이 실패하거나 빈 결과가 돌아오면 인식 원문을 대신 자동 입력하지 않습니다. 기존 실패 녹음 보관 정책에 따라 다시 처리할 수 있습니다. **같은 설정으로 다시 처리**하면 당시 출력 언어를 사용합니다. **현재 설정으로 복구**하면 받아쓰기 녹음은 현재 받아쓰기 출력 언어를, 별도 번역 단축키의 녹음은 현재 번역할 언어를 사용합니다. 복구한 결과는 확인한 뒤 원하는 입력창에 복사합니다.

**최근 결과**에는 번역이 끝났을 때의 출력 언어를 표시합니다. 이후 설정에서 언어를 바꿔도 이미 만든 결과의 언어 표시는 바뀌지 않습니다. **인식 원문과 비교**로 발화와 결과를 함께 보거나 **최근 결과를 Jev로 검토…**로 직접 검토를 요청할 수 있습니다.

기록에는 당시 출력 언어와 목표 언어를 보관합니다. 기록의 **다시 처리**는 현재 언어·모델·사전·말투로 새 미리보기를 만들며, 저장된 원문과 결과는 유지합니다. 받아쓰기 번역과 별도 번역 단축키의 기록 모두 **보관된 결과를 Jev로 검토…**로 당시 언어에 맞게 검토할 수 있습니다. 당시 언어 정보가 없거나 확인할 수 없는 번역 기록은 언어를 추정하지 않으며, 현재 설정으로 다시 처리한 미리보기를 검토할 수 있습니다.

자동 Jev 검토·교정과 교정 학습은 말한 언어 유지 받아쓰기에 적용하며, 번역에는 직접 검토를 사용합니다. 출력 언어 표시와 직접 검토 기능은 결과를 확인하는 수단이며 모델의 번역 품질이나 의미 보존을 보장하지 않습니다.

직접 검토는 원문과 번역을 비교한 평가를 보여 줍니다. 번역문을 자동으로 수정·입력하거나 보관된 결과를 덮어쓰지 않습니다.

## 품질 확인 범위

번역은 숫자·이름·시점·조건·부정·미확정·요청과 약속의 강도를 유지하면서 목표 언어의 자연스러운 문장으로 전달하도록 요청합니다. 원문에서 뒷받침되지 않는 수행자·관계·성별·위계를 추정하거나 자연스럽게 보이기 위해 새 내용을 만들도록 허용하지 않습니다. 다의어는 명시된 분야·수량·통화·실제 활동을 근거로 해석하고, 구체 분야가 없으면 뜻을 임의로 좁히지 않는 방향입니다. 모든 AI 생성이 이 요청을 지킨다는 보장은 아닙니다.

명확한 현재 자기정정은 최종 값을 사용하고 취소된 값과 순수 말실수 설명을 정리하도록 요청합니다. 실제 과거 정정 활동, 변경의 독립 이유, 유효한 조건·요청은 별도 내용으로 유지해야 합니다. 일반 대사는 발화자와 요청·질문의 종류를 유지해 번역하고, 그대로 두라고 지정한 코드 문자열·표기는 정확히 보존하도록 구별합니다.

말투 기본값에서는 인용 화자와 이야기하는 사람의 반말·존댓말을 각각 읽어 전달하도록 요청합니다. 사용자가 반말·존댓말·격식을 명시하면 해당 설정을 적용할 수 있지만 화자 귀속과 요청·제안·약속의 종류와 강도는 유지해야 합니다. 말투 설정이 인용의 모든 표현을 동일한 말투로 바꾼다는 보장은 아닙니다. 번역에서는 요약·창작 강도를 적용하지 않습니다.

음성 인식과 문장 처리 제공자는 각각 선택할 수 있어 Groq 전사와 OpenRouter 문장 처리를 함께 사용할 수 있습니다. 문장 모델은 번역뿐 아니라 일반 받아쓰기 정리와 선택 문장 수정에도 적용됩니다. 번역 전용 제공자 설정이나 자동 기본 모델 변경을 추가한 것은 아닙니다. 모델 설명의 이전 합성 받아쓰기 비교 결과는 번역 품질 통과나 추천을 뜻하지 않습니다.

[16개 번역 명세](fixtures/native-translation.json)와 [추가 회귀 명세](fixtures/native-translation-regression.json)는 Codex가 작성한 합성 입력·참고 예문·보존 조건입니다. 실제 모델 호출 결과나 원어민 사람의 검수 결과가 아니며, 자연스러운 번역을 단일 참고 문장과의 글자 일치로 평가하지 않습니다.

고정 합성 명세와 실제 호출 결과는 구분합니다. 참고 예문은 유일한 정답 문장이 아니며 HTTP·JSON 파싱·보호 검사 통과도 뜻 보존과 자연스러움의 합격 판정이 아닙니다. 출력이 차단돼 저장되지 않으면 해당 언어 품질은 미평가입니다. 보호 검사는 제한된 표기·시간 오류의 입력을 막는 장치이며 모든 의미 오류를 검출하지 않습니다.

2026-10-06의 최신 v11 지침을 OpenRouter `openai/gpt-6-luna`, `medium`으로 호출한 합성 텍스트 48개는 모두 한 번의 HTTP200 응답과 출력이 돌아왔습니다. Codex 독립 판독에서는 이 48개에서 명확한 의미 오류를 식별하지 않았고, 앞선 v10에서 수량 문맥의 `total`을 `총액`으로 좁혔던 사례는 `요약의 합계`로 돌아왔습니다. 새 수량·금액·분야 미지정 대조에서도 해당 의미 경계를 관찰했습니다. 다만 취소된 수량을 `not two`로 남긴 정정 cleanup 미충족 1건, 일본어 문장 결합과 모호한 장소·심리 상태의 해석 주의가 남았습니다. 기존 26개·추가 6개·인용·말투 대조 8개·정정 대조 4개·어휘 대조 4개는 별도 기준과 분모로 판독했으며 전체 원어민 자연스러움 통과율로 합산하지 않습니다.

같은 지침의 OpenRouter 기존 기본 문장 모델 `openai/gpt-4.1-mini` 선별 12개도 모두 반환했지만, 취소된 변수명을 다시 선택지로 만들거나 천천히 걷기를 멈춤 요청으로 바꾸고 문서의 수정 위치를 누락한 의미 오류 3건이 있었습니다. 정정 흔적 미충족도 3건이며 그중 1건은 의미 오류와 겹치므로 독립 결함 수로 단순 합산하지 않습니다. 이 12개는 알려진 문제와 긍정 대조를 선택한 제한 사례이며 전체 모델 순위를 대표하지 않습니다. 모델별 결과 차이를 확인한 것이지 모든 모델이 같은 품질을 내거나 기본 모델의 품질이 완료됐다는 뜻이 아닙니다. 제공자·모델·사용자 설정은 자동 변경하지 않았습니다.

합성음성은 WAV 3개를 목표 언어가 다른 4개 작업에 사용해 실제 음성 인식→번역 API 결과를 확인했습니다. 원문→전사에서 식별된 의미 손실은 없었고 수량·공손한 요청·비긴급·부정·미정 조건의 주요 경계는 유지됐습니다. 한국어의 병렬 설명이 일본어의 이유 연결로 읽힐 수 있는 약한 담화 관계 주의는 따로 기록했습니다. 이 결과는 실제 사용자 마이크·잡음 환경·대상 앱 삽입 시험을 대신하지 않습니다.

실측은 합성 입력의 각 1회 출력에 대한 Codex 독립 판독이며 사람 원어민 검수가 아닙니다. 실제 upstream 모델 공급자를 고정하지 않았으므로 특정 지침 한 줄의 확정 인과 효과나 다음 출력의 품질 보장으로 확장하지 않습니다. 새 기능의 실제 사용자 마이크·대상 앱 삽입·사람 원어민 자연스러움 검증은 아직 완료하지 않았습니다. 별도 합성 미리보기 화면 확인과 합성음성 API는 서로 다른 근거입니다. 개발 앱 0.2.1(build29)과 설치본 0.1.26(build28)을 구분하며 설치본은 교체하지 않았습니다.

AI 모델에 따라 표현이 달라지거나 뜻·수량을 잘못 옮길 수 있습니다. 최근 결과와 기록에서 원문·번역을 함께 확인할 수 있으며, 직접 Jev 검토는 평가를 보여 주고 번역문을 자동 수정·입력하거나 보관된 결과를 덮어쓰지 않습니다. 검사나 검토 기능도 품질 보장은 아닙니다.

상세 호출·반환·차단·미호출과 후보 상태는 [실측 기록](native-translation-evaluation.md), 검사 범위와 처리 구조는 [기능 설계](native-translation-design.md)에 기록합니다. 최신 가격과 비교 예산 예약은 비용 추정이며 최종 청구액 보장과는 별개입니다.

실제 프로덕션 프롬프트를 API 호출 없이 내보내려면 다음을 사용합니다.

```sh
python3 scripts/export-cleanup-prompts.py \
  --fixtures docs/fixtures/native-translation.json \
  --output build/native-translation-prompts.json
```

이 검사는 실제 Swift 소스로 요청을 구성하고 인식 원문·출력 언어·프로필 경계를 확인할 수 있게 합니다. API 키·마이크·사용자의 실제 녹음은 사용하지 않습니다. 자동 테스트 통과나 프롬프트의 지시 자체가 모델의 모든 출력에서 자연스러움·의미 보존을 보장하는 것은 아닙니다.

실제 모델 비교에서는 동일한 합성 발화와 설정을 사용하고 목표 언어 원어민이 다음 항목을 함께 판단해야 합니다.

- 숫자·이름·시점·부정·조건·미확정이 모두 남아 있는지.
- 요청·희망·제안·약속의 종류와 강도가 같은지.
- 목표 언어의 문장 순서·관용 표현·말투가 자연스러운지.
- 불필요한 직역, 없는 사실·인사말·서명·관계가 추가되지 않았는지.
- 인식 오류가 번역 오류로 이어졌는지, 원어민이 말하는 자연 발화에서도 같은 기준을 만족하는지.

프로덕션 통합 XCTest는 XCTest를 제공하는 전체 Xcode 환경에서 실행해야 합니다. Command Line Tools만 설치된 환경의 Swift 구문 검사·프롬프트 내보내기는 통합 테스트와 별도의 근거입니다. 실제 마이크와 대상 앱 삽입 검증, 원어민 자연스러움 검토도 별도로 기록합니다.
