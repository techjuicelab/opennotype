# 기본 받아쓰기의 재시작·추임새 정리 검증

이 문서는 **기본 faithful/0 받아쓰기**에서 동일한 명제의 재시작과 추임새를 정리하는 변경을 평가하기 위한 기준이다. creative·간결·요약 설정의 효과를 시험하지 않는다. [16개 합성 사례](../../fixtures/faithful-restarts.json)는 사람이 작성한 시험 명세이며 모델 출력이나 실제 음성 인식 결과가 아니다. FR01은 사용자가 설명한 A/B/C 예문을 그대로 사용했다.

이 문서는 **0.1.23 / build 25**의 판정 기준과 저장된 전후 합성 출력의 독립 판정을 기록한다. [압축 시험 근거](faithful-restarts-live.json.gz)에는 GPT-6 Luna 문장 요청 40회와 TypeSafe Jev 요청 6회의 정제된 보고서가 들어 있다. 실제 마이크와 자동 입력의 완료를 증명하지 않는다. 모델 결과를 본 뒤 유리하게 원문이나 기대 의미를 바꾸지 않는다. 보조 regex의 명백한 오류를 고치면 수정 이유와 이전 결과에 재적용했는지를 함께 기록한다.

## 판정 방법

출력마다 다음 두 축을 따로 평가한다.

1. **의미 보존**: 모든 독립 명제, 사실, 이름과 역할, 수치의 대상, 조건과 부정의 범위, 실제 사건 횟수, 불확실성, 강조, 희망과 직접 요청이 보존됐는가? 결과는 `보존 / 실패 / 판단 불가`로 기록한다.
2. **정리 품질**: 같은 의미의 불필요한 재시작, 명제 없는 추임새와 버린 구절을 정리했는가? 결과는 `완료 / 일부 잔존 / 실패 / 판단 불가`로 기록한다.

의미를 보존하면서 재시작이 남았다면 정리 품질만 미달이다. 재시작을 잘 지웠어도 희망을 명령으로 바꾸거나 새 조건을 잃으면 의미 보존 실패다. API 오류·잘린 응답·빈 결과·미완료는 성공으로 계산하지 않는다. `expected_text`는 가능한 올바른 표현의 예시이며 exact-match 정답이 아니다.

절마다 원문과 출력의 대응 관계를 확인한다. 동일한 이름이 여러 번 나왔다는 이유로 모든 참조를 고정하지 않는다. **같은 명제의 재시작만 합칠 수 있고, 그 이름에 연결된 독립적인 행동·조건·역할은 모두 남아야 한다.** 의도적인 강조와 반복된 실제 사건은 별도로 확인한다.

FR01에서는 B의 언급 3회가 예시의 2회로 줄어도 누락이 아니다. A를 개발하고 싶은 목적, 현재 B를 리서치하는 사실, B를 리서치할 때 C도 필요하다는 관계를 모두 유지해야 한다. 이 원문의 `그런데`는 앞의 리서치 설명에서 추가 필요 C로 넘어가는 전환이므로 `그리고`라는 단순 나열로 바꾸지 않는다. 다른 원문에서 정당하게 사용된 `그리고`를 전역 삭제하라는 규칙은 아니다.

regex 검사는 이 기준의 일부를 보조한다. 검사 통과 수를 전체 의미 정확도나 실제 음성 정확도로 제시하지 않는다. 조건의 적용 범위, 같은 행위자 여부, 직접 요청이 희망 문장에 흡수됐는지, 강조의 정도, 단순히 더 짧아진 것인지 등은 사람이 다시 확인한다. 숫자 검사는 `5`를 `15·50`과, `3`을 `13`과, `10`을 `110`과 혼동하지 않도록 경계를 둔다.

## 자동 입력 보호의 범위

이번 정리는 이름 참조의 불필요한 반복 감소를 허용하는 것과 숫자·인용 리터럴의 보호를 구분한다. FR06의 같은 `10초` 설명이나 FR11의 같은 인용 문구가 적힌 사실은 의미상 한 번으로 합칠 수 있다. 그러나 숫자·인용 전체의 반복 등장 횟수까지 자동으로 완화하지 않는 보수적 Jev 보호 설정에서는, 이런 정상 정리 결과도 수동 확인을 요구하거나 입력을 보류할 수 있다. 이 제한은 문장 생성 품질 판정과 별도로 기록한다.

특히 **인용 내부의 `retry retry`를 `retry`로 줄이는 것은 허용하지 않는다.** 서로 다른 수치의 값·단위·대상과 실제 사건 횟수도 유지해야 한다. 정상 생성 예시의 등장 횟수가 줄었다는 이유만으로 모든 숫자·인용 보호를 해제하지 않는다.

## 재현 및 결과 기록

API·키 접근 없이 fixture 검사만 실행한다.

```sh
python3 -m unittest scripts/test_faithful_restarts.py
```

기존 production 문장 비교 도구로 요청을 생성하는 dry run은 다음과 같다.

```sh
python3 scripts/compare-text-models.py \
  --fixtures docs/fixtures/faithful-restarts.json \
  --models openai/gpt-6-luna \
  --output build/faithful-cleanup-quality/dry-run.json
```

전후 비교에는 같은 16개 입력과 모델을 쓰고 두 production 소스의 해시를 각각 고정한다. 실제 API 호출은 별도 키 주입·예산 한도로 실행하며, 요청 지연과 비용은 해당 시험의 측정 결과만 기록한다. 이 문서의 합성 예시는 실제 마이크·자동 입력 검증을 대신하지 않는다.

## 전후 합성 문장 시험의 독립 판정

저장된 GPT-6 Luna 전후 출력 16개씩을 원문과 대조해 별도로 읽었다. 실제 음성은 보내지 않았으며 이 판정은 후처리용 합성 인식 텍스트에만 적용한다. 최신 fixture의 검사로 두 보고서의 결과를 다시 확인했으며 **기본 14/16, 수정 15/16**의 보조 검사 통과 수는 유지됐다. 자동 검사를 통과했다는 이유만으로 수동 의미 판정을 생략하지 않았다.

> 나는 A를 개발하고 싶어서 B를 리서치하고 있어요. B를 리서치하고 있는데요. 그런데 말이죠, B를 리서치할 때 또 필요한 것이 C인데요.

> 나는 A를 개발하고 싶어서 B를 리서치하고 있어요. 그런데 B를 리서치할 때 또 필요한 것이 C인데요.

A 개발 희망, 현재 B 리서치, B 리서치 때 C가 필요한 관계와 `그런데` 전환을 모두 유지했다. 단순히 B의 등장 횟수가 줄었다는 이유로 의미 누락으로 판정하지 않았다.

FR14의 문두 `Well`은 두 결과 모두 남아 합성 예시의 정리 목표와 보조 검사는 충족하지 않았다. 그러나 `Well`은 실제 발화에서 담화 연결 역할도 할 수 있어 의미 실패로 분류하거나 모든 `Well`의 강제 삭제를 유도하지 않는다. **남은 정리 한계를 명시하고 보수적으로 유지한다.** 이 관측을 유리하게 만들기 위해 시험 원문이나 자동 검사 기대값을 바꾸지 않았다.

FR06의 같은 10초 설명과 FR11의 같은 인용 문구가 적힌 사실의 반복은 의미상 정상적으로 합쳐졌다. 생성의 수동 의미 판정은 보존이지만, 앞서 설명한 숫자·인용 반복 횟수의 보수적 자동 입력 보호는 별도 한계로 남는다. 이번 시험으로 그 보호가 해제됐거나 실제 입력까지 완료됐다고 판단하지 않는다.

### 같은 사용자 예문의 반복 시험과 Jev 보호

같은 사용자 예문을 이전 production에서 4회, 최종 production에서 4회 더 시험했다. 최종 4회는 같은 B 리서치 명제의 재시작과 명제 없는 추임새를 모두 제거했다. 이는 **재시작 제거 4/4**라는 관측이며 모든 표현이 매번 정확히 같다는 결과가 아니다.

최종 `USER03`은 명시적인 `그런데`를 생략했고, `USER02/03/04`는 `또`도 생략했다. A 개발 목적·B 리서치·C 필요 사실은 유지했지만 원문의 명시적 전환·추가 연결 표현이 항상 같은 강도로 보존된다고 주장하지 않는다. 이 작은 반복 시험의 관계 표현 약화 가능성은 별도 한계로 남긴다. 최종 16개 묶음의 FR01은 `그런데`와 `또`를 모두 보존해 목표 예시와 정확히 일치했다.

중간 후보 4회 시험에서는 한 결과가 `그런데`를 `그리고`로 바꿔 관계를 약화하는 사례가 관측돼 전환 보존 계약을 보강했다. 이 중간 시험은 최종 압축 근거 묶음과 아래 40회 집계에 포함하지 않는다.

실제 TypeSafe Jev의 합성 보호 시험 6회도 production 요청·해석·repair 정책으로 확인했다.

| Jev 시험 경계 | 요청 수 | 관측된 production 판단 |
| --- | --- | --- |
| A/B/C 재시작, 제품명 재시작, 동일 이름의 같은 명제 반복 | 3 | 재교정 필요 없음, 정상 repair 수용 3/3 |
| 같은 이름의 별도 행동 누락, 부정 누락, 조건 누락 | 3 | 재교정 필요, 잘못된 repair 거부 3/3 |

이 시험은 이름 참조 횟수가 줄었다는 이유만으로 정상 재시작 정리를 다시 반복시키지 않으면서, 별도 행동·부정·조건이 사라지면 보호 신호를 유지하는지를 확인했다. Jev 확률은 이 6개 합성 비교의 관측이며 일반적인 오류 검출률이나 실제 음성의 정답 인증으로 제시하지 않는다. 숫자·인용 리터럴의 보수적 guard 한계는 유지된다.

압축 근거의 문장 요청 수는 사용자 예문 이전 4회 + 전후 16회씩 + 사용자 예문 최종 4회 = 40회이다. Jev 보호 시험 6회는 별도다. 중간 후보 시험과 앞선 다른 기능의 API 시험은 이 집계에 포함하지 않는다.
