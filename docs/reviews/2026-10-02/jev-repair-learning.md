# Jev 교정·오류 유형 학습 — 0.1.20

## 문제와 변경

기존 `observe`는 입력 후 진단만 표시하고, `protect`는 강한 오류 신호에서 입력을 보류했다. 자동 검토 결과가 이후 문장 정리 요청을 바꾸지 않아, 사용자가 원한 ‘입력 전 해결’과 ‘같은 유형의 실수에 대한 후속 반영’이 빠져 있었다.

0.1.20 (build 22)은 `repair` 모드를 추가한다. 최초 문장 생성 후 Jev 검토를 실행하고, 강한 오류 신호가 있으면 같은 제공자·현재 문장 모델에서 교정안 한 개를 생성한다. Jev 재검토 및 로컬 보존 검사를 통과한 결과만 입력한다. 검토 미완료·단가 미확인·실패·시간 초과는 보류하며, 미검사 결과를 입력하거나 교정을 반복하지 않는다. 기존 `off`·`observe`·`protect` raw value와 기본 꺼짐을 보존한다.

`observe`의 화면 이름은 ‘입력 후 검토·학습’이다. 먼저 입력한 후 강한 오류 신호에서 교정·재검토를 뒤에서 실행한다. 이미 입력한 글과 기존 최종 기록은 바꾸지 않는다. 새 `jevFeedbackLearningEnabled` 옵션을 선택한 경우에 재검토를 통과한 교정의 정해진 오류 유형만 다음 같은 제공자·모델 요청에 주의사항으로 반영한다. 신규·이전 설정에서 새 학습은 꺼짐이며, 오류 발견 자체는 학습 근거가 아니다.

## 계약·범위

- 생성 주체는 기존 문장 제공자다. Jev는 원문·결과의 의미 신호와 제공된 이름 후보를 검토한다. Jev에는 녹음이나 주변 앱 문맥을 보내지 않는다.
- 교정은 작업당 생성 최대 1회(8초)+재검토 1회(1.5초)다. 참고 단가로 예약한 추가 비용은 US$0.05 이내이며 알 수 없는 단가에서는 실행하지 않는다. 자동 개선안 옵션으로 같은 작업에 두 번째 생성을 추가하지 않는다.
- 재검토 통과에는 모든 유효한 위험 점수 0.5 미만, 이름 후보의 명확한 선택, 원문 기반 숫자·URL·인용·식별자·명시한 Latin 이름 보존 등이 포함된다. 점수는 정확도나 검증의 보장이 아니다.
- 학습 유형은 `meaning`·`additions`·`omissions`·`numbers`·`negation`·`conditions`·`intent`·`entities`이며, 모델의 자유형 지시·문장·수정 사실은 저장하지 않는다. 이름 표기의 전역 매핑은 기존 사용자 확인 사전 저장으로 유지한다.
- 암호화 유형 저장은 문장 제공자·모델별 범위를 구분한다. 다른 모델의 오류 유형을 섞거나 AI 모델 자체를 재학습하지 않는다.
- 학습 옵션 해제는 새 저장과 다음 요청 반영을 중단하고 기존 유형을 유지한다. 명시적 ‘학습한 오류 유형 지우기’는 모든 모델의 유형만 삭제한다. 기록 해제·전체 기록 삭제는 진행 중 작업 취소와 학습 유형 삭제를 함께 수행한다.
- 새 녹음·취소·관련 설정·키 변경 시 진행 중 교정과 학습을 취소하고 늦은 결과를 버린다. 다른 앱에 입력하기 직전 기존 대상·권한 확인을 계속 수행한다.

## 사용 위치

설정 → AI 연결 → Jev → 문장 검토 → **입력 전 교정**.

같은 화면의 **해결한 오류 유형을 다음 문장 정리에 반영**에서 학습을 별도로 켠다. 현재 문장 모델에 반영할 유형 수·목록과 최근 처리 상태를 볼 수 있고, 모든 모델의 유형을 직접 지울 수 있다. 한국어와 영어 화면을 함께 제공한다.

## 검증 상태

새 설정의 기본값·이전 모드 보존·명시적 선택 round trip·깨진 필드별 복구·알 수 없는 제공자의 전송 선택 해제·한영 설명 테스트 7개를 추가했다. 기존 설정·사전 후보·모델 선택·화면 설명 회귀와 함께 **20개 통과, 실패 0건**을 확인했다. 로컬 CLT에서 XCTest가 제공되지 않아 동일 테스트 본문을 production Preferences와 순수 화면 설명 함수로 컴파일한 headless runner 결과이며, 전체 XCTest 실행을 대신하지 않는다. 검증 기록과 당시 소스 해시는 `build/jev-repair-verification/preferences-ui/run.log` 및 `source-manifest.json`에 있다.

Core·앱 흐름 결과는 아래에 기록했다. 전체 GitHub XCTest·설치 검증 결과는 별도로 갱신한다. 새 실제 마이크 발화의 정확도 향상을 이미 검증한 것으로 해석하면 안 된다.

외부 모델·가격·API 계약은 이전 검증 문서의 근거를 유지하며, 이번 변경에서 upstream endpoint나 키 저장 경로를 바꾸지 않는다. Developer ID·Apple 공증·워크플로 파일 변경은 범위에 포함하지 않는다.

## 실제 OpenRouter·TypeSafe 검증

사용 중인 qwen/qwen3-30b-a3b-instruct-2507과 TypeSafe jev-1.13.0으로, 잘못된 정리 결과를 주입한 합성 문장 3개를 검사했다. 제품 JevRepairRunner·ProviderClient·DecisionClient를 그대로 사용했고 API 키는 1Password 런타임 주입으로만 전달했다.

| 합성 사례 | 잘못된 결과 → 재검토를 통과한 교정 |
| --- | --- |
| 숫자 | 오후 4시 → 원문의 오후 3시 |
| 부정 | 배포하고 테스트 → 원문의 배포하지 말고 테스트만 |
| 이름 | GRAV / OpenType → 원문의 JEV / OpenNoType |

3개 모두 원문과 같은 결과를 생성하고 Jev 재검토 및 로컬 literal 조건을 통과했다. 총 9개 HTTP 요청은 모두 200, 각 1회 시도, 재시도 없음이었다. 최초 최대 위험 신호는 0.93/0.98/0.93, 교정 후 0.07/0.08/0.09였다. 전체 8.934초, 사례별 1.546~3.840초였으며 보수적 예약 합계 US$0.0383818은 검증 상한 US$0.15 이하였다. OpenRouter 보고 생성 비용 US$0.0004591863과 TypeSafe 추정 검토 비용 US$0.000406014의 합계는 US$0.0008652003이다. TypeSafe 비용은 청구서로 확정하지 않았다.

이 검증은 합성 텍스트 3건의 실제 네트워크 경로이며 실제 마이크 인식 시험이나 일반 정확도 측정이 아니다. Jev는 최초 음성 인식문을 기준으로 검사하며 직접 음성을 듣지 않는다. 학습은 재검토를 통과한 교정의 오류 유형을 같은 문장 모델의 다음 프롬프트에 재사용하는 것이며 모델 재훈련이나 임의 이름·사실의 자동 사전 등록은 하지 않는다. 영문 이름의 특정 표기는 확인된 개인 사전으로 유지한다. 상세 오류 유형은 세부 검토를 켰을 때 구분된다.

GitHub 전체 XCTest와 설치된 앱의 확인 결과는 배포 후 별도로 기록한다.

## 전체 XCTest에서 발견한 회귀 수정

첫 GitHub 실행에서 새 언어 테스트의 `OpenNoTypeCore` import 누락을 수정했다. 다음 실행은 662개 XCTest를 실행해, 새 모델 설정 변경의 전체 `refreshData()`가 명시적으로 기다리는 데이터 갱신을 무효화하는 실제 회귀를 발견했다. 암호화 데이터 유실은 없었지만 기록·사용량 화면이 빈 배열로 남고 기록 재처리가 시작되지 않을 수 있었다.

모델 변경과 오류 유형 저장 뒤에는 학습 목록만 독립적으로 갱신하도록 변경했다. 초기 설정 대입에서는 자동 갱신을 예약하지 않으며, 모델 전환·유형 삭제 이후 늦게 도착한 학습 목록도 반영하지 않는다. 기존 테스트와 시간 제한을 유지한 실제 제품 코드의 headless 재검증에서 기록 재처리 11개와 사용량 8개가 모두 통과했다. GitHub 전체 XCTest 결과는 이 수정 커밋 기준으로 다시 확인한다.
