# 옵션별 도움말 UI 개선 — 실제 구현 보고

작성일: 2026-10-15
상태: **코드 적용 완료 · 최종 검증 결과 아래 참조**
비교 기준 HEAD: `f223adc544dc9e69dbb91e10627782538054d29b`

설정의 긴 설명을 이름 옆 `?` 도움말로 옮기고, 현재값·적용되지 않는 이유·비용과 보류 조건을 짧게 남기는 1차 UI 개선을 실제 SwiftUI 소스에 적용했다. 홈의 최근 결과 위치와 일반 결과 완료 시 스크롤도 조정했다. 이 문서는 실제 코드 적용·검증·인수인계를 기록한다. 설치되어 실행 중인 앱 교체는 수행하지 않았다.

## 비교 기준과 병행 작업 보존

작업 전부터 다른 에이전트가 녹음·단축키·로컬 처리·입력 안정성 등 기능을 개선하고 있었다. 현재 작업 디렉터리의 전체 `git diff`와 미추적 파일 수를 이번 UI 작업의 변경량으로 계산하면 안 된다.

이번 작업 전의 변경 보존 사본:

```text
/var/folders/54/pt7hl9y55rz6bc4c2k78dr4c0000gn/T/opennotype-uiux-baseline-lbgl8o1m/
```

이 사본의 `manifest.json`은 보존한 파일의 해시를 기록한다. 사본에 있는 기존 수정 파일은 이 기준과 현재 파일을 비교하고, 사본에 없는 당시 변경되지 않은 추적 파일은 위 HEAD와 비교한다. 임시 경로가 없어졌다면 현재 기능 변경을 옛 HEAD 파일로 덮어쓰지 말고 먼저 해당 작업자와 변경 경계를 다시 확인한다.

이번 UI 범위는 아래 소유 파일의 View·도움말·비활성화 범위 조정이다. `AppModel`, `Preferences`, 오디오·추론·입력·암호화 저장 알고리즘과 기존 미커밋 기능 변경은 이번 작업에 포함하지 않는다.

## 구체적인 변경

### 공통 도움말과 편집 가능 범위

`OptionHelpPresentation.shared.activeID`로 한 번에 하나의 설명을 선택한다. 다른 도움말로 바뀔 때 이전 팝오버의 닫힘 이벤트가 새 도움말 ID를 지우지 않도록 ID를 확인한다. 화면에서 사라질 때 해당 도움말 상태를 정리한다.

`?`는 옵션명을 포함한 접근성 이름을 가진 실제 버튼이며, 팝오버에 제목·본문·닫기 버튼을 제공한다. 닫기 버튼에는 취소 키보드 단축키를 연결하고 호출 버튼으로 포커스를 돌리는 처리를 넣었다. 네이티브 검증에서 닫기 버튼·Escape·같은 물음표 재클릭의 포커스 복원과 도움말 전환을 확인했다. 본문 높이는 실제 텍스트 높이를 측정해 불필요한 빈 공간 없이 표시하고, 긴 설명은 최대 360pt 안에서 스크롤한다. 기본 Button의 키보드 탐색을 사용하며 별도 focusable 래퍼를 만들지 않는다.

`OptionToggle`은 라벨과 도움말을 남기고 토글만 비활성화한다. 설정 복구·시안·준비 상태 등 기존 편집 보호는 값 조절과 실행 행동에 유지한다. 설명을 열기 위해 녹음·다운로드·API 요청·설정 저장을 실행하는 코드를 추가하지 않는다.

### 언어·표현·번역 다듬기

- 출력 언어는 현재 선택과 기존 예시·적용 창을 유지한다. 미리보기만으로 설정을 바꾸지 않으며, 적용 완료 안내도 남긴다.
- 표현 방식·편집 강도는 각각 도움말을 제공한다. 강도 0/기본 표현의 기존 정리 의미와 비기본 표현 선택 시 40으로 시작하는 바인딩을 유지한다.
- 번역 중에는 표현 설정이 적용되지 않는다는 짧은 상태를 남긴다. 선택값을 자동 초기화하지 않는다.
- 읽기 전용으로 전환되면 열린 예시 창을 닫고 적용 바인딩을 보호한다. 도움말은 그대로 읽을 수 있다.
- 번역 다듬기를 켠 상태에서는 `추가 요청 1회 · 비용 발생 가능 · 실패 시 입력 보류`를 화면에 남긴다. 켜진 번역 입력 전 Jev 검토의 현재 관계도 짧게 표시한다.

### 녹음·로컬 모델·설정 조립

녹음 방식·마이크·알림음·시스템 음소거·로컬 모델·메모리 유지·미리보기의 긴 설명을 관련 옵션 도움말로 옮긴다. 지정 마이크 연결 끊김, 모델 준비 상태, 음소거 때문에 알림음이 들리지 않을 수 있는 상태, 미리보기 미적용 이유 등 현재 문제는 숨기지 않는다.

연결·API 키·문체·주변 문맥·학습·보관·일반 설정에서도 같은 규칙을 사용한다. 기존 키 저장·삭제·권한·모델 준비·업데이트·진단 버튼의 실제 행동과 확인 절차는 도움말로 대체하지 않는다. Jev 두 설정 구조체의 적용과 읽기 전용 연결도 소유 범위 diff로 확인했다. 검토 절약은 입력 전 교정 모드에서 미적용, 오류 유형 반영은 빠른 로컬·번역·기록 꺼짐에서 현재 받아쓰기 미적용으로 표시한다. 입력 후 검토의 재인식 대기 안내도 빠른 로컬에서는 표시하지 않는다.

### 홈의 결과와 프롬프트

최근 결과와 최근 검토를 준비 상태·입력 모드·모델 설명보다 앞에 둔다. 처리 종료 후 홈에서 위로 이동하는 조건을 프롬프트뿐 아니라 일반 결과·번역 다듬기 결과까지 넓힌다.

프롬프트 버튼의 기존 action과 활성화 조건을 유지한다. 홈 녹음·재처리·원문 수정은 복사용, 외부 앱 단축키는 기존 입력 경로, AI 자동 제출 없음, 차단·오류·취소 때 입력 안 함, 입력 실패 때 복사 가능이라는 설명을 보존한다. 문장 생성 1~2회·검토 2회의 추가 비용과 시간은 화면에도 남긴다.

## 교차 검토로 보완한 빠른 로컬 미적용 표시

첫 구현에서 번역 출력의 표현 미적용은 표시했으나 빠른 로컬 받아쓰기 조건은 View에 전달하지 않았다. 이 상태에서는 AI 정리를 생략하는데도 표현·강도 설정이 현재 적용되는 것처럼 보일 수 있었다.

통합 과정에서 `DictationExpressionSettingsView.isFastDictation`을 추가하고, `SettingsView`가 `model.preferences.usesFastDictation`을 전달하도록 보완했다. 빠른 로컬일 때 미적용 이유와 저장값을 함께 보여 주고, 표현·강도·예시 적용·초기화 조작은 비활성화한다. `?` 도움말은 유지한다. 도움말의 적용 범위에도 빠른 로컬 제외를 반영했다.

이는 표시·조작 범위 수정이다. 빠른 로컬 엔진, 출력 언어 판정, AI 처리 알고리즘, 기존 저장값을 바꾸지 않는다. 번역 출력에서는 저장된 빠른 설정과 실제 유효 경로가 다르므로, 단순 저장값 대신 기존 `usesFastDictation` 조건을 사용한다.

## 유지해야 할 기능 계약

| 계약 | 이번 작업의 보존 기준 |
|---|---|
| 빠른 로컬 받아쓰기 | 인식 문장을 AI 정리·자동 검토 없이 입력하는 기존 범위. 인식 정확도를 보장한다고 부르지 않음 |
| 저장된 빠른 설정 + 번역 출력 | 저장값을 바꾸지 않고 번역의 AI 처리와 빠른 설정 미적용을 안내 |
| 표현·강도 | 적용 범위·숫자·이름·의도 보존 지침·0/40 전이 유지, 강도 0을 AI 정리 끔으로 설명하지 않음 |
| Jev 검토 모드 | 일반 `protect`의 실패 시 기존 결과 입력 가능성과 `repair`의 실패 시 보류를 구분 |
| 번역 보호·번역 다듬기 | 검토/다듬기 실패의 기존 보류, 초안을 대신 자동 입력하지 않는 계약 유지 |
| 예시와 직접 적용 | 예시 탐색만으로 값 변경 없음, 실제 적용은 기존 명시적 행동 |
| API 키·모델 상태 | 키 저장과 연결 성공, 모델 파일과 메모리 준비를 구분 |
| 녹음·외부 입력 | 대상 추적·취소·포커스·클립보드 보호 로직 변경 없음, 홈 일반 녹음 버튼 추가 없음 |
| 전송·보관·학습 | 상세 설명을 도움말로 이동해도 기존 데이터 영향·확인·삭제 범위 유지 |
| 프롬프트 | 복사용/외부 입력용 차이, 차단 판정, 자동 AI 제출 없음, 생성·검토 비용 보존 |
| 업데이트 | 녹음·처리 중 확인/설치와 재실행 보호, 실제 오류·보류 상태는 상시 안내 |

## 통합 검증

- **소스 경계:** 임시 보존 사본의 해시와 현재 변경을 대조했다. 기존 `AppModel`·`Preferences`·`Platform`·`OpenNoTypeCore` 및 기능 테스트의 변경 내용은 이번 UI 작업에서 추가 수정하지 않았다. UI 소스 9개와 보고·설계 문서가 이번 범위다.

### 네이티브 UI에서 확인한 것

macOS 검증 앱 `app.opennotype.usage-preview`를 사용했다. 합성 데이터·차단된 네트워크/녹음/저장 경로를 사용하므로 일반 앱의 API 키나 기록을 열어 설정을 바꾸는 검증이 아니다.

| 항목 | 결과와 범위 |
|---|---|
| 읽기 전용 설정의 도움말 | 한국어 입력·단축키와 일반 설정에서 값 컨트롤은 disabled, 물음표는 enabled인 AX 상태와 실제 팝오버를 확인 |
| 도움말 이름·본문 | 옵션명 포함 접근성 이름, 별도 닫기 버튼·본문이 AX에 노출되는 것을 확인 |
| 설명 높이 | 초기 네이티브 화면에서 발견한 큰 빈 공간을 수정하고 짧은 설명이 본문 길이에 맞게 표시되는 것을 확인 |
| 닫기·Escape | 팝오버가 사라지고 원래 앱 언어 도움말 버튼이 focused로 돌아오는 것을 확인 |
| 같은 물음표 재클릭 | 화면 모드 도움말 재클릭으로 닫히고 해당 버튼으로 포커스가 돌아오는 것을 확인 |
| 하나씩 표시 | 로그인 실행 도움말에서 화면 모드 도움말로 전환할 때 AX popover 한 개만 유지되는 것을 확인 |
| 키보드 | 최종 빌드에서 Escape 후 앱 언어 도움말 focused → Tab 1회로 로그인 실행 도움말 focused → Space 1회로 해당 팝오버 열림 확인. 중복 focusable 래퍼 제거 |
| 영어·다크 | 별도 검증 앱의 번들 설정만 바꿔 영어·다크 설정 행과 본문을 실제 화면·AX로 확인. 사용자 앱 언어·화면 설정은 변경하지 않음. 최종 다크 도움말 버튼 색상도 실제 화면 확인 |
| 복구·fast·번역·예시 창 | 적용 조건·guarded binding·읽기 전용 전환의 소스/기존 테스트를 검토. 이 모든 조합을 네이티브로 실행한 것은 아님 |
| 홈 결과 | 결과 우선 순서·완료 시 스크롤의 소스 경로를 검토. 실제 사용자 녹음·입력 보류 재현은 수행하지 않음 |

**미수행:** VoiceOver를 켠 실제 음성 낭독, 모든 작은 창/긴 문자열 조합, 실제 마이크·외부 앱 입력·유료 API·삭제·권한 변경, 전체 홈 상태 조합. AX 검증이나 자동 테스트 통과를 이 항목들의 성공으로 확대하지 않는다.

**설치 경계:** 일반 앱 산출물은 `build/OpenNoType.app`, 검증 앱은 `build/usage-preview/OpenNoTypeUsagePreview.app`이다. `/Applications/OpenNoType.app`을 덮어쓰거나 실행 중인 일반 앱을 종료하지 않았다. 작업 전후 실행 중인 일반 앱 PID는 `1194`로 유지됐다. 검증 앱은 검증 후 종료했고, 전달용 검증 번들은 한국어·라이트로 복원해 다시 서명을 검사했다. 커밋·설치·배포는 하지 않았다.
