# 번역 다듬기 1차 검증

판정: **품질 향상 채택 보류**. 추가 처리·보류·취소·사용량 등 기능 계약은 통과했지만, 같은 모델을 한 번 더 부르는 것만으로 자연스러움과 의미 보존이 나아졌다고 볼 근거가 부족합니다. 공개 v0.2.3과 설치 앱은 변경하지 않았습니다.

## 비교 조건

- 원문 12개: 구현 전에 고정한 새 한국어 합성 발화 8개(EN4/JA4), 알려진 사례 4개. JF801은 제공된 일본어만 있어 한국어 원문과 비교한 번역 정확도 시험이 아닙니다.
- OpenRouter `openai/gpt-6-luna`·기존 medium 정책으로 초안 12회, 각 동일 초안 정제 12회. 재시도·Jev 호출 없음. 코드 28파일은 `c99512579ca3edbf15d1b537345e9671cbad7567`에 결합했습니다.
- 정답 문장을 모델에 제공하지 않았습니다. 의미·자연스러움 기준은 평가에만 사용했고 실제 요청은 원문·초안·목표 언어·프로필·관련 사전으로 제한했습니다.
- 3명의 AI 판독자가 A/B 순서를 가린 12쌍을 잠근 뒤 대응표를 공개했습니다. 같은 12쌍에 대한 여러 판독이며 36개 독립 사례가 아닙니다. 사람 원어민 검수나 대표 모집단 평가는 아닙니다.

## 관측 결과

| 코어 | 3 | 1 | 8 |

상대 선호는 품질 합격과 다릅니다. JF801의 반복된 일본어 테스트 표현과 JF810의 영어 강조 횟수 표현은 양쪽 모두 세 판독에서 자연스러움 1/3으로 남았습니다. 사용자가 마지막으로 제시한 원문의 영어·일본어 두 사례는 세 판독 모두 초안을 선호했습니다.

TRH1103에서 초안은 “오늘 반드시 공유하겠다는 뜻은 아니다”라는 확약의 부정을 `absolutely has to be shared today`라는 의무의 부정으로 바꿨습니다. 정제는 확약 표현을 고쳤으나 공유·결정 주체를 원문에 없는 `we`로 넓혔습니다. 루트·코어는 초안의 양태 변경을 명확한 의미 문제로, UI는 주의 사항으로 판독했습니다. 정제의 `we` 추가는 코어·UI가 명확한 문제로, 루트는 해석 위험으로 기록했습니다. 미정인 최종 검토 담당자는 두 결과 모두 미정으로 남았습니다.

TRH1104의 `we discussed yesterday`도 주체 추정에 대한 판독 차이가 있었습니다. 이견을 만장일치 합격이나 실패로 바꾸지 않았습니다. 실제 일본어 대비·인용 말투·별도 테스트 목적·배송비 계산 등은 다수 결과에서 유지됐지만, 이것이 전체 의미 보존을 보증하지 않습니다.

## 기능 증거

HTTP 200·사용량 이벤트·요청 지문 각 24개, 같은 실제 초안 전달 12개를 검증했습니다. 추가 요청 재시도는 0회입니다. 공급자 보고 비용 합은 $0.006862125입니다. 문자열이 달라졌다는 사실은 품질 개선으로 집계하지 않았습니다.

정식 Xcode CI 두 건(`37562288484`, `37562281933`)은 각각 Swift 899개 중 897개 통과·기존 로컬 오디오 선택 실행 2개 제외·실패 0, Python 198개 통과·제외 0입니다. 신규 35개 검사(코어 20·앱 흐름 11·설정 4)는 개별 실행·통과를 확인했습니다. 개발 앱 빌드·업로드도 성공했습니다. 앱 정적 검사에서 arm64·최소 macOS14·`LSUIElement=true`를 확인했고 메뉴바 소스는 공개 v0.2.3과 같습니다. 실제 실행·설치·메뉴바/Dock 시각 확인은 이 검증에 포함되지 않습니다.

## 후속 범위

초안의 문장틀에 매이는 원인이라는 가설은 아직 입증되지 않았습니다. 후속에서는 정제 지침의 시작을 원문 기반 문장 재구성으로 명확히 하고, 주체·판단 소유자·약속·의무·허가·예측과 부정 범위를 따로 확인했습니다. 확정한 새 문장 4개는 후보 동결 전 구현자가 읽지 않았습니다. 알려진 문제 3개는 이전 초안을 그대로 재사용해 정제 3회, 새 문장 4개는 초안·정제 8회로 후속 호출 11회를 마쳤습니다. 이 시험은 최초 24회와 별도이며 기존 증거를 덮어쓰지 않았습니다. [후속 결과](translation-refinement-round2.md)에 개선과 미해결 사항을 기록했습니다.
