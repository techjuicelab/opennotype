# 0.2.3 준비와 번역 검증

**현재 상태: 0.2.3 후보 검증 중. 공개·설치 완료나 전반적인 번역 품질 향상을 선언하지 않는다.** 공개 다운로드 안내는 [0.2.2(34)](https://github.com/techjuicelab/opennotype/releases/tag/v0.2.2)를 유지한다. 0.2.3의 소스·자동 검사·실측·공개 파일·이 Mac 설치와 실행 결과는 확인한 단계부터 아래 기록에 반영한다.

## 앞선 문장 흐름 후보의 결과

앞선 후보 `b2bc22415bbcce435b0b8b8a0a824c7c2e8e23dd`는 같은 번역 요청 안에서 영어의 추상적인 표현과 일본어의 반복·절 연결을 다듬는 지침을 추가했다. [고정 명세 10개](../../fixtures/native-translation-japanese-flow.json)는 사용자 제공 일본어 1개·한국어 텍스트 1개와 작성한 합성 한국어 8개이며 목표 언어는 일본어 8개·영어 2개다.

공개 0.2.2와 이 후보를 각각 한 번 생성해 총 20회 호출했고 재시도는 없었다. 모두 HTTP 200·텍스트 반환·제한된 번역 보호 검사와 요청 fingerprint 대조를 통과했다. 제공자 보고 모델은 `openai/gpt-6-luna`, 추론 설정은 `medium`이었다. 이 기술적 성공은 품질 합격 수가 아니다.

4개 에이전트는 언어 판독 3개와 주 에이전트의 요청·근거·통합 감사로 나눴다. 원문과 후보 지침은 이미 알고 있었고, A/B의 실제 대응만 판독 파일을 고정한 뒤 공개했다. 미공개 표본이나 사람 원어민 검수가 아니다.

| 독립 판독 범위 | 후보 선호 | 공개판 선호 | 동률 |
| --- | ---: | ---: | ---: |
| 일본어 전문 판독 8개 | 1 | 2 | 5 |
| 영어 전문 판독 2개 | 1 | 0 | 1 |
| 전체 충실도 판독 10개 | 1 | 2 | 7 |

일본어·영어 전문 판독을 합치면 후보 2·공개판 2·동률 6이다. 전체 충실도 판독은 같은 출력 10개에 대한 별도 판단이므로 위 전문 판독에 추가 표본처럼 합산하지 않는다. 영어의 후보 선호는 약한 문체 선호였으며 원어민 수준의 개선이나 통계적 효과를 뜻하지 않는다.

선정 출력에서 명확한 의미 훼손은 식별하지 못했지만, 사용자 일본어 사례 JF801은 양쪽 모두 반복적인 테스트 문장틀이 남았다. JF810도 강조를 보존하는 영어 구문이 양쪽 모두 뻣뻣했다. JF801은 원 한국어가 없어 제공 일본어의 내용 보존·자연스러움만 평가했으며 한국어→일본어 충실도는 판정하지 않았다. 사용자가 제공한 기존 영어 번역도 대체로 자연스러우며 일부 모호하거나 추상적인 표현을 심각한 오역으로 분류하지 않는다.

첫 후보는 전반적인 향상을 확인하지 못해 채택을 보류했다. 당시 Swift 862개 통과·2개 건너뜀, Python 197개 통과와 개발 앱 빌드 성공은 해당 소스의 자동 검사 결과다. 후속 0.2.3의 소스·품질·설치 검증으로 확대하지 않는다.

## 0.2.3 첫 보수 후보: 28회 비교 후 보류

동결한 `NativeTranslationInstructions.swift` SHA-256 `c9d53dcf57ac5168585a4167bb94c6ddf21a1aacf163bb866a5c7eee01f188a2`의 첫 보수 후보는 공개 0.2.2와 원문 14개를 각각 한 번 생성해 비교했다. 목표 언어는 일본어 10개·영어 4개이며, OpenRouter `openai/gpt-6-luna`의 `medium` 설정으로 총 28회 호출했다. 재시도 없이 모두 HTTP 200·텍스트 반환·제한된 번역 보호 검사를 통과했다. 이는 출력 품질 합격 수가 아니다.

| 독립 판독 범위 | 후보 선호 | 공개판 선호 | 동률 |
| --- | ---: | ---: | ---: |
| 일본어 전문 판독 10개 | 3 | 0 | 7 |
| 영어 전문 판독 4개 | 1 | 2 | 1 |
| 전체 충실도 판독 14개 | 4 | 4 | 6 |

일본어·영어 전문 판독을 합치면 후보 4·공개판 2·동률 8이다. 전체 충실도 판독은 동일한 출력에 대한 별도 판단이므로 추가 표본이나 일치한 점수로 합산하지 않는다. 명확한 의미 오류를 식별하지 못했고 일부 부정절과 문장 연결은 선호했지만, JF801의 반복적인 테스트 문장틀과 JF810의 뻣뻣한 강조 표현이 남아 목표한 자연스러움 개선은 미완료로 판정했다. **이 후보도 채택을 보류했다.**

4개 에이전트는 앞선 비교와 같이 언어 판독 3개와 요청·근거·통합 감사로 나눴다. A/B의 실제 대응은 판독 JSON과 출력 SHA를 고정한 뒤 공개했다. 원문·후보 지침·개선 방향은 알려져 있었으며, 원 한국어가 없는 JF801은 제공된 일본어의 보존과 문장 흐름만 평가했다. 사람 원어민 검수나 실제 사용자 마이크·대상 앱 입력 시험이 아니다.

## 후속 후보: 별도 36회 검증 진행 중

후속 후보의 Native 지침 동결 SHA-256은 `bc58277f1b4e07dda9b92b7b37411d18ee1b5d99d76739e0c282c6699703c1cc`다. 앞선 실패를 알고 일반 예시 두 개를 보강했으며, 기존 원문 14개에 새 합성 4개를 더한 18개를 공개판과 각각 생성하는 총 36회 비교를 진행 중이다. 아직 품질 판정이나 채택 결과는 없다.

새 합성 4개는 후속 지침 편집 전에 SHA-256 `ebc57787dc387c644fe318363936c3fde0e3d81fb3f5458c685419118bb12079`로 동결했고, 소스 작성자는 그 원문을 열람하지 않은 상태에서 지침을 동결했다. 앞선 사례의 실패와 개선 방향은 알려져 있으므로 전체 설계가 완전히 가려진 검토로 표현하지 않는다. 기존 14개와 신규 4개는 분리해 판독하며, 첫 20회나 이번 28회의 기술적 성공·선호를 후속 후보의 성과로 재사용하지 않는다.

## Dock·메뉴바와 설치 경계

코드의 `LSUIElement=true`는 Dock을 숨기는 정책이다. App delegate가 `StatusBarController`를 강하게 소유하고 단일 `NSStatusItem`을 유지하며, 저장된 숨김 상태를 초기화하고 `isVisible=true`로 설정한다. 마지막 관리창을 닫아도 앱을 종료하지 않고 메뉴의 열기·설정 경로를 유지하는 구조다. 이 코드 확인을 새 버전의 실제 상태 아이콘 표시·클릭·창 재열기 검증으로 대신하지 않는다.

[0.2.2 설치 기록](community-release-0.2.2.md)에서는 공개 앱의 바이트·서명 검증 후에도 Gatekeeper의 앱별 실행 승인이 필요했다. 사용자가 직접 허용한 뒤에는 임시 `AppTranslocation` 경로의 실행으로 업데이트 확인이 차단되는 현상을 관측했다. 이 과거 경험을 소스 crash, 악성코드 판정 또는 0.2.3의 동일 현상 재현으로 단정하지 않는다.

설치 전 백업, 새 공개 앱의 무결성, 실제 실행 경로·버전·단일 프로세스와 메뉴바 동작, 마이크·손쉬운 사용·Keychain 접근은 구분해 확인한다. 앱 교체 후 macOS가 요구하는 승인은 사용자가 직접 수행해야 하며 권한 유지나 업데이트 성공을 서명 검증만으로 보장하지 않는다. 커뮤니티 배포의 ad-hoc 서명·Sparkle Ed25519와 Apple 공증 여부도 최종 공개 파일 기준으로 기록한다. [설치 안내](../../mac-installation.md)와 [업데이트 운영](../../updates.md)을 참고한다.

원어민 사람 검수, 실제 사용자 마이크·잡음 환경과 모든 대상 앱 삽입은 별도 검증 범위다. 특정 출력에서 오류를 식별하지 못한 사실이나 선호 점수만으로 모든 다음 생성의 뜻 보존·자연스러움을 보장하지 않는다.
