# 0.2.2 번역 비교와 검토 기능

0.2.2의 번역 생성과 선택형 입력 전 검토를 확인한 기록이다. 공개 버전과 설치 안내는 [README](../../../README.ko.md)에서 확인한다. 아래 개발 앱·CI·실측의 commit과 build는 각 시험 당시 값으로 보존한다. 기능 구현·CI 통과·합성 모델 응답·실제 마이크 시험·사람 원어민 검수는 서로 다른 근거다.

## 실제 번역 비교

2026-10-06 원래 기준을 유지하며 baseline과 후보 세 버전을 OpenRouter GPT-4.1 Mini 및 GPT-6 Luna로 비교했다. actual `ProviderClient.process`를 사용했고 실제 재시도는 없었다.

| 범위 | 요청 | HTTP 200 | 텍스트 반환 | 리터럴 보호 차단 |
| --- | ---: | ---: | ---: | ---: |
| baseline 및 build30 비교 | 104 | 104 | 102 | 2 |
| build31 기존 42사례 × 모델2 | 84 | 84 | 83 | 1 |
| build32 같은 42사례 × 모델2 | 84 | 84 | 83 | 1 |
| 기술 합계 | 272 | 272 | 268 | 4 |

합계는 HTTP·요청 계보 검증이며 품질 합격률이 아니다. 후속 42사례는 알려진 회귀이며 새 blind 평가라고 부르지 않는다. 제공자 보고 비용 합계는 $0.112653500이며 실제 청구액 보장과 다르다.

build32는 Mini의 명확한 의미 오류 3개와 Luna의 미지정 결정 집단 추가를 해소했다. Luna의 즉시 자기정정 흔적 2개도 정리됐다. 그러나 Luna가 수량 맥락의 일반 합계를 `총액`으로 좁힌 의미 오류 1개가 새로 관측됐고, Mini에는 정정 흔적 4개와 표현 주의가 남는다. 단일 출력이나 평균 관용성 개선만으로 원어민 품질 완료를 선언하지 않는다. build33은 초기 번역 생성 지침과 모델 정책을 build32와 동일하게 유지하며 입력 전 검토 기능을 별도로 추가한다.

사용자가 제공한 일본어 두 결과는 비긴급·자료 3점·내일 마감 강제가 아님과 시험 목적·점진 개선을 자연스럽게 전달한다. 그 결과의 모델과 빌드는 확인되지 않았으므로 전체 후보의 품질 통과 근거로 확대하지 않는다.

## 입력 전 검토

기존 번역 검토는 직접 요청하는 방식이었다. build33은 기본 꺼짐인 `translationProtectionEnabled`와 `.protect`를 함께 선택하면 한 번 검토하고 불확실하거나 실패한 번역의 자동 입력을 보류한다. 선택한 말투와 당시 목표 언어를 전송하며 자동 재번역하지 않는다. 비번역 요청의 wire 상태와 질문은 기존 바이트를 유지한다.

build32 계약으로 고정 오류·정상 8사례를 실제 Jev 검토했다. HTTP 200·typed 응답 8개였으나 일반 합계의 금액 좁힘을 기존 높은 위험 경고가 구별하지 못했다. 새 보수적 입력 허용 기준을 적용하면 정상 사례도 모두 보류된다. API 성공은 검출 품질 통과가 아니다.

말투·문맥을 포함한 build33 계약에서도 **같은 8개를 상세8질문과 기본3질문으로 각각 실제 호출**했다. 두 경로 모두 HTTP200·typed8·단일 시도·runtime exit0이며, 기본3은 상세 응답에서 항목을 제거한 모의 결과가 아니다. 원문·번역·당시 언어·선택 말투를 사용했고 정답이나 외부 판독 결과를 모델 요청에 넣지 않았다.

| 고정 사례 | 기존 상세8 최대 위험 | 새 상세8 최대 위험 | 새 기본3 최대 위험 |
| --- | ---: | ---: | ---: |
| 일반 합계를 금액으로 좁힌 의미 오류 | 0.12 | 0.22 | 0.19 |
| 같은 원문의 일반 합계 보존 | 0.14 | 0.21 | 0.20 |
| 최종 수량은 맞고 정정 흔적이 남은 결과 | 0.15 | 0.24 | 0.19 |
| 같은 원문의 최종 수량·정정 정리 보존 | 0.43 | 0.49 | 0.54 |
| 선택한 공손한 말투의 정상 결과 A | 0.44 | 0.59 | 0.44 |
| 선택한 공손한 말투의 정상 결과 B | 0.59 | 0.50 | 0.50 |
| 자료 제작 완료·검토 완료 아님 보존 | 0.18 | 0.32 | 0.27 |
| 명시된 청구 금액·수량 보존 | 0.19 | 0.18 | 0.13 |

입력 허용 기준인 모든 위험 점수 ≤0.1을 적용하면 새 상세·기본 경로 모두 **허용0/보류8**, 정상6도 전부 보류다. 기존 높은 위험 경고인 ≥0.9도 두 경로 모두 0건이다. 새 상세 경로에서 금액 오류와 정상 합계의 점수 차이는 작고, 기본 경로에서는 정상 결과의 점수가 더 높았다. 정정 흔적이 없는 정상 결과도 흔적이 남은 결과보다 높게 평가됐다. 선택 말투를 전달했다는 사실만으로 오탐 해소나 판별력 향상을 주장하지 않는다.

부정 대조 2개 중 하나는 명확한 의미 오류, 다른 하나는 최종 수량을 유지한 정정 cleanup 미충족이다. Jev의 의미·추가·누락 및 세부축은 원어민 자연스러움이나 cleanup의 독립 점수가 아니다. 이 작은 선별 표본으로 임계값을 완화하거나 정확도 확률을 보정하지 않았으며, 실제 보호 기능의 대상 앱 삽입·사람 원어민 검수 완료를 뜻하지 않는다. 입력 전 번역 검토는 기본 꺼짐인 실험 기능으로 유지한다.

출력 원본·요청 fingerprint·판독 기준·비용·CI artifact 계보는 로컬 `build/native-translation/refinement-0.2.2`에 보관한다. 개인 발화·키값은 평가 입력과 증거 자료에 포함하지 않았다. 실제 API 인증에는 1Password 런타임 주입을 사용했다.

[TypeSafe의 공식 언어 지원](https://docs.typesafe.ai/models)은 영어의 정확도가 가장 좋고 CJK 언어는 실제 사용 내용으로 별도 시험해야 한다고 안내한다. [Noul 판단](https://docs.typesafe.ai/confidence)은 별도 confidence를 반환하지 않는다. 이 설명은 이번 낮은 판별력의 원인을 특정하거나 번역용 임계값의 보정 완료를 증명하지 않는다.

## 코드·개발 앱 검증

실행한 앱의 소스는 `47a2e2b86d1249fd5604192de4280069d08b4e76`이며 버전은 0.2.2(33)이다. 이 소스의 [push CI](https://github.com/techjuicelab/opennotype/actions/runs/37532233737)와 [PR CI](https://github.com/techjuicelab/opennotype/actions/runs/37532241729)는 각각 Swift858 시작·856 통과·기존2 제외·실패0, Python196 통과였다. 신규 회귀19개가 모두 통과했다. 첫 CI에서 실패한 기록 미리보기 검토는 작업 전환 이후 epoch를 캡처하고 사용량 갱신 중 같은 보호검토를 유지하도록 수정했으며, 기존 assertion을 유지하고 검토 사용량 보존을 추가 확인했다.

push artifact `11444418747`의 전체 파일99·링크9, 원본 해시, 앱·Sparkle 서명, arm64/macOS14, `LSUIElement=true`, 개발 업데이트 feed/key 없음과 실행 파일을 독립 확인했다. 별도 실행 도구가 공유 설정·암호화 기록을 비공개 백업하고 새 앱을 단일 프로세스로 실행했다. 실행 버전33과 `accessory` 활성화 정책, 화면의 새 옵션·기존 설정 유지를 확인했다. `/Applications`의 0.1.26(28)은 전후 해시가 같고 Keychain은 내보내지 않았다.

이 build33 시험에서는 마이크·손쉬운 사용 권한 미준비가 관측돼 실제 녹음·대상 앱 입력을 검증하지 않았다. 시스템 승인은 사용자가 직접 해야 한다. 당시 `MenuBarExtra` 코드는 유지했지만 실제 메뉴 막대 status icon은 도구로 관측하지 못했다. 이 기록을 후속 build의 메뉴 막대 수정이나 실제 마이크 시험 완료로 확대하지 않는다.
