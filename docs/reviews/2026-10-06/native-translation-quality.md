# 0.2.1 음성 번역 품질 보강 검토

2026-10-06 `codex/native-translation-0.2.1`에 실제 시험한 v11 보강을 채택했다. 목표는 말한 뜻·조건·말투를 유지하면서 목표 언어에 맞게 표현하는 것이다. 명확한 뜻 변경 개선을 취소 값 정리보다 우선했으며 남은 실패를 삭제하거나 원래 평가 기준을 바꾸지 않았다. 원어민 수준의 전체 품질 완료를 선언하는 문서가 아니다.

## 제품 변경과 경계

- `NativeTranslationInstructions`: 수행자·조건·정정·인용 화자별 말투·문맥의 단어 뜻을 확인하는 일반 지침. 순수 말실수 설명은 제거하고 독립 이유·실제 과거 정정은 보존하도록 요청한다.
- `ProcessingPrompt`: 번역의 최종 점검을 프로필·대안 출력 지침 다음에 한 번 배치한다. 원문 받아쓰기·수정은 적용하지 않는다.
- `OpenRouterTextPolicy`·`ProviderClient`: 선택 모델이 Luna일 때 번역만 `medium`, 나머지 작업은 기존 `none`. 다른 모델 정책·기본 모델·사용자 설정은 유지한다.
- 전사 후 기존 문장 요청 한 번을 사용한다. 새 유료 의미 수정·원문 자동 입력 대체·자동 번역 Jev 학습은 추가하지 않는다. 기존 일시적 HTTP 오류 재시도는 별도다.

검증된 source26 가운데 변경4개를 동결 사본과 그대로 대조했다. 실제 모델 호출 때 Git HEAD는 `c9e3fb75955911685124b11a2c341b51a3d4382a`이며 후보 사본을 실행했다. 그 뒤 `main`을 개발 브랜치에 통합하고 검증한4개를 제품에 반영했다. 새 Git commit을 실행 당시 메타데이터에 소급 기록하지 않는다. 공개 버전은0.1.26(build28), 개발 버전은0.2.1(build29)이고 설치본을 교체하지 않았다.

## 실제 결과

| 실행 범위 | 기술 결과 | 원문 대조 |

총68 HTTP·번역 반환64·자동 의미 재요청0이다. Luna48은 알려진26·추가통합6·후속8·추가4·어휘4로 구성되며 영어17·일본어16·한국어15다. 이전 후보와 입력이 겹치므로 누적 요청을 독립 문장 통과 수로 해석하지 않는다. 같은44 입력의 v10에서는 HU706의 수량 맥락 `total`을 `총액`으로 좁혔고, v11에서는 `요약의 합계`를 유지했다. 대신 HU705의 최종3은 맞아도 `not two`가 남는 실패가 재발했다. 이를 알고 제한적으로 채택했다.

Luna의 HU701·HF906·HX1104에는 가능한 해석 범위를 좁히는 주의가 남고 HU704에는 일본어 관용 표현 주의가 있다. 기본 mini의 GC404는 최종 코드 값을 대안으로 바꾸고, QH601은 속도를 낮추라는 요청을 멈추라는 요청으로 바꾸며, HU706은 합계의 문서 위치를 빠뜨렸다. mini의 HU705·HF903 정리 잔존은 이3개와 별도다. 한 모델에서 관찰된 결과를 모든 모델의 품질로 확대하지 않는다.

합성음성은 고유 WAV3개·번역 요청4조합이다. 실제 전사 결과를 번역 요청에 넣었으며 실제 마이크·잡음·입력 권한·대상 앱 삽입·원어민 사람 검수는0이다. 모든 판독은 Codex 에이전트의 원문 대조다.

OpenRouter 보고 합계 input187,538/output13,638 tokens, reasoning10,619(출력의 일부), USD0.018217105다. Groq STT4의 비용·token은 미보고이며 전체 pipeline 비용은 알 수 없음으로 유지한다. 응답 지연 중앙값은 Luna48 3,486.5ms, mini12 1,373.5ms, 음성4의 전사부터 번역까지4,065.5ms다. upstream·캐시를 고정하지 않은 단일 실행이므로 보편적인 모델 비교 결과로 해석하지 않는다. 추론을 숨기는 `exclude`가 추론 비용을 없애는 것은 아니다([공식 설명](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)).
