# 번역 다듬기 후속 검증

판정: **특정 의미 오류는 개선했으나, 일반적인 자연스러움 향상 채택은 보류**. 원문에 없는 주체를 더하지 않고 약속과 의무의 부정을 구별하는 개선은 관측했습니다. 그러나 알려진 영어·일본어의 어색한 표현 두 개는 해결하지 못했습니다. 기능은 기본값이 꺼진 실험 옵션이며 draft PR에만 있습니다. 공개 v0.2.3과 설치 앱에 반영하지 않았습니다.

## 비교 조건

- 후보 소스는 `c7e43bf7b5d59af56dfc614d3f67dd32e50d1c7c`입니다. 1차 대비 처리 소스 28개 중 다듬기 지침 한 파일만 바뀌었고, 나머지 27개는 바이트가 같습니다. 원문 기준 문장 재구성, 주체·판단 소유자, 약속·의무·예측과 부정 범위의 구분을 강화했습니다. 시험 정답이나 예문은 지침에 넣지 않았습니다.
- 알려진 JF801·JF810·TRH1103은 1차의 **원래 생성 초안**을 바이트 그대로 재사용해 정제만 3회 호출했습니다. 이전 정제 결과를 다시 정제한 시험이 아닙니다.
- 새 한국어 합성 발화 4개(영어 2·일본어 2)는 지침 수정 전에 고정했고 구현자는 후보 동결 뒤 읽었습니다. 작성자는 1차 실패 유형과 후속 방향을 알고 있으므로 완전히 독립적이거나 대표적인 표본이 아닙니다. 각 새 원문에서 초안과 그 동일 초안의 정제를 각각 한 번 호출했습니다.
- OpenRouter `openai/gpt-6-luna`·기존 medium 정책을 유지했습니다. 새 호출은 총 11회(생성 4·정제 7)이며 재시도와 Jev 호출은 없습니다. 평가 기준은 모델 요청에 넣지 않았습니다. 각 단계는 단일 응답 표본이며 OpenRouter의 실제 상위 공급자는 고정하지 않았습니다.
- 루트·코어·UI의 AI 판독을 각각 잠근 뒤 A/B 대응표를 공개했습니다. 알려진 3개는 이전 초안을 이미 읽어 완전한 가림 평가가 아닙니다. 같은 7쌍을 여러 번 판독한 것이며 21개 독립 사례나 사람 원어민 검수가 아닙니다. JF801은 원래 한국어를 모르므로 일본어 문장 정돈만 평가했습니다.

## 관측 결과

| AI 판독 | 초안 선호 | 정제 선호 | 동률 | 새 4개만 초안 / 정제 / 동률 |
| --- | ---: | ---: | ---: | --- |
| 루트 | 2 | 4 | 1 | 2 / 2 / 0 |
| 코어 | 1 | 3 | 3 | 1 / 2 / 1 |
| UI | 1 | 4 | 2 | 1 / 2 / 1 |

선호 수는 합격률이나 원어민 수준의 인증이 아닙니다. 문장 연결·동사 결합 등 작은 차이가 많았고 UI의 모든 선호는 약한 선호였습니다.

TRH1103의 초안은 “오늘 반드시 공유하겠다는 뜻은 아니다”를 `absolutely has to be shared today`로 바꿨습니다. 후속 정제는 `That doesn’t mean it will definitely be shared today`로 옮겨 약속·확정의 부정에 가까워졌고, 1차 정제의 근거 없는 `we`도 추가하지 않았습니다. 루트·코어는 기존 초안의 의무 표현을 명확한 의미 문제로, UI는 이전과 같이 주의 사항으로 기록했습니다. 새 정제에는 `It seems it may be possible`라는 겹친 완곡 표현이 남습니다.

JF801의 `テストを行っています…一度テストしています`와 JF810의 `twice-emphasized parts`는 세 판독 모두 양쪽 자연스러움 1/3으로 남았습니다. 표현을 조금 바꾸었어도 핵심 문제를 해결한 것으로 보지 않았습니다.

새 4개에서는 세 판독 모두 명확한 의미 오류를 기록하지 않았습니다. 확약 부정과 남아 있는 기한 의무, 명시된 팀, 이중 부정, 서로 다른 행동 횟수, 의도적인 강조와 별도 확인 목적은 유지됐습니다. 그러나 작은 합성 표본에서 오류를 찾지 못한 결과로 전체 의미 보존을 보증할 수 없습니다. 일본어의 확인·테스트 반복도 남았습니다. 1차에 초안이 더 낫다고 판독한 사용자 영어·일본어 두 사례는 후속에서 재시험하지 않았습니다.

## 기능·실행 증거

실제 새 HTTP 200·사용량 이벤트·전체 요청 지문 각 11개, 원래 초안 3개 재사용과 새 실제 초안 4개 전달을 검증했습니다. 공급자 보고 비용은 생성 $0.001036150, 정제 $0.001675900, 합 $0.002712050입니다. 이 시험에서 추가 정제 요청의 경과 시간 중앙값은 약 4.7초이며 일반적인 지연 보장은 아닙니다. 1차 24회와 합쳐 새 모델 호출은 35회이고, 후속 3개 입력이 겹치므로 19개 독립 원문 시험으로 집계하지 않습니다.

정식 Xcode CI 두 건([PR 실행](https://github.com/techjuicelab/opennotype/actions/runs/37563618190), [브랜치 실행](https://github.com/techjuicelab/opennotype/actions/runs/37563614911))은 각각 Swift 899개 중 897개 통과·기존 로컬 오디오 선택 실행 2개 제외·실패 0, Python 198개 통과입니다. 신규 35개 검사도 각각 실행·통과했으며 개발 앱 빌드와 업로드가 성공했습니다. 로컬 실제 테스트 본문 55개 통과는 정식 XCTest와 별도의 근거입니다. 실제 마이크 발화·자동 입력·설치 앱 실행은 이 품질 비교에 포함되지 않습니다.

## 적용 판단

원문과 동일 초안을 비교해 한 번 다듬고, 선택형 Jev 보호가 켜져 있으면 최종 번역안을 검토하는 장치를 구현했습니다. 다듬기 실패·유효하지 않은 응답·로컬 보존 검사 실패는 자동 입력을 보류합니다. 옵션 해제·취소·기록 보관 철회 뒤 늦게 온 결과를 다시 표시하거나 입력하지 않는 회귀 검사도 통과했습니다.

현재 구현은 미리보기 전용이 아닙니다. 사용자가 실험 옵션을 켠 경우 정제가 성공하고 기존 입력 조건과 선택형 Jev 보호를 통과하면 최종안을 자동 입력합니다. 다듬기 성공과 Jev 검토 완료는 자연스러움·정확성 보증이 아닙니다. 기본값은 꺼짐으로 유지하며 일반 품질 향상을 입증했다고 배포하거나 메인에 병합하지 않습니다.

다음 평가에서는 같은 모델의 추가 요청만으로 해결되지 않은 문장 구조를 중심으로 더 높은 성능의 문장 모델 비교와 사람 원어민 판독을 분리해 검토해야 합니다. 이 후속에서는 모델 기본값·Jev 기준·메뉴바/Dock 정책을 변경하지 않았습니다.
