기존 상태를 `aa56f8a`로 먼저 커밋한 뒤, 세 에이전트가 입력 안전성, 암호화 저장소, 설정·복구 UX를 나눠 구현했다. 통합 담당이 AppModel의 시작·취소·처리 흐름을 수정했고, 에이전트 간 교차검토에서 발견한 빈 모델 설정과 학습 되돌리기 경합도 보강했다. 새 개발 빌드는 **0.1.5 (6)**이다. 공개 배포나 push는 수행하지 않았다.

## 함께 개선한 부분

- 마이크 권한 미결정·허용·거부·제한을 구분하고, 거부 상태에서는 시스템 설정으로 안내한다. 로그인 자동 실행은 저장 Bool 대신 실제 `SMAppService` 상태와 승인 필요 여부를 표시한다.
- 홈에서 키 저장과 API 연결 확인을 구분하고, 모델 준비 상태와 무음 입력 연습을 보여 준다. 페이지 이동 시 스크롤을 맨 위로 돌리고 현재 페이지의 접근성 선택 상태와 동작 줄이기를 반영한다.
- 잘못된 단축키 배열의 개수·중복·수정키를 검사해 해당 필드만 기본값으로 복구한다. 모델 ID가 비었거나 공백뿐이면 화면과 실제 요청이 같은 제공자 기본값을 쓴다.
- 처리 상태를 오디오 준비·음성 인식·문장 정리·입력 확인·저장으로 구분한다.
- 녹음 완료 실패와 encode 오류를 정상 종료와 나눠 처리하고, 일반 녹음의 남은 원음을 암호화 복구 대상으로 보관한다. 실제 마이크 분리·절전 시험은 이번에 수행하지 않았다.
- 정상 vault 옆의 불완전 staging 파일은 정상 자료를 먼저 검증한 뒤 격리한다. 고아 blob은 인증된 원래 만료 시점까지 보존하고, 만료 메타데이터를 읽을 수 없는 격리 파일은 발견 후 24시간 이내 정리 대상으로 관리한다. 앱이 실행되지 않는 동안 물리 삭제 시각을 보장하지는 않는다.

캐시 전사 출력: `내일 오후 3시에 회의가 있습니다. 회의 자료를 미리 준비해주세요.` 이 한 합성 문장의 성공은 자연 발화 정확도·한영 혼용·긴 녹음 품질을 입증하지 않는다.

저장소는 동일 크기 합성 원음으로 최적화 컴파일된 별도 프로세스를 측정했다. 9분 원음은 16,000 Hz × 16-bit × 540초 = 17,280,000 bytes로 표현했다.

| 9분 원음 3개 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| snapshot 3회 | 0.370–0.374초 | **0.000431–0.000653초** |
| metadata vault | 약 69.1 MB, 원음 포함 | **880 bytes**, 원음은 별도 암호화 파일 |
| 전체 workload 최대 RSS | 약 1,015 MB | **116.9 MB** |

RSS는 저장과 조회 전체 과정의 최고값이며 실행 중인 OpenNoType 앱의 실제 메모리 사용량이 아니다. 디스크에 원음을 보관하지 않는다는 뜻도 아니다. 새 원음 파일에는 암호화 인증 정보가 포함된다.

## 저장 형식과 되돌리기

기존 envelope·키 계정·파일 경로를 유지하면서 내부 version을 2로 바꿨다. v1 자료를 읽고 원음 blob을 쓰기·검증·동기화한 다음 metadata를 원자 교체한다. 실패하면 기존 v1 vault를 유지하며, 재시도는 검증된 동일 blob을 재사용한다. 기존 자료가 새 보관 한도를 넘더라도 마이그레이션 과정에서 자르지 않는다. 삭제도 metadata commit 이후 실행하고, 중간 종료 후 다음 실행에서 이어서 처리한다.

**구버전 바이너리는 v2를 읽지 못한다.** 소스 커밋만 되돌리는 것은 데이터 다운그레이드가 아니다. 실제 앱 재실행 전에 기존 암호화 저장소를 `build/private-backups/20260910-075538/Data`에 복사하고 vault 바이트 일치를 확인했다. 이 로컬 백업·사용자 데이터·키는 Git에 포함하지 않았다. 새 버전에서 추가한 기록이 생긴 뒤 이전 백업으로 복구하면 그 이후 변경은 포함되지 않으므로, 단순 덮어쓰기를 해서는 안 된다.
