# 메뉴바 대기와 관리 창 자동 표시 수정

검증일: 2026-10-12. 대상은 main `69acc2e` 위의 로컬 수정본이며, 앱 표기는 기존 `0.2.7 (43)`이다. 새 공개 릴리스나 원격 저장소 반영을 뜻하지 않는다.

## 변경

- 관리 창의 최초 프레임을 투명하게 준비하고 WindowServer 표면이 생긴 뒤 숨긴다. 첫 합성 전에 창을 닫아 재열기 때 빈 창이 되는 문제를 피한다.
- 관리 창 복원을 끄고, 사용자가 요청한 열기는 대기 중인 초기 숨김보다 우선한다.
- 녹음 상태 표시와 관리 창 열기 콜백을 앱 수명에 연결한다. 메뉴바의 열기·설정·사용량과 Finder 재열기 경로를 유지한다.
- 로그인 실행 설정에 창 없이 메뉴바에서 대기한다는 설명을 추가한다.

## 자동 검사

`swift test --arch arm64 --sdk "$(scripts/macos-preflight.sh --print-sdk)" --filter 'MenuBarLaunchTests|StatusBarControllerTests|AppStartupTests|UpdaterTests'`: **44개 통과, 실패 0개**.

초기 숨김, 표면 준비 지연, 명시 열기와 숨김의 경합, 창 재생성, 디자인 미리보기, 상태 창·녹음 패널 제외, 창 복원 거부, 관리 창 없이 녹음 표시 초기화, 기존 시작 준비와 업데이트 종료 보호를 검사했다. 창 조작 검사는 대역을 사용하며 실제 녹음이나 API 요청을 하지 않는다.

## 설치와 실제 실행

- release 빌드와 `codesign --verify --deep --strict` 통과. 기존 앱과 같은 `TechJuice Local Code Signing` 서명 조건으로 `/Applications/OpenNoType.app`을 교체했다.
- 설치 직전과 직후 사용자 상태 파일 **147개**의 SHA-256이 일치했다. 이전 앱과 사용자 상태는 로컬 백업에 보존했다.
- 새 프로세스가 설치 경로에서 단일 실행 중임을 확인했다. 최초 시작에서는 CUA가 관리 창을 찾지 못했고, Finder에서 앱을 명시적으로 다시 열자 관리 창이 표시됐다.
- 실제 창 스크린샷으로 정상 렌더링과 새 로그인 실행 안내를 확인했다. 창을 닫은 뒤 Finder에서 다시 열어도 관리 창이 정상 표시됐다. 검증 후 창을 닫고 프로세스를 유지했다.
- 로그인 자동 실행은 설치 경로에 등록되어 있고, 체크 상태·저장된 키의 준비 상태·마이크·손쉬운 사용 권한이 유지됐다.
- 실행 검증 후 보관 데이터 **146개**의 해시가 그대로였다. 설정 plist는 창 프레임과 JSON 직렬화 순서가 바뀌었으며, 저장된 설정 JSON 내용은 동일했다.

## 검증 경계

- 실제 재부팅·로그아웃과 로그인 자동 실행은 수행하지 않았다. 최초 실행 경로와 창 복원 거부를 코드·자동 검사·앱 재실행으로 확인했다.
- 실제 녹음, 외부 앱으로의 입력, 녹음 상태 표시의 실제 오디오 경로는 이번 검증 범위에 포함하지 않았다.
- WindowServer 표면이 60회 재시도 안에 생기지 않는 예외 경로에서는 창의 불투명도를 복구해 수동 열기가 막히지 않도록 한다. 이 복구 경로는 자동 검사로 확인했으며 실제 로그인 환경에서 재현하지 않았다.
