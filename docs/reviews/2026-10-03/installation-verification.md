# 설치·음성 입력·업데이트 검증표

이 검증표는 2026-10-03 전반 검토에서 남은 실제 환경 검증을 구분한다. 합성 bundle의 설치 회귀 테스트 성공은 자연 음성 정확도, 모든 앱의 자동 입력, 실제 Sparkle 업데이트 성공을 뜻하지 않는다. 사용자의 기존 API 키·기록·설정을 시험용 데이터로 복사하거나 전송하지 않는다.

## 확인 근거와 미확인 범위

| 영역 | 이 개선 작업의 확인 범위 | 별도로 필요한 확인 |
| --- | --- | --- |
| 공개 설치 트랜잭션 | 임시 폴더의 합성 릴리스로 다운로드·서명·하드웨어 응답을 모의하고, 실제 macOS plist·ZIP·파일 교체·quarantine 도구를 검증 | 실제 공개 ZIP 검증과 설치 후 첫 실행 |
| 이전 앱 보존 | 정상 교체 후 권한 `700`의 고유 백업 폴더 보존, 명시적 삭제, 오류 복원·복원 실패 시 백업 보존, 설치 중 bundle 교체 거부 | 실제 이전 버전으로 수동 복원 후 설정·기록 호환성 |
| API 파이프라인 | 소스·회귀 테스트에서 요청 조건과 결과 처리를 검증 | 실제 합성 발화를 녹음해 STT → 정리 → Jev → 입력까지 연결 |
| 앱별 입력 | 입력 대상·정책의 소스·회귀 테스트 | 아래 9개 앱에서 사람이 실제 포커스와 입력 결과를 확인 |
| Sparkle | 공개 배포 채널·업데이트 검증 규칙과 합성 테스트 | 서명된 공개 이전 버전 → 공개 새 버전의 실제 업데이트 |

이 문서 작성 단계에서 마지막 세 행의 실제 환경 시험은 **미실시**이다. 미확인 항목은 통과로 표시하지 않는다. 개별 테스트 실행 결과는 해당 개발 작업의 로그에 남기고, GitHub CI·앱 빌드·설치·실제 입력 결과를 각각 기록한다.

2026-10-03 로컬 실행에서 `python3 -m unittest scripts.test_install_release -v`는 합성 설치 회귀 **23개, 실패 0개(47.837초)**로 완료했다. `bash -n scripts/install-release.sh`도 통과했다. 시험 대상은 임시 폴더의 합성 bundle뿐이며, 실제 설치 앱·사용자 데이터·API 키에 접근하지 않았다.

## 새 Mac과 첫 실행

깨끗한 별도 macOS 사용자 계정 또는 시험용 Mac에서 진행한다. API 키는 시험용 키를 해당 Mac의 Keychain에 저장하고, 키 값·사용자 개인정보·실제 대화가 로그나 화면 캡처에 나타나지 않도록 한다.

| 환경 | 실제 확인 상태 | 확인할 항목 |
| --- | --- | --- |
| Apple Silicon + 최소 지원 macOS 14 | 미실시 | 다운로드, Gatekeeper 앱별 허용, 첫 실행, API 연결, 마이크, 손쉬운 사용, TextEdit 입력 |
| Apple Silicon + 개발에 사용하는 macOS | 이 체크리스트로 재검증 필요 | 현재 bundle 버전·commit, 키 유지, 권한 유지 또는 재허용 안내, 녹음·입력 |
| Apple Silicon + Rosetta 터미널 | 합성 하드웨어 판단 시험, 실제 환경 미실시 | `hw.optional.arm64` 확인, 설치·첫 실행 |
| `/Applications`에 쓰기 권한 없는 계정 | 합성 경로 안내 시험, 실제 환경 미실시 | 사용자 Applications 설치와 첫 실행 |
| 기존 정상 앱이 실행 중인 상태 | 합성 교체 거부 시험, 실제 환경 미실시 | 다운로드 전 또는 교체 전 중단, 기존 앱·데이터 보존 |
| 기존 앱·설정이 있는 계정 | 합성 bundle 보존 시험, 실제 환경 미실시 | 모델·언어·Jev 모드·사전·보관기간·Keychain 유지 |

1. 실행 전과 후의 bundle 버전·build·commit을 기록한다. 소스 버전은 `Resources/Info.plist`, 설치 버전은 설치 위치의 `Contents/Info.plist`에서 읽는다.
2. 설치 스크립트의 검증 결과와 이전 bundle 백업 경로를 기록한다. 백업 위치의 앱을 직접 실행하지 않는다.
3. 설치 위치의 앱 하나만 연다. 최초의 영어 기본 언어와 한국어 선택이 동작하고, 명시해 둔 언어·모델·Jev 설정은 업데이트 후 유지되는지 확인한다.
4. 앱 준비 화면에서 API 연결, Keychain, 마이크, 손쉬운 사용 상태를 확인한다. macOS의 인증·권한 승인은 사람이 직접 처리한다. 요구되지 않은 재허용이나 보안 설정 우회를 시험 절차로 추가하지 않는다.
5. 녹음 없는 입력 테스트를 먼저 수행한 뒤, 아래 합성 발화를 직접 읽어 실제 녹음한다. 녹음 성공·텍스트 생성·Jev 판단·대상 앱 입력 완료를 각각 구분한다.
6. 첫 실행과 입력이 확인되기 전에는 이전 앱 백업을 지우지 않는다. 문제가 있으면 [수동 복원 절차](../../mac-installation.md#이전-앱으로-수동-복원)를 따른다. 설정·기록·키를 삭제하지 않는다.

## 자연 음성 → STT → 문장 정리 → Jev → 대상 앱

실제 음성 검증에는 미리 만든 텍스트를 API에 직접 보내는 시험을 대신 사용하지 않는다. 동일한 음성·설정으로 비교하고 각 모델·모드와 시작/종료 시각을 기록한다. 기본 받아쓰기와 표현 강도가 높은 모드는 따로 비교하며, 의도적으로 요약한 결과를 기본 받아쓰기의 누락 허용 기준으로 삼지 않는다.

| 합성 발화 | 확인할 결과 |
| --- | --- |
| “나는 A를 개발하고 싶어서 B를 리서치하고 있어요. B를 리서치하고 있는데요. 음, 그런데 말이죠. B를 리서치할 때 또 필요한 것이 C인데요.” | 반복·군말 제거 후 A를 개발하려는 목적, B 리서치, 필요한 C를 모두 유지 |
| “제브 제이 이 브이로 오픈노타입을 개선하고 싶어요.” | 의도한 `JEV`, `OpenNoType` 표기와 공백 없는 철자 정정 |
| “JEV로 OpenNoType을 개선하고 싶어요.” | 한국어 문장 속 영어 발음·앱 이름 보존 |
| “회의는 세 시에 있고, 제가 아니라 네 명이 참석해요.” | 시간과 인원을 별개로 보존, 인원 정정을 시간 정정으로 오해하지 않음 |
| “회의는 세 시, 아니 네 시에 시작해요.” | 같은 시간 역할의 정정은 네 시로 정리 |
| “I don't think it's necessary.” | 축약형을 자연스럽게 정리하더라도 가짜 인용문 오류로 보류하지 않음 |
| “인용문 ‘Don't change this’는 그대로 두세요.” | 실제 인용문은 유지 |
| “아직 확정되지 않았고, 승인되면 다음 주에 시작할 수 있어요.” | 부정·조건·불확실성·시점을 보존 |

Jev 모드별로 `사용 안 함`, `입력 후 검토·학습`, `입력 전 보호`, `입력 전 교정`을 구분한다. 입력 전 모드에서는 검토·한 번의 교정·재검토 결과와 최종 입력 여부를 확인한다. 입력 후 모드에서는 검토 완료 전 최초 입력이 가능한지, 검토가 기존 입력을 변경하지 않는지 확인한다. 재인식 옵션 등으로 기다림이 추가되는 경우 그 이유와 실제 지연도 기록한다.

인위적인 실패는 시험용 환경에서만 만든다. 필수 Jev 키 없음, 응답 시간 초과, 길이 초과, 교정 후 재검토 실패에 대해 유료 STT·정리 요청이 불필요하게 먼저 발생하는지, 원문/결과를 수동으로 확인할 수 있는지, 보류·실패 사유가 정확히 나타나는지 확인한다.

### 9개 앱 입력 매트릭스

모든 행은 실제 재검증 전까지 **미실시**이다. 해당 앱이 설치되어 있지 않으면 사유와 함께 `미실시`를 유지한다. 입력 시험은 빈 문서·초안·시험용 채널에서 하고 전송 버튼이나 Enter로 메시지를 보내지 않는다.

| 앱·입력 대상 | 녹음 없는 입력 | 실제 발화·Jev | 확인할 동작 |
| --- | --- | --- | --- |
| TextEdit 빈 일반 텍스트 문서 | 미실시 | 미실시 | 기본 AX 입력·붙여넣기, 입력 완료 판정 |
| Notes 시험용 노트 본문 | 미실시 | 미실시 | 서식 있는 본문, 커서 위치, 기존 내용 보존 |
| Safari 시험용 HTML `textarea` | 미실시 | 미실시 | 브라우저 포커스·AX, 자동 전송 없음 |
| Chrome 시험용 HTML `textarea` | 미실시 | 미실시 | 브라우저 포커스·AX, 자동 전송 없음 |
| VS Code 저장하지 않을 텍스트 편집기 | 미실시 | 미실시 | Electron 편집기, 줄바꿈·선택 범위 |
| Slack 시험용 작성창 | 미실시 | 미실시 | 작성창 포커스, 전송 없음, 확인 불가 시 정확한 안내 |
| Mail 받는 사람 없는 초안 본문 | 미실시 | 미실시 | 본문 위치, 기존 초안 보존, 전송 없음 |
| Pages 시험용 문서 본문 | 미실시 | 미실시 | 문서 본문 AX, 서식·선택 내용 보존 |
| Codex 비어 있는 입력창 | 미실시 | 미실시 | Electron/Web 입력창, 자동 전송 없음 |

각 행에 대해 앱 버전, macOS 버전, 입력 방법, 보류/실패 사유, 전체 지연과 주요 단계의 시간을 기록한다. 기본 한국어 입력 상태에서도 `ㅍ` 한 글자처럼 단축키의 일부가 삽입되지 않아야 한다. 입력 완료를 관찰할 수 없는 앱에서는 결과를 미확인으로 표시하며, 글이 보였다는 이유만으로 AX 확인 성공을 주장하지 않는다.

## 실제 공개 이전 버전 → 새 버전 Sparkle 업데이트

새 개발 commit이나 로컬 설치만으로 이 항목이 완료되지 않는다. 실제 시험에는 같은 공개 업데이트 채널의 서명된 이전·새 릴리스 두 개와 올바른 appcast가 필요하다. 이 작업에서 새 공개 latest 릴리스가 발행되지 않았다면 **시험 조건 미충족·미실시**로 남긴다.

1. 별도 계정에 공개 이전 버전을 설치하고, 합성 사전 항목·시험용 기록·언어·모델·Jev 모드·보관기간을 설정한다. 시험용 Keychain 키와 macOS 권한만 사용한다.
2. 이전 버전의 `CFBundleShortVersionString`, `CFBundleVersion`, 업데이트 채널, `SUPublicEDKey`, 서명·quarantine 상태와 설정 값을 기록한다. 키 값과 기록 본문을 보고서에 넣지 않는다.
3. 앱의 업데이트 확인으로 새 공개 버전을 발견하는지, 정확한 버전·채널·안내가 나타나는지 확인한다. community 릴리스와 notarized 릴리스를 혼동하지 않는다.
4. 업데이트 설치·재실행 후 실행 중인 앱이 하나인지, 실제 실행 위치·버전·build가 새 bundle과 일치하는지 확인한다.
5. 언어·STT/문장 모델·Jev 연결/검토 모드·표현 강도·사전·기록·보관기간을 다시 확인한다. Keychain은 키를 읽을 수 있다는 상태와 실제 시험 요청 성공으로 확인하고, 키 값을 출력하지 않는다.
6. 마이크·손쉬운 사용의 유지 또는 필요한 재허용 안내를 확인하고 TextEdit에서 녹음 없는 입력·실제 합성 발화 입력을 재시험한다. 서명 교체 후 재허용이 필요했다면 이를 기록한다.
7. 별도 시험 환경에서 잘못된 서명·다른 채널·낮은 build의 업데이트가 거부되고 기존 앱이 유지되는지 확인한다. 실제 공개 feed를 시험용 잘못된 값으로 변경하지 않는다.

통과 판정에는 두 실제 공개 버전·appcast URL·macOS 환경·보존 전후 결과·실제 입력 증거가 필요하다. 합성 updater backend 시험이나 릴리스 ZIP의 `--verify-only` 성공만으로 Sparkle의 실제 교체·설정·권한 보존을 통과 처리하지 않는다.
