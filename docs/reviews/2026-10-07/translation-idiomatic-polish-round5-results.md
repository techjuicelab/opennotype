# 번역 관용 표현 개선 5차 실측 결과

2026-10-07, 후보 `4261228f002ae74449cdc8e5f84afba4ecdc0249`를 설치본36의 소스 기준인 `e5bfe2bdf0196fbc5587ca98025c8a4ab56aa8bd`와 6쌍으로 비교했다. **실제 12회 응답을 네 AI가 독립 판독했고, 이번 기준에서 명확한 의미 실패를 표시한 출력은 없었다.** 알려진 일본어 전달 의도·도입 제안 두 사례는 모두 후보 선호였지만, 일부 긴 표현과 영어 완곡 표현·시간 참조에 대한 주의는 남았다. 이 한정된 근거로 제품 반영을 진행하는 판단이며 전반적인 번역 품질이나 원어민 수준을 보장하지 않는다.

## 정책과 비교 범위

사용자가 확인한 후속 원칙은 **발화 내 문맥상 화자 자신의 일로 자연스럽게 읽히는 생략 주어를 `I`로 표현할 수 있다**는 것이다. 모든 생략 행동을 화자에게 배정하지 않으며 명시된 타인, 명시적으로 미정·불명인 수행자, 각 팀의 소유 관계를 보존한다. 판단·결정·약속 소유자와 행동 수행자를 구별하고, 화자를 근거 없이 `we`나 팀으로 넓히지 않는다. 일본어의 자연스러운 주어 생략도 허용한다. 초안은 사실의 근거가 아니며 원문 발화의 문맥을 따른다.

이 원칙은 이번 신규 기준에 적용했다. 과거의 미지정 수행자 기준을 사후에 바꾸거나 기존 영어 사례의 실패 판정을 통과로 고쳐 쓰지 않았다. 후보와 기준의 차이에는 앞선 관용 표현 지침과 이번 수행자 정책이 함께 포함되므로 결과를 어느 한 문구의 효과로 분리해 단정할 수 없다.

OpenRouter `openai/gpt-6-luna`, `medium`으로 **12회 모두 HTTP 200·응답 반환·보호 검사 통과**, 자동 재시도 0회, Jev 0회였다. 제공자가 12개 usage 이벤트에 보고한 비용 합계는 **US$0.004119510**이다. 최종 청구액 보장은 아니며 HTTP·파싱·보호 검사 성공을 언어 품질 합격으로 환산하지 않는다.

초기 인증 시도는 timeout으로 frozen runtime 진입 전 종료되어 API 호출 0회였다. 이후 사용자 요청에 따른 인증 준비 확인을 거쳐 실제 12회를 완료했다. 인증 확인 자체를 모델 호출로 세거나, 처음 미호출인 6쌍을 HTTP·품질 실패로 집계하지 않는다.

네 판독 파일의 SHA를 `2026-10-07T14:34:54.917261+00:00`에 모두 확인한 뒤 라벨 대응표를 공개했다. 원문·실패 방향·지침 설계를 아는 AI 평가이므로 **arm label만 가린 판독**이다. UI는 자기 파일을 잠그기 전 대응표·raw 결과·다른 판독·에이전트 상태 요약을 열지 않았다.

네 판독자는 같은 **12개 출력·6쌍**의 모든 arm에 `meaning_pass=true`를 기록했다. 이는 의미 해석 위험이나 문체 주의가 없다는 뜻이 아니다. 네 AI의 판독을 48개 독립 출력이나 24개 독립 쌍으로 늘려 세지 않으며, 선호 수를 품질 합격률·통계적 효과로 사용하지 않는다.

- `TIPK03_ja_intent`: 후보의 `言おうとしていたこと`는 전달하려던 내용을 더 자연스럽게 연결해 네 판독자가 모두 선호했다. 기준의 `どういう意味で言ったのか`도 문맥상 전달 의도로 읽히므로 명확한 뜻풀이 오역으로 세지 않았다. UI는 후보의 `少しまとまりのないものになっても`라는 무거운 틀을 남은 주의로 적고 양쪽 유창성을 2로 평가했다. 다른 세 판독자의 후보 점수는 3이다. 개선 선호와 일본어 전체 해결을 구별한다.
- `TIPK04_ja_adoption`: 양쪽 모두 취지 이해, 즉시 도입 우려, 전면 배제 부정, 소규모 시험 후 확대 판단을 보존했다. 후보가 도입하지 않는 선택을 직접 가리켜 네 판독자가 모두 선호했다. 기준의 `全面的にやめよう`도 제안을 접는 뜻으로 읽힐 수 있어 이미 진행 중인 활동으로 확정한 의미 실패로 세지 않았다. UI는 후보의 긴 부정 틀에도 주의를 남겼다.
- `TIPR5501_en_contextual_personal_work`: 자신의 발표 자료를 정리하는 문맥이 후속 `I`를 뒷받침한다. 사진이 오늘 도착한다는 조건, 내일 오전까지의 완료 가능성과 별도 전달 약속 부정은 양쪽 모두 유지했다. root는 기준의 간결한 연결을, UI는 후보가 완료 기한과 전달 시점을 별도로 명시한 점을 약하게 선호했고 core·verification은 동률이었다. root·UI는 기준의 마지막 `by then`이 원문의 ‘내일 오전에 전달’을 ‘그때까지 전달’로 연결하는 작은 시간 범위 위험을 적었지만 명확한 의미 실패로 세지 않았다. 후보의 `I do think I may be able`도 조심스러운 인정으로 가능한 영어이며 헤지 수만으로 오류나 필수 삭제 대상으로 삼지 않는다.
- `TIPR5502_ja_explicit_other_and_speaker_roles`: 명시 타인의 금요일 오전 장비 두 대 점검과 화자의 결과 수령 후 보고서 정리를 분리하고, 추가 부품 교체 부탁의 부정도 양쪽 모두 유지했다. `だけ`의 한정 위치 차이는 허용되는 변형으로 네 판독자 모두 동률이었다.
- `TIPR5503_en_explicit_unknown_installer`: 양쪽 모두 설치 담당자 미정, 화자의 날짜 확인만 하는 역할, 금요일 시작 가능성과 안내판 세 개 전체의 당일 설치 약속 부정을 유지했다. 후보의 `installer hasn’t been chosen`과 공간의 사용 가능 날짜 표현은 네 판독자가 모두 선호했다. 부정된 `promise to install`만으로 화자를 실제 설치자로 확정하지 않았다.
- `TIPR5504_ja_two_teams_conditional_trial`: 두 팀 각각의 시안, 먼저 시험할 안 미정, 이번 주 승인 조건과 다음 주 한 차례 시험 가능성, 공동 참여 합의 부정을 양쪽 모두 유지했다. 합의에 연결하는 조사 차이는 자연스러운 복수 표현으로 네 판독자 모두 동률이었다.

## CI·후보 앱·반영 경계

실측 소스 `4261228`의 초기 CI는 기존 `DictationTranslationTests`의 옛 문구 exact assertion 한 줄 때문에 실패했다. 이 실패 이력은 보존했다. 후속 `2d6a9ff90c60e989749d559d1b30783eddf0bb2f`는 그 assertion 한 줄만 새 정책 문구로 갱신했으며 제품 소스28개와 Info는 실측 소스와 바이트가 같다. 초기 소스 CI가 처음부터 통과했다고 쓰지 않는다.

후속 [PR CI 37636889016](https://github.com/techjuicelab/opennotype/actions/runs/37636889016)과 [push CI 37636881157](https://github.com/techjuicelab/opennotype/actions/runs/37636881157)는 모두 성공했다. 각 실행은 고유 XCTest **899개: 897 통과·기존 LocalAudio 2개 건너뜀·실패 0개**, Python **198개 통과·건너뜀 0개**다. 관련 35개, golden, 개발 앱 빌드·artifact 연결도 확인했다. 이 검사는 모델 문장 품질이나 실제 마이크·자동 입력의 증거가 아니다.

로컬 후보40은 0.2.4(40), arm64, 최소 macOS 14.0, `LSUIElement=true`이며 6개 구성요소의 strict ad-hoc 서명을 확인했다. 설치본36과 entitlements·업데이트 4개 정책 필드가 같고 동결 소스28·커밋·빌드 로그 연결도 일치했다. 실행파일 SHA는 `5c1c41edf1bf100e3ec822df0fe39eae74cbf372e84c63faea618ac1eb431e11`, tree SHA는 `a13c0d241eb129f7359be0a1c1a395a298db11bbcc6c745ca5e88a073a45bc57`이다. tree 범위는 파일 바이트·모드·링크 대상·디렉터리 모드이며 xattr·소유자·시각은 제외한다. 소스 연결 기록은 바이너리에 Git commit의 암호학적 증명이 내장되었다는 뜻이 아니다.

이미 만든 후보40을 test-only 후속 CI에 연결하는 설치 보조 게이트는 `docs/` 또는 정확한 `Tests/OpenNoTypeCoreTests/DictationTranslationTests.swift` 경로만 후속 변경으로 허용한다. rename을 끈 NUL 구분 경로 검사와 별도의 제품 빌드 입력 동일성 검사를 함께 수행한다. 이전 준비·번들 proof는 덮어쓰지 않고 별도 bridge proof로 남겼다. 이것은 설치 완료나 앱 실행의 증거가 아니다.

제품 반영은 사용자 정책과 이번 제한된 보존·관용성 관찰에 따른 한정 채택이다. 기본 모델·사용자 선택·추가 호출 흐름을 이번 지침 때문에 자동 변경하지 않는다. 이 실험에는 실제 마이크, Jev, 대상 앱 삽입, 메뉴바 클릭, 실제 업데이트 교체가 없었다. 설치에는 현재 사용자 작업 확인, 정상 종료와 설정·암호화 데이터 백업·동일성 검증이 별도로 필요하다. 프로세스 존재·창 부재·CUA 인벤토리만으로 idle이나 미실행을 추론하거나 강제 종료하지 않는다.
