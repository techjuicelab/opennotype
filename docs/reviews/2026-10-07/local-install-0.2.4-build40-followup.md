# 로컬 0.2.4(40) 실행 후속 확인

2026-10-07, [설치·첫 실행 기록](local-install-0.2.4-build40.md) 이후의 root 관측을 추가한다. Keychain·설정 준비 완료 뒤에는 macOS 시스템 설정의 켜진 스위치와 앱의 ‘허용 필요’ 표시가 한동안 일치하지 않았다. 이후 root의 앱 UI 관측에서 마이크·손쉬운 사용이 모두 ‘허용됨’으로 바뀌었다. root는 권한 재적용을 수행하지 않았다. **5초 입력 연습 한 차례는 의도한 TextEdit가 아닌 Codex를 캡처해 보안 입력 보호에서 보류됐다.** 현재는 사용자가 직접 TextEdit 빈 본문을 선택하는 무녹음 입력 연습을 기다리며, 실제 자동 입력 성공을 주장하지 않는다.

이 문서는 이전 보고서를 덮어쓰지 않는 후속 기록이다. 초기 불일치 항목은 `2026-10-07T17:40:10.523448+00:00`의 후속 proof에, 이후 ‘허용됨’ 표시와 입력 진단은 `2026-10-07T17:48:58.940999+00:00`의 입력 연습 proof에 연결한다. 사용자 수동 시험 결과는 아직 대기 중이다. UI 담당자가 앱이나 보안 설정을 조작하거나 개인 기록·키 값을 열지 않았다.

## 17:40 UTC의 준비 완료와 권한 표시 불일치

| 항목 | root 후속 관측 |
| --- | --- |
| 앱 초기화 | Keychain·설정 준비 배너 사라짐 |
| 저장 키 | 홈에서 AI 키의 저장 상태와 Jev 키 준비 상태 확인; 값은 기록하지 않음 |
| macOS 설정 | `sysDeviceControl`·Microphone의 OpenNoType 스위치 모두 켜짐 |
| 앱 Mac 일반 | 마이크·손쉬운 사용 모두 ‘허용 필요’ |
| 입력 연습 | 비활성 상태; 실행·문장 삽입 없음 |

키의 저장·준비 표시는 실제 제공자 API 연결 시험과 다르다. 이 후속 확인에서 음성 녹음·번역 API·Jev 검토·대상 앱 입력을 실행하지 않았다. macOS의 켜진 스위치와 앱의 허용 필요 표시가 일치하지 않는 관측을 권한 유실·키 유실·특정 서명 문제라는 확정 원인으로 바꾸지 않는다.

## 서명 식별자에 관한 원인 후보

root의 읽기 검증에서 이전36과 설치40의 designated requirement는 각각 `cdhash H"0fe8940fbfdb5b4435062b4420493f2b92497daa"`, `cdhash H"a6eff9799f02ad35ef1c90db987c8e64ad735e9c"`로 달랐다. Apple은 macOS가 마이크 접근 승인과 앱의 designated requirement를 연결하고, ad-hoc 서명의 requirement는 특정 코드 버전에 묶여 권한 선택의 지속성에 문제가 생길 수 있다고 설명한다. [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)

따라서 빌드별 식별자 변화는 권한 표시 불일치의 유력한 원인 후보였으나 확정 진단은 아니다. TCC 데이터베이스나 실제 승인 레코드 연결은 읽지 않았고 손쉬운 사용의 원인도 확정하지 않았다. 이후 재적용 없이 앱 표시가 ‘허용됨’으로 바뀐 사실도 함께 보존한다. 문서의 일반 설명이나 서명 차이를 근거로 권한 리셋·보안 예외를 자동 실행하지 않는다.

## 정상 종료·재실행 뒤에도 유지된 상태

root는 앱의 정상 메뉴 종료 뒤 AppKit에서 실행 앱이 없는 상태를 확인하고 정확한 `/Applications/OpenNoType.app`을 다시 실행했다. 새 PID는 **41392**다. 재실행 뒤에도 준비 완료·저장 키 상태가 유지됐고 입력 연습은 여전히 비활성이었다. 정상 메뉴 종료와 프로세스 부재 관측은 직접 exit code 확인을 뜻하지 않는다. 앱 경로나 PID 관측을 실제 메뉴바 상태 아이콘 클릭·Dock 시각 검증으로 대체하지 않는다.

이 재실행만으로 권한 문제가 해소됐다고 주장하지 않는다. 초기화가 진행 중이던 첫 실행 상태와 이번 준비 완료 뒤 권한 불일치를 구별한다. 실제 상태 아이콘 클릭·창 닫기와 재열기·대상 앱 입력·음성 번역 성공은 이번 후속 관측으로 입증되지 않았다.

## 승인 대기 당시와 최신 상태

17:40 UTC의 불일치 상태에서는 macOS 권한 스위치를 껐다 다시 켜는 작업에 대한 사용자 승인을 요청했다. 이 작업은 보안 설정 변경이므로 승인 없이 실행하지 않았다. 그 뒤 사용자 답변을 받기 전에 root가 앱 UI를 다시 읽었고 두 권한 모두 ‘허용됨’으로 바뀐 것을 확인했다. 따라서 기존 권한 재적용 요청을 실행하지 않으며 root에 의한 권한·보안 설정 변경은 0이다. 사용자 측에서 어떤 조작을 했는지는 이 관측만으로 단정하지 않는다.

권한 표시를 확인한 뒤 root는 TextEdit의 새 빈 문서에서 무녹음 입력 연습을 진행했다. 앱의 ‘허용됨’ 표시를 실제 삽입 성공으로 대체하지 않으며 실제 음성 번역·모델 호출은 이 무API 시험과 구분한다.

메뉴바 추가 관측을 위해 SystemUIServer를 CUA에서 선택하려 했으나 timeout으로 UI를 읽지 못했다. 이는 OpenNoType 상태 아이콘이 없다는 증거가 아니다. 실행의 accessory raw1 메타데이터는 유지되며 실제 상태 아이콘 시각 확인·클릭과 Dock 시각 확인은 미관측으로 남긴다.

## 권한 허용 뒤 무녹음 입력 연습 실패

처음에는 입력 연습을 준비한 상태에서 도구로 `⌥Space`를 전달했으나 단축키가 앱에 처리됐는지 확인되지 않았고 본문에는 비분리 공백만 나타났다. root는 시험 문서의 공백을 정리하고 준비 상태를 취소했다. 이를 완료된 입력 연습이나 정상 핫키 동작의 증거로 세지 않는다.

이후 홈의 입력 연습 설명을 펼쳐 ‘5초 뒤 입력 연습’을 한 번 실행하고 도구의 TextEdit Raise·본문 클릭을 시도했다. 그러나 이 조작으로 TextEdit가 실제 캡처 대상이 되지는 않았다. 대기 뒤에도 본문은 비어 있었으며 앱은 설정 화면으로 이동해 ‘비밀번호 입력란이거나 보안 입력이 켜진 상태’라는 취지의 실패 배너를 표시했다. 마이크·손쉬운 사용의 ‘허용됨’ 표시는 유지됐다.

정확한 앱 진단은 다음과 같다. 캡처 전후의 본문 값·선택 범위·스냅샷은 읽지 않았다.

| 진단 항목 | 관측값 |
| --- | --- |
| 의도한 대상 | 새 빈 TextEdit 문서 |
| 실제 캡처 대상 | `com.openai.codex` |
| 권한·보호 표식 | `trusted=true`, `secure=true`, `role=secure` |
| 값·범위·스냅샷 | `value=skipped`, `range=skipped`, `snapshot=skipped` |
| 입력 결과 | `notSubmitted.secureInput` |
| TextEdit 고정 시험 문장 | 없음 |

따라서 이번 관측은 Codex를 대상으로 한 보호 보류이며 TextEdit의 비밀번호 입력란이나 전역 보안 입력 상태를 확정하는 근거가 아니다. TextEdit를 실제 대상으로 캡처한 자동 입력 경로도 아직 시험하지 못했다. 좌표 클릭·스크롤은 `noWindowsAvailable`, SystemUIServer 선택은 timeout, 해당 Mac surface의 `cua.computer.launch_app`은 사용 불가였으므로 도구의 전경 전환 한계를 기록한다. 보안 입력 우회·권한 변경·음성 녹음·번역 API·Jev 호출은 하지 않았다.

root는 입력 연습을 다시 준비한 뒤 사용자가 TextEdit의 빈 본문을 직접 클릭하고 `⌥Space`를 한 번 누르도록 요청했다. 이는 준비된 고정 문장의 무녹음·무API 입력 연습이며 실제 받아쓰기·번역 시험과 다르다. 현재 결과는 대기 중이다. 앱 준비와 두 권한의 허용 표시, 번역 다듬기 토글 꺼짐·목표 언어 일본어도 관측했으며 해당 값을 바꾸지 않았다.

## CI와 로컬 증거 연결

문서 반영 main `fc2bd6e88a5fc555ce99d5829b2b9bf914c72ac0`의 [CI 37639754892](https://github.com/techjuicelab/opennotype/actions/runs/37639754892)는 root의 감사에 따라 고유 XCTest 899개(897 통과·기존 2개 건너뜀·실패 0개), Python 198개 통과를 확인했다. 문서 HEAD의 기능·빌드 검사가 성공한 근거이며 실제 권한 승인·자동 입력·번역 품질이 추가 검증됐다는 뜻은 아니다.

## 유지되는 범위

설치본은 로컬 0.2.4(40), 공개 다운로드는 v0.2.3(35)이며 [5차의 한정 채택 근거](translation-idiomatic-polish-round5-results.md)와 기본 꺼짐인 번역 다듬기 정책은 그대로다. 이번 관측을 번역 자연스러움의 추가 실측이나 원어민 사람 검수로 세지 않는다. 설치 파일·설정·암호화 데이터 보존에 관한 근거는 이전 설치 보고서에 유지한다. 이 문서에는 비밀 값·백업 본문·개인 발화를 노출하지 않는다.
