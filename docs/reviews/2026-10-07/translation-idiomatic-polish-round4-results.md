## 소스와 실제 호출 범위

공유 유창성 지침의 ownership 관련 두 줄만 좁게 명료화했다. 판단·결정·약속의 소유자와 각 행동의 수행자를 따로 식별하고, 화자의 판단이나 완료 약속 부정만으로 완료 수행자를 확정하지 않도록 했다. 해당 행동절이 명시적 또는 언어적으로 뒷받침하는 개인 계획·희망의 수행자는 유지한다. 기존 행동 단계·부정·조건·약속·의무와 자연스러운 수동태·명사절의 허용 범위는 그대로다. 정답 문장이나 특정 단어 금지 목록을 넣지 않았다.

후보 Native 파일 SHA는 `248cb90f9620b708ab501b0a112e6092353281e42e178a9d90d0c210c9fad617`이다. Refinement 파일은 `ccb9f8db3f31e7b55c758abb9084065052973eaefeb5f3daed6831bca1f778a5`로 그대로이며 공유 지침을 참조한다.

OpenRouter `openai/gpt-6-luna`, `medium`으로 **12회 모두 HTTP 200·응답 반환·보호 검사 통과**, 자동 재시도 0회, Jev 0회였다. 제공자가 12개 usage 이벤트에 보고한 비용 합계는 **US$0.003204960**이다. 이는 최종 청구액 보장이 아니다. HTTP·파싱·보호 검사 성공을 의미 보존이나 자연스러움 합격으로 환산하지 않는다.

| 비교 묶음 | 입력 관계 | 쌍 | 호출 |

**이번에는 1차 생성 호출이 0회다.** 새 초안은 실제 1차 생성 결과를 이어 받은 것이 아니라 작성한 합성 초안이다. 따라서 초기 번역 생성이나 원문→생성→정제의 연속 처리 품질을 검증한 결과가 아니다. 3차의 신규 생성·최종 종속 관측과도 분모를 섞지 않는다.

## 판독 잠금과 선호

네 파일의 SHA 잠금을 `2026-10-07T13:55:58.382064+00:00`에 확인한 뒤 라벨 대응표를 공개했다. 원문·이전 실패 방향·지침 설계를 아는 AI 판독이므로 arm label만 가린 평가다. 새 2개 본문은 소스 동결 후 공개했고 UI는 지정 블라인드 파일에서 처음 읽었다.

표의 셀은 후보 선호 / 기준 선호 / 동률이다.

| 평가자 | 전체 6쌍 | 기존 정제 4쌍 | 신규 정제 2쌍 |
| --- | --- | --- | --- |
| root | 1 / 3 / 2 | 1 / 3 / 0 | 0 / 0 / 2 |
| core | 1 / 2 / 3 | 1 / 2 / 1 | 0 / 0 / 2 |
| UI | 1 / 3 / 2 | 1 / 3 / 0 | 0 / 0 / 2 |
| verification | 1 / 4 / 1 | 1 / 3 / 0 | 0 / 1 / 1 |

네 AI는 **같은 6쌍을 판독**했다. 24개 독립 출력쌍이나 원문 표본이 아니다. 약한 문체 선호와 의미 보존에 따른 선택이 함께 들어 있으므로 승패를 품질 합격률·통계적 효과로 사용하지 않는다.

### 잠금 후 상태 도구의 요약 노출

UI는 자기 판독 파일의 SHA를 잠근 뒤, 네 판독 전체 잠금 전에 `collaboration.list_agents`로 상태를 조회했다. 도구 결과에 core의 완료 요약인 A2/B1/동률3과 수행자 문제 한 개가 자동 포함되어 보였다. 이때 다른 리뷰 파일·대응표·raw 결과를 열지는 않았고, 이미 잠긴 UI 판정은 변경하지 않았다. 해당 노출을 root에 즉시 보고했다. 판독 전 독립성과 판독 완료 뒤 요약 노출을 구별하며, 모든 평가 정보가 끝까지 가려져 있었다고 주장하지 않는다.

## 의미 보존과 자연스러움

`TIPK02_en_tentative` 후보는 `I can finish`와 `I’ll finish`로 완료 수행자를 화자로 특정했다. 원문은 화자의 판단과 완료 약속 부정을 담지만 해당 행동의 수행자를 명시하지 않으며, 고정 기준도 수행자 추가를 금지한다. core·UI·verification은 이 출력 하나를 명확한 수행자 추가로 표시했다. root는 한국어 문맥의 화자 읽기가 가능하다고 보고 `meaning_pass=true`와 해석 위험을 함께 기록했다. 네 판독자 모두 수행자를 열어 둔 기준 출력을 선호했다. 이는 같은 출력에 대한 분류 이견이며 의미 오류가 세 개 발생했다는 집계가 아니다.

생략된 주어를 어느 경우에 문맥상 화자로 풀어 쓸 수 있는지는 별도의 제품 원칙 검토 대상이다. 후속 정책 선택을 이유로 이번 고정 기준과 잠긴 판정을 소급 변경하지 않는다. **이번 후보가 기존 수행자 문제를 해결했다고 말할 수 없어 HOLD를 유지한다.**

다른 관찰은 다음과 같이 분리한다.

- `TIPK03_ja_intent`: 후보의 전달 의도 구문과 가벼운 두서없음의 연결은 네 판독자 모두 선호했다. 기준의 긴 명사절도 의도는 읽히므로 명확한 오역이나 명사절 전면 금지로 분류하지 않는다.
- `TIPK04_ja_adoption`: 양쪽 모두 취지 이해, 즉시 도입 우려, 전면 배제 부정과 소규모 시험 후 확대 여부 결정을 유지했다. UI는 기준의 도입 대상 참조를 약하게 선호했고 core는 동률이었다. 제안 단계의 배제와 진행 중 활동의 중단을 명확히 뒤집은 의미 실패로 세지 않는다.
- `TIPK01_en_intent`: 양쪽 모두 가벼운 두서없음·전달 의도·하지 않은 말 추가 금지를 유지한다. `speak a bit disjointedly`와 `ramble a little`의 회화적 정도에 대한 선호가 있을 뿐, 이를 원어민 여부나 심각한 오역 판정으로 확대하지 않는다.
- `TIPR4401_en_explicit_personal_plan`: 양쪽 모두 명시된 화자의 다음 주 월요일 직접 점검 계획, 장비 두 대, 조건부 통보 계획과 시간 미정을 보존했다. 수행자 보호 지침이 명시된 개인 계획까지 지우지는 않았다. 다만 부정문 끝의 `too` / `as well` 결합이 양쪽 모두 어색해 문체 주의가 남았다. 세 판독자는 동률, verification은 기준을 약하게 선호했다. 유창성 점수의 1·2 차이는 있지만 의미 반전으로 분류하지 않았다.
- `TIPR4402_ja_draft_added_performer`: 양쪽 출력이 완전히 같았다. 초안에 추가된 공동 수행자를 사실로 고정하지 않고 분류 수행자 미정, 지수의 시작 날짜만 확인하는 역할과 네 묶음의 당일 처리 약속 부정을 유지했다. `資料の4つの束`에는 제한적인 수량 표현 주의가 남지만 수량 변경은 아니다. 네 판독자 모두 동률이었다.

이 두 신규 정상 경계가 보존된 관찰을 기존 수행자 실패의 상쇄 점수로 쓰지 않는다. 모든 상황의 주체·말투·관용성이 검증된 결과도 아니다.
