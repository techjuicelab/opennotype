# 번역 관용 표현 개선 2차 실측 결과

2026-10-07, 기준 `e5bfe2bdf0196fbc5587ca98025c8a4ab56aa8bd`와 후보 `6d5791c5db0b8fdcbc075d54cd9dac69de7d9129`를 실제 24회 호출해 12쌍을 평가했다. 기존 일본어 전달 의도와 영어 잠정 표현에서 개선을 관측했지만, **일본어 도입 제안의 어색함이 남았고 신규 영어 최종안에 유창성 회귀가 있어 후보 채택을 보류한다.** 수행자 귀속 우려도 별도로 남긴다. 후속 3차 지침을 검토 중이며, 이번 결과로 main 반영·후보 설치 완료를 주장하지 않는다.

[1차 기록](translation-idiomatic-polish-round1.md)과 [2차 준비 기록](translation-idiomatic-polish-round2.md)은 당시 상태를 보존한다. 준비 기록의 실제 호출 0회·인증 대기는 실행 전 이력이고, 이 보고서는 이후 인증을 통과해 완료한 실측을 다룬다. 현재 설치본은 로컬 0.2.4(36), 공개판은 0.2.3(35), 이번 로컬 후보는 0.2.4(37)이다. 후보37은 빌드·서명·번들 검증을 마쳤지만 설치·실행하지 않았다.

## 실행과 평가 분모

OpenRouter `openai/gpt-6-luna`, `medium`으로 24회 모두 HTTP 200·응답 반환·보호 검사 통과를 확인했다. 자동 재시도 0회, Jev 호출 0회다. 제공자가 24개 usage 이벤트에 보고한 비용 합계는 **US$0.008725315**이며, 최종 청구액 보장이나 다른 조건의 비용 추정값이 아니다. HTTP 성공과 결정적 보호 검사 통과는 의미·자연스러움 합격을 뜻하지 않는다.

| 비교 단계 | 원문·초안 관계 | 쌍 | 호출 |
| --- | --- | ---: | ---: |
| 기존 정제 | 기존 4개에 같은 초안을 기준·후보로 정제 | 4 | 8 |
| 신규 생성 | 신규 4개를 기준·후보로 각각 1차 생성 | 4 | 8 |
| 신규 최종 | 각 조건의 실제 1차 출력으로 그 조건의 정제를 수행 | 4 | 8 |
| 합계 | 기존 4개 + 신규 4개 원문 | 12 | 24 |

신규 생성과 신규 최종은 **같은 신규 4개 원문의 종속 관측**이다. 신규 8개 독립 사례가 아니다. 신규 최종 비교에는 서로 다른 1차 초안과 정제 지침의 효과가 함께 들어가므로 정제 지침만의 효과로 귀속하지 않는다. 기존 4쌍의 동일 초안 정제와 구분한다.

최초 요청 바인딩 16개, 실제 생성 후 파생 요청 바인딩 8개, 각 조건 자신의 생성 출력과 정제 초안 SHA 연결 8개를 확인했다. 원문·profile·목표 언어·사전은 유지했고, 평가 기준은 모델 입력에서 제외했다. 반환 출력 SHA 24개도 대조했다.

## 블라인드 판독과 선호

root·core·UI·verification 네 AI 판독자가 A/B 라벨로 독립 평가 파일을 작성하고 SHA를 잠근 뒤 대응표를 공개했다. 잠금 시각은 `2026-10-07T13:26:09.812676+00:00`이다. 원문·이전 실패 방향·지침 설계는 알려져 있었으므로 모든 조건을 가린 시험이 아니라 **arm label만 가린 평가**다.

표의 각 셀은 후보 선호 / 기준 선호 / 동률이다. 약한 문체 선호도 포함하므로 이를 품질 합격률로 환산하지 않는다.

| 평가자 | 전체 12쌍 | 기존 정제 4쌍 | 신규 생성 4쌍 | 신규 최종 4쌍 |
| --- | --- | --- | --- | --- |
| root | 4 / 1 / 7 | 3 / 0 / 1 | 1 / 0 / 3 | 0 / 1 / 3 |
| core | 5 / 1 / 6 | 3 / 0 / 1 | 2 / 0 / 2 | 0 / 1 / 3 |
| UI | 5 / 1 / 6 | 3 / 0 / 1 | 2 / 0 / 2 | 0 / 1 / 3 |
| verification | 3 / 2 / 7 | 2 / 1 / 1 | 1 / 0 / 3 | 0 / 1 / 3 |

네 평가자는 **같은 12쌍을 반복 판독**했다. 48개 독립 모델 출력쌍이나 48개 독립 원문 표본이 아니다. 이 표본에서 네 판독 파일 모두 명확한 의미 실패로 표시한 arm은 없었지만, 아래의 수행자 해석 우려와 유창성 회귀가 있다. `meaning_pass=true`를 아무 주의점 없는 보존이나 원어민 수준 합격으로 확대하지 않는다.

## 개선과 남은 문제

### 기존 동일 초안 정제

- `TIPK03_ja_intent`: 네 판독자 모두 후보를 선호했다. 기준의 `私がどういう意味で話したのか`보다 후보의 `私が何を言いたかったのか`가 전달하려던 내용을 자연스러운 동사절로 나타냈다. 다만 후보에도 `言葉をただ滑らかに整える`처럼 더 다듬을 여지가 있다. 이 관측 표현을 이후 프롬프트의 정답 문장으로 주입하지 않는다.
- `TIPK02_en_tentative`: 네 판독자 모두 후보를 선호했다. 조건·완료 가능성·약속 부정·일정 재조정 전망을 보존하면서 문장 흐름이 평이해졌다. 헤지 수를 줄였다는 이유만으로 선호한 것은 아니다.
- `TIPK01_en_intent`: root·core·UI는 후보의 `ramble a bit`와 전달 의도 표현을 약하게 선호했고, verification은 기준의 중앙 문장 구조를 약하게 선호했다. 기존 영어를 심각한 오역으로 판정하거나 의견 차이를 숨기지 않는다.
- `TIPK04_ja_adoption`: 네 판독자 모두 동률이었다. 양쪽에 `まったくやめよう`와 `小さな範囲`가 남아 도입 제안의 전면 배제와 소규모 시험을 자연스럽게 표현하려던 목표가 충분히 해결되지 않았다. `やめる`는 아직 시작하지 않은 계획을 포기한다는 뜻으로도 읽혀 진행 중 활동 중단이라는 확정적 오역으로 세지 않았다.

### 신규 생성과 최종 정제

`TIPR3201_en_message_intent`의 신규 최종안은 네 판독자 모두 기준을 선호했다. 후보의 `the shipment is promised to be delivered by then`은 문맥상 배송 약속 부정을 읽을 수 있지만 수동·명사적 약속 구조가 겹쳐 뻣뻣하다. 신규 생성 단계에서 후보를 선호한 판독이 있어도 그 선호를 최종안 개선으로 이어졌다고 세지 않는다. 최종 비교는 서로 다른 초안을 포함한 두 단계 결과이므로 이 회귀를 정제 지침 하나의 인과 효과로 확정하지도 않는다.

`TIPR3202_en_independent_judgments`의 신규 최종안에는 기준·후보 모두 `I could try`가 나타났다. 원문의 화자 판단과 보장·약속 부정은 화자가 시도한다는 읽기를 뒷받침할 수도 있으나, 시도 절의 수행자는 직접 명시되지 않았다. **판단의 소유자와 행동의 수행자를 합칠 우려**를 남기며, 명확한 사실 변경과는 구별했다. 기준·후보 양쪽에 생긴 문제이므로 후보만의 회귀나 해결로 집계하지 않는다.

신규 일본어의 실제 버튼 이름 뜻풀이 요청과 별개 점검·승인 후 한 번 제한·의도적인 중요성 재강조는 주요 조건을 유지했다. 정상적인 명사구나 의도적인 반복을 일괄 삭제해야 한다는 결론은 내리지 않는다.

## 판정과 한계

후보는 일부 알려진 목표를 개선했지만 **채택 보류**다. 일본어 미도입 제안 표현, 영어 최종안의 수동 문장틀, 수행자 귀속을 일반 지침 수준에서 더 검토해야 한다. 정답 문장이나 금칙어를 넣는 대신 실제 행동·단계·부정·역할과 자연스러운 목표 언어 서술 관계를 함께 보존하는 후속안을 검토한다. 3차 결과는 아직 이 보고서의 품질 근거에 포함하지 않는다.

신규 입력 4개는 이전 실패 방향을 아는 AI가 작성해 소스 동결 전 봉인했으며 참고 정답 문장은 없다. source freeze 전 root·core·UI에 신규 본문을 공유하지 않았다는 작성 기록을 보존한다. 1차의 root 사전 열람 이탈은 별도 [1차 보고서](translation-idiomatic-polish-round1.md)에 그대로 남는다. 사람 원어민 검수나 대표 표본이 아니고, 조건당 단일 확률적 응답이며 OpenRouter 상위 공급 경로도 고정하지 않았다. 실제 마이크·대상 앱 입력·Jev 검증은 하지 않았다. Minji 성별은 평가 범위 밖이다.

정식 CI는 후보6d에서 두 실행 모두 XCTest 899개(897 통과·기존 LocalAudio 2개 건너뜀·실패 0개), Python 198개 통과·건너뜀 0개였다. 로컬 후보37의 서명·소스28·번들·업데이트 정책 검증도 준비 기록과 일치한다. 이 기술 검증을 문장 품질이나 설치·실행 성공의 증거로 대체하지 않는다.
