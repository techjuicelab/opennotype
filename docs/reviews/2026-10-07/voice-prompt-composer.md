# 음성 작업 프롬프트 개발 기록

2026-10-07, `main`의 `f8a2adf`에서 새 브랜치 `codex/voice-prompt-composer`를 만들었다. 기존 받아쓰기·번역과 별도로, 불규칙한 발화를 코드나 직접 설계가 없는 간결한 요구사항 프롬프트로 변환한다. 공개 릴리스·설치 앱 교체는 이 작업에 포함하지 않았다.

## 분담과 구현

| 담당 | 범위 |
| --- | --- |
| 에이전트 1 | 프롬프트 생성·최종 다듬기 계약, 설정 분리, 코드·설계 제외 지침과 테스트 |
| 에이전트 2 | 공식 API 확인, Jev 4축 검토·엄격한 파서·목적별 기록 검토 |
| 에이전트 3 | 홈·메뉴·결과 복사 화면, 네 번째 단축키와 기존 설정 이주 |
| 에이전트 4 | 독립 통합 감사, runner 호출 순서·실패·취소·크기 한도 회귀 테스트 |
| 통합 담당 | 음성·복구·기록 다시 처리 연결, 수명/취소, 사용량, 문서와 빌드 검증 |

실행 슬롯 제한에 따라 1~3 담당을 먼저 시작하고 UI 완료 뒤 네 번째 담당을 투입했다. 새 채팅 네 개를 만든 것이 아니라 현재 작업의 하위 에이전트 네 개를 사용했다.

초안과 최종 결과는 각각 독립 Jev 검토를 거친다. 최종 통과는 네 축 모두 pass probability ≥0.8 및 confidence ≥0.6일 때다. 이 임계값은 미보정 제품 정책이며 정확도 백분율이 아니다. 실패·불확실·잘못된 응답은 완성 결과로 제공하지 않는다. 첫 검토의 고정 문제 유형만 한 번의 최종 다듬기에 전달한다. 상대 AI가 쓸 코드나 설계·도구 흐름을 생성하지 않는다.

최종 결과는 복사 전용이며 외부 앱 입력·AI 제출을 실행하지 않는다. `InputMode.prompt`는 기존 언어/표현·번역·개인화 학습 정책을 사용하지 않는다. 기본 단축키는 ⌃⌥⇧Space이며 기존 세 조합을 보존한다. 선택한 Jev 연결이 필수이며 일반 자동 검토 설정과 독립적이다.

## 검증 현황

로컬의 전체 XCTest 시도는 Command Line Tools 환경의 XCTest 부재로 실행하지 못했다. 첫 일반 앱 빌드는 macOS 27 SDK의 SwiftUIMacros 플러그인 부재로 실패했으며, 저장소의 SDK preflight가 선택한 macOS 26.5 SDK로 최종 개발 앱 빌드와 strict ad-hoc 서명 검증이 통과했다. 최초 CI의 전체 938개 중 두 테스트에서 세 assertion이 실패했다. 기존 세 단축키 보존에 네 번째 조합을 추가하는 이주 기대값과, 접근 때마다 사전 UUID가 달라지는 테스트 fixture를 수정했다. 이전 리비전 `ddbfab9`의 CI에서 XCTest 951개(2개 건너뜀·실패 0개), Python 198개 전체와 개발 앱 빌드가 통과했다. 실제 API 시험 이후 보강한 신규 테스트는 생성 계약 26개, Jev 검토 12개, runner 13개, 플랫폼 흐름 6개로 합계 57개다. 최신 리비전의 전체 XCTest·Python·개발 앱 빌드 결과는 [PR 검사 기록](https://github.com/techjuicelab/opennotype/pull/28/checks)에서 확인할 수 있다.

최초 Python 검증에서 새 prompt 의존성이 수동 Swift 소스 레지스트리에 빠져 세 평가 도구 테스트가 실패했다. `export-cleanup-prompts.py`와 `compare-decisions.py`의 소스 목록에 새 계약 파일을 추가했다. 수정 후 전체 Python 198개가 완료됐고 195개 통과, 환경 의존 3개는 건너뛰었다.

별도 미리보기 앱에서 홈의 프롬프트 카드, 기본 단축키, Jev 연결 미설정 안내, 코드·설계 제외와 생성/검토 횟수 안내를 화면으로 확인했다. 최종 결과 화면과 실제 마이크는 이 확인에 포함하지 않았다. 설치 앱은 교체하지 않았다.

독립 감사에서 기록 재처리를 시작하고 첫 비동기 작업이 재개되기 전에 제공자·모델을 바꾸면 이전 설정의 유료 처리가 시작될 수 있는 틈을 확인했다. 실제 프롬프트 작업 UUID를 시작 시점부터 추적해 취소하며, 마지막 녹음 모드가 프롬프트여도 일반 기록 재처리의 설정 캡처 동작은 유지한다. 두 동작에 회귀 테스트를 추가했다. 로컬 코드 문법 검사는 17개 거부/허용 사례를 실제 production 함수로 별도 확인했다.

## 실제 API 시험

개인 음성·기록을 사용하지 않고 합성 한국어 발화 세 개를 production Swift runner로 처리했다. 생성은 OpenRouter의 `openai/gpt-oss-120b`, 검토는 실제 Jev API를 사용했다. 각 사례는 생성 두 번·검토 두 번으로 제한하고 자동 재시도는 하지 않았다.

첫 시험에서 두 사례가 앱의 최종 검토를 통과했으나 모두 영어로 바뀌었으며, 하나는 기능 구현 요청을 다른 프롬프트 작성 요청으로 바꿨다. 나머지 사례는 초안에 잠정 API·DB·코드 조건 설계가 남고 최종 문장이 잘렸으며 앱이 보류했다. 이를 품질 통과로 집계하지 않는다. 이 결과를 바탕으로 원문 언어 hint, 실제 작업을 직접 요청하는 규칙, 잠정 설계도 배제하는 기준, 동작·음성 재응답 조건 보존을 보강했다. 코드·SQL·HTTP 설계 표기의 좁은 로컬 문법 차단도 생성 응답과 runner 양쪽에 연결했다.

1Password 인증 완료 후 두 차례 실제 API 재시험을 진행했다.

| 시험 | 앱 제공/보류 | 독립 검토 결과 |
| --- | --- | --- |
| 2차: 한국어 3개 | 1개 제공·2개 보류 | 한국어와 코드·설계 제외는 개선됐다. 기능 구현이 요청문 작성으로 바뀐 사례는 보류했고, 적절한 로그인 요청도 최종 pass 확률 0.79로 기준 0.8에 못 미쳐 보류했다. 제공한 게임 사례에는 선택적 오프라인 희망이 빠지고 추후 결정 약속이 생겼다. |
| 3차: 한국어 3개·영어 1개 | 3개 제공·1개 보류 | 기능 구현 의도는 복구됐으나 Codex 이름 누락 사례는 보류했다. 로그인 사례는 코드·설계를 제거한 요구만 남겼고 영어도 유지됐다. 게임 사례는 초안의 음성 재응답이 다듬기에서 일반 답하기로 약해졌는데도 최종 검토를 통과했다. |
| 4차: 같은 한국어 3개·영어 1개 | 1개 제공·3개 보류 | 모든 후보에서 언어와 코드·직접 설계 제외를 유지했다. 게임의 음성 재응답 누락과 화면 제약 강화는 보류됐다. 기능 구현·Codex·브랜치·에이전트 수는 회복됐으나 프롬프트 제약의 적용 대상이 모호한 사례는 보류됐다. 내용상 적합해 보이는 로그인 요청도 intent 점수 때문에 보류됐다. 영어 사례는 통과한 초안 자체가 최종 검토·제공됐다. |

따라서 제공 개수를 품질 통과 개수로 계산하지 않는다. 이를 바탕으로 기능 구현과 일회성 프롬프트 작성 구분, 명시된 수신자 직접 호명, 희망과 미정 상태 동시 보존, 설계 예시를 대체 요구 없이 삭제하는 허용 범위를 보강했다. 첫 검토를 통과한 초안은 다듬기의 불필요한 표현 변경으로 교체하지 않고, 유지한 초안 자체를 마지막 Jev 검토에 보낸다. 첫 검토가 불충분한 경우에만 다듬은 후보를 선택하며 마지막 검토 기준은 유지한다. 최종 보류 후 이전 초안으로 되돌아가 제공하지 않는다.

4차 결과 이후 GPT-OSS 120b/20b의 프롬프트 생성에만 추론 수준을 `medium`으로 올리고, Jev의 메타 요청 구분 문장이 다른 실패 조건까지 제한하는 듯 읽히지 않도록 범위를 명시했다. 요청 한도·시간 제한·최종 판정 임계값은 유지했다. OpenRouter·Groq의 두 OSS 모델과 초안/다듬기 단계, 오류 무재시도, 다른 모델 정책 보존을 확인하는 제공자 계약 테스트 세 개를 추가했다. 최신 코드의 로컬 개발 앱 빌드와 strict ad-hoc 서명 검증도 통과했다. 공식 [OpenRouter 추론 문서](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)와 [Groq 추론 문서](https://console.groq.com/docs/reasoning)를 확인했으며, 추론 강화의 품질 효과는 실제 시험 결과로 판단한다.

생성 계약 문자열 검사와 모의 공급자 테스트는 실제 모델의 의미 보존이나 코드·설계 배제 성공률을 입증하지 않는다. 어떤 모델·언어·발화에서나 동일한 품질을 보장하지 않으며, 대상 AI 앱에 직접 붙여넣어 실행하는 시험은 하지 않았다. 후속 실제 시험과 CI 결과는 [초안 PR #28](https://github.com/techjuicelab/opennotype/pull/28)에 함께 기록한다.
