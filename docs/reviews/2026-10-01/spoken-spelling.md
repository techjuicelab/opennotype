# 발음 뒤에 덧붙인 영문 철자 정리 검증 — 2026-10-01

사용자가 이름을 발음한 뒤 철자를 읽어 명확히 했는데, 문장 정리 결과에 이름과 분리된 철자가 모두 남는 문제를 재현했다. 예를 들어 `제브 제이 이 브이 활용하기 좋은 아이디어들 적용하고 싶어요.`의 이름 부분은 `JEV` 하나로 정리되어야 한다. 일반 명사·친족인 `제부`, 인용한 발음, 의도적으로 띄어 쓴 영문 글자와 코드 식별자는 보존해야 한다.

주 평가 16개 사례는 **문장 정리 모델의 텍스트 처리**를 대상으로 한다. 입력은 음성 인식이 끝났다고 가정한 문자열이며 마이크 녹음, Groq 음성 인식, Jev 판정, 다른 앱에 대한 자동 입력을 포함하지 않는다. 수정은 문장 정리 지시문에 적용했고 Jev API를 더 호출하도록 바꾸지 않았다. 별도의 Jev 판정 진단 8건은 아래에서 구분한다.

## 고정 평가 자료와 production 경로

[16개 사례](../../fixtures/spoken-spelling.json)를 수정 전 실행 전에 만들었다. fixture SHA-256은 `6c58bce8de30e39d650c72b7dbc992865c11842b820878e3924b356684e23d1b`이며 수정 전·후에 같은 자료를 사용한다.

- S01–S06: 사용자 보고 문장, 동음 인식 오류, 명시적 철자·자기 수정, 분리된 Latin 글자, 한국어 조사를 포함한 이름.
- S07: 미등록 이름 `RUMEX`의 철자 결합 회귀 사례. 최종 프롬프트에도 같은 이름의 예시가 있으므로 독립적인 미학습 이름 평가로 해석하지 않는다.
- S08: 사전의 `제브 → JAB`과 이번 발화의 `J E V`가 충돌할 때 명시적 철자를 우선하는지 확인한다.
- S09–S16: 실제 제부, 한글 이름 보존 지시, 분리 글자 보존 지시, 인용된 발음, 코드 식별자, 독립된 퀴즈 답, 이름과 인용문의 공존, 이름과 글자가 무관하다는 부정 대조 사례.

`scripts/compare-text-models.py`와 `Tools/TextModelBench/main.swift`를 사용한다. Swift 하네스가 실제 `ProviderClient.process`를 호출해 `ProcessingPrompt`에서 만든 요청을 캡처한다. API 응답도 같은 `ProviderClient` 파서로 재생한다. production 요청과 다른 필드는 비용 상한을 위한 `max_tokens`뿐이다(`16,384 → 1,024`). 별도의 복제 프롬프트로 평가하지 않는다.

대상 모델은 `qwen/qwen3-30b-a3b-instruct-2507` 하나이며, 요청은 병렬 실행하지 않는다. 16회 평가의 보수적 예약 금액은 $0.0257697, 실행 상한은 $0.05였다. 이 값은 공개 카탈로그 단가로 계산한 예약이며 계정 청구 한도 설정은 아니다.

## 회귀 판정 기준과 한계

필수 확인은 이름을 하나의 연속된 영문 표기로 만드는 것, 발음명·철자 읽기 중복을 없애는 것, 글자를 빠뜨리지 않는 것, 사용자의 의미와 말투를 유지하는 것이다. `expected_text`는 가능한 예시이며 문장 전체의 정확한 문자열 일치를 강제하지 않는다. 명시적인 철자 설명이 문장 내용인 사례에서는 그 설명을 지워도 된다고 가정하지 않고 결과를 따로 읽는다.

최초 fixture의 정규식은 `JEV`, `Jev`, `jev`를 같은 철자로 취급한다. 수정 전 자료를 보존하기 위해 fixture는 바꾸지 않고 [`scripts/check-spoken-spelling.py`](../../../scripts/check-spoken-spelling.py)에 추가 판정을 만들었다. S01–S06·S08의 이름은 정확한 대문자 `JEV`여야 한다. S07은 `RUMEX` 옆에 `루멕스`가 다시 남으면 실패, S08은 `제브`·`제부`가 다시 남으면 실패, S13은 정확한 대소문자의 `j_e_v`만 허용한다. 검사기는 동일한 16개 fixture·모델·live 보고서·누락/중복 없는 결과인지 확인하고, 저장된 통과 표시를 신뢰하지 않고 원래 정규식도 다시 계산한다.

부정 대조군은 모델명을 추측해 무조건 영어로 바꾸는 부작용을 막는다. 추가로 다음 사항을 사람이 확인한다.

- S01의 “적용하고 싶어요”가 완료 주장이나 명령으로 바뀌지 않는지.
- S03·S07에서 모델·도구 소개나 철자 설명의 뜻이 불필요하게 사라지지 않는지.
- S08에서 사전보다 우선한 명시적 철자 `JEV`가 정확한지.
- S09의 친족 `제부`, 방문 시각과 전언 뉘앙스가 유지되는지. 수정 전에는 “온대요”가 “올 거예요”로 바뀌었다. 이 결과는 철자 대조 검사를 통과하지만 전언 뉘앙스까지 보존했다는 증거가 아니다.
- S10–S16에서 명시적 표기 보존·공백·인용·코드 식별자·부정이 그대로인지.

텍스트 모델의 출력은 매번 달라질 수 있다. 소규모 조건 검사의 통과를 전체 음성 인식 정확도나 모든 이름의 변환 정확도로 일반화하지 않는다.

## 재현 명령

먼저 키 없이 계획을 생성한다. 이 명령은 임시 Swift 하네스를 컴파일하며 네트워크 호출을 하지 않는다.

```sh
python3 scripts/compare-text-models.py \
  --models qwen/qwen3-30b-a3b-instruct-2507 \
  --fixtures docs/fixtures/spoken-spelling.json \
  --workers 1 --max-usd 0.05 \
  --output build/spoken-spelling-verification/plan.json
```

예약 금액을 확인한 뒤 `OPENROUTER_API_KEY`를 안전하게 주입한 환경에서 같은 명령에 `--live`를 추가한다. 키 값을 명령 인자나 문서에 넣지 않는다. 모델 결과를 본 뒤 fixture의 정답 조건을 바꾸지 않는다.

평가 CLI는 보고서 생성에 성공하면 품질 조건 실패와 무관하게 exit 0을 반환한다. 다음 검사는 원래 조건과 추가 보존 조건을 모두 확인하며 하나라도 실패하면 exit 1을 반환한다. JSON과 gzip JSON을 모두 읽으며 API를 호출하지 않는다.

```sh
python3 scripts/check-spoken-spelling.py \
  docs/reviews/2026-10-01/spoken-spelling-evidence/after-v2.json.gz
```

검사기 자체에는 S07 발음 중복, S08 발음 중복, S13 대소문자 변경, 소문자 이름을 주입한 출력과 누락·중복·dry-run·통과 표시 변조 보고서를 넣어 실패하는지 확인했다. 자동 검사에 통과해도 실제 문장의 의미 보존을 별도로 검토해야 한다.

## 합성 음성의 실제 Groq → OpenRouter 처리

macOS `say`의 Yuna 음성으로 `제브 제이 이 브이 활용하기 좋은 아이디어들 적용하고 싶어요`를 읽은 4.093초·16 kHz·단일 채널 파일을 실제 production `ProviderClient`로 처리했다. Groq `whisper-large-v3-turbo`가 `제보 제이의V 활용하기 좋은 아이디어들 적용하고 싶어요.`로 인식했고, OpenRouter `qwen/qwen3-30b-a3b-instruct-2507`의 최종 결과는 `JEV 활용하기 좋은 아이디어들을 적용하고 싶어요.`였다. 개인 사전은 비워 두었다.

음성 인식 1.648초, 문장 처리 1.210초, 전체 2.860초였으며 단계별 요청은 각각 1회였다. 보고된 문장 처리 비용은 $0.0001431108, 음성 인식 비용은 $0.0001111111 추정이다. 이는 **합성 음성 한 건의 실제 API 경로**를 확인한 것이며 사람의 마이크·단축키·권한·다른 앱의 자동 입력을 시험한 결과는 아니다.

증거: [합성 음성 처리 결과](spoken-spelling-evidence/synthetic-audio-result.json.gz), [소스·음성 해시](spoken-spelling-evidence/synthetic-audio-manifest.json.gz). 실제 음성 파일은 증거 묶음에 넣지 않았다.

로컬 Python 검사는 171건 중 168건 통과·3건 환경에 따른 제외였고, `0.1.17(19)` release 빌드와 코드 서명 검증은 성공했다. 로컬 CLT에는 XCTest 모듈이 없어 정식 XCTest는 GitHub의 Xcode CI에서 확인한다.

`/Applications/OpenNoType.app`에 0.1.17(19)를 설치하고 기존 0.1.16을 백업했다. 설치 실행 파일 SHA-256은 `03797143360322c687678072b0839ee788bc2598bad88613229c399e20dc51ef`이다. 앱에서 0.1.17 버전, 기존 Groq/OpenRouter 모델, 한국어 화면과 저장된 API 키 준비 상태를 확인했다. 앱은 마이크와 손쉬운 사용 권한을 ‘허용 필요’로 표시하므로 사용자에게 재허용과 실제 발화 시험을 요청했다. 사람의 마이크·단축키·외부 앱 입력 결과는 아직 확인하지 않았으며 위 텍스트 통과 수에 합산하지 않는다.
