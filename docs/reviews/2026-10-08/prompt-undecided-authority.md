# 미정 기능을 구현 지시로 바꾼 실제 생성 결과

`bfcc815` 테스트 앱의 저장된 22:10 원문을 GUI에서 한 번 다시 처리했다. 음성을 재전송하지 않았으며 문장 생성 1회와 Jev 검토 2회를 실행했다. 생성 모델은 OpenRouter `openai/gpt-oss-120b`, 검토 모델은 OpenRouter `typesafe/jev-1.13-20260917`이었다.

원문은 “알림도 있으면 좋겠는데 널지는 아직 미정이에요”였지만 실제 제공문은 “알림 기능은 추가하되 도입 여부는 아직 미정임을 명시해 주세요”였다. 도입을 결정하지 않은 희망이 구현 지시로 바뀌었다. 검토 화면은 의도·추가·누락·기존 지침을 모두 통과로 표시했다. 이는 실제 생성 오류와 검토의 놓침을 함께 관측한 사례이며, 검토 신호를 의미 보존의 증명으로 볼 수 없음을 보여 준다.

기존 지침에도 미정 상태 보존 기준은 있었다. 이번 보강은 앱 전체의 확정된 작업과 미정인 하위 기능의 도입 권한을 명확히 나누고, 미정이라는 단서가 같은 기능의 구현 명령을 취소하지 못한다는 기준을 생성과 의도 검토 양쪽에 추가한다. 명시적인 결정 위임과 도입이 확정된 기능의 사용자 on/off 요구는 유효하게 유지한다. 검토 문구를 압축해 축별 2,400바이트 상한을 유지한다.

내용 검토의 참고 표시 정책, 기존 지침 위반 시 보류, 모델·공급자·임계값·호출 수·시간 제한은 변경하지 않는다. 사용자가 미정 기능의 결정을 먼저 내려야 하는 흐름도 추가하지 않는다.

회귀 검증은 생성·일반 다듬기·문장별 복구가 같은 기준을 사용하고 OpenRouter·TypeSafe 요청에 전달되는지, 원문과 후보가 지시문에 섞이지 않는지, 네 검토 축과 기존 요청 예산이 유지되는지를 확인한다. 이 정적 계약 검증은 실제 모델의 의미 품질을 증명하지 않는다. 실제 비교에는 기존 원문 1건, 새 미정 기능 사례 1건, 도입 확정·사용자 on/off·기본값 결정 위임의 반례 1건을 미리 고정하고 각 1회만 처리한다. 평가는 모델에 보내지 않은 별도 기준으로 수행한다.

원문·실제 결과·검토 표시·사용량과 테스트 증거는 `build/prompt-undecided-authority-2026-10-08/`에 보존한다. 앞선 실제 오류는 `build/prompt-fresh-recording-2026-10-08/runtime-semantic-before.json`에 보존했다.

## 실제 설치본 비교

보강 코드 `cb9a81a`를 테스트 앱으로 빌드·엄격 서명 확인·설치한 뒤, 미리 고정한 세 원문을 GUI에서 각각 한 번 처리했다. 모델은 변경하지 않았다. 결과와 복사 버튼은 모두 홈 상단에 표시됐다. 첫 원문은 저장 기록의 텍스트 다시 처리, 나머지는 화면의 원문 편집을 사용했고 기존 기록을 덮어쓰지 않았다.

| --- | --- | --- |
| 같은 독서 기록 원문 | “알림 기능을 원하지만, 구현 여부는 아직 결정되지 않았습니다.” 구현 명령이나 필수 결정 질문으로 바꾸지 않음 | 생성 2회·검토 2회 |

비공개 기준을 모델에 보내지 않은 독립 대조에서도 세 최종 결과의 희망·도입 상태·구현 권한·조건 범위를 보존했다고 판단했다. 기록 보존, 날짜 추측 금지, 음성 입력과 브랜치 조건도 유지됐다. 단 첫 사례의 마지막 “문구는 짧고 담백”이 “결과는 짧고 담백”으로 넓어져 대상 범위가 덜 명확한 품질 주석은 남는다. 이 세 번의 관측을 일반적인 성공률이나 의미 품질 보장으로 확대하지 않는다. Jev 화면의 네 축 통과와 독립 의미 대조는 별개 증거다.

실제 사용량 차이는 생성 4회·검토 6회·음성 인식 0회, 자동 재시도 0회였다. UI의 반올림된 비용 추정 차이는 약 USD 0.0071이며 최종 청구액의 증명이 아니다. 앞선 `bfcc815`의 실패 관측은 별도 보존했고, 새 메모·확정 도입 사례의 변경 전 비교는 수행하지 않았다.

로컬에서 동일한 최종 테스트를 직접 컴파일한 결과, 수정 전 코드 111개 메서드·2,829 assertion 중 새 계약 관련 45개가 실패했고 보강 코드에서는 전부 통과했다. 이는 실제 XCTest 러너나 모델 의미 평가가 아닌 production 소스의 계약 검증이다. 초기 보강에서 발견한 검토 지시문 길이 초과도 상한을 늘리지 않고 압축해 해결했다.

설치 직후와 세 비교 후 모두 기존 기록 2건을 확인했고 API 연결·실제 요청도 성공했다. 운영 앱 executable hash는 바뀌지 않았다. 기존 설치본과 암호화 저장소 사본은 보존했고 키는 내보내지 않았다. 로컬 빌드 교체 직후에는 macOS 마이크·손쉬운 사용이 허용 필요로 표시됐다. 마이크 인증 요청과 시스템 권한 화면을 연 뒤 앱을 다시 활성화하자 두 권한 모두 허용됨으로 갱신됐고, 홈의 녹음·입력 준비 상태와 시작 버튼도 확인했다. 세 비교는 텍스트 처리이므로 새 설치본의 물리 마이크·다른 앱 입력 확인을 대신하지 않는다.
