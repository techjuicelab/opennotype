# 최종 프롬프트 검토 보류 진단

사용자가 생성 중단 보고를 최종 검토 항목에 따른 프롬프트 보류로 구체화했다. 실패 원문은 남아 있지 않아 개별 사용자 작업의 원인을 확정하지 않는다. 조사 중 실제 API로 관측한 합성 사례와 production 소스의 검토 계약을 비교했다.

## 적합 후보의 보류

원문은 `Codex, 메모 앱에서 글자 크기를 키울 수 있게 해 주세요. 기존 메모 내용은 바꾸지 말고 새 브랜치에서 작업해 주세요.`였다. 후보는 `Codex, 메모 앱에서 글자 크기를 키울 수 있는 기능을 구현해 주세요. 기존 메모 내용은 변경하지 말고, 새 브랜치에서 작업해 주세요.`였다. 대상·동작·기존 내용 보존·작업 브랜치를 유지한 등가 표현이다.

수정 전 실제 첫 검토와 최종 검토의 `unsupportedAdditions`는 모두 `pass`를 골랐지만 신호 0.72/0.71, 확신 0.58/0.56으로 보류됐다. 나머지 세 항목은 높은 신호·확신으로 통과했다. 같은 원문에서 별도로 생성한 등가 후보도 이 항목의 신호 0.67/0.65, 확신 0.51/0.48로 보류됐다. 원문·후보의 전송 누락, 질문 ID 매핑이나 확률 parser 오류는 발견하지 못했다.

추가 내용 질문의 `or a solution?`은 구체적인 구현 설계뿐 아니라 사용자 요구 자체를 기능 구현 요청으로 표현한 것까지 넓게 읽힐 수 있었다. 생성 정책은 이런 요청 표현을 허용하지만 해당 검토 항목에는 이 구분이 명확하지 않았다. 이를 `or prohibited implementation content?`로 한정하고, 등가 동작 요청과 원문에 명시한 브랜치·에이전트 수·기한·결과물은 정당한 작업 제약임을 명시했다. 원문에 없는 제약의 발명, 미정 요구 확정, 코드·구체 설계 포함은 계속 금지한다.

네 검토 항목, `pass` 신호 0.8·확신 0.6 기준, 모두 통과해야 제공하는 판정, 두 번의 검토, strict 응답 schema/parser를 바꾸지 않았다. 최종 보류를 초안 제공으로 우회하거나 통과할 때까지 반복하는 동작도 추가하지 않았다.

## 타당한 보류와 표시 수정

이전 독서 앱 합성 시험의 후보에는 말하지 않은 감상 추가 금지·제품 문체·알림의 희망과 미정 상태가 빠지거나, 미정 기능이 확정된 기능으로 바뀐 사례가 있었다. 이런 보류는 타당한 생성 결함이며 검토 기준을 낮춰 해결할 문제가 아니다. 음성 인식 원문이 틀렸다면 실제 발화를 기준으로 원문을 먼저 고쳐야 한다.

보류 화면은 `0.799 → 80%`, `0.599 → 60%`로 정수 반올림해 통과 기준을 만족한 것처럼 보일 수 있었다. 실제 판정은 정확했다. 이제 Decimal 기반 소수 첫째 자리 내림으로 각각 `79.9%`, `59.9%`를 표시한다. 정확한 경계값 0.8/0.6은 `80%`/`60%`이며 극소값·NaN·Infinity도 검증했다.

## 검증과 한계

실제 production wire를 검사하는 저장 테스트 본문에서 정책 수정 전 12개 assertion 실패를 재현하고, 수정 후 16개 메서드·604개 assertion 실패 0을 확인했다. 네 항목 지침은 각각 2,317/2,286/2,285/1,109 UTF-8바이트로 2,400바이트 제한을 지킨다. 표시 테스트 본문 3개·25개 assertion과 전체 SwiftUI 결과 화면 typecheck도 통과했다. 로컬 CLT의 XCTest 제약으로 이 하네스를 정식 XCTest 실행으로 집계하지 않는다.

별도 담당이 적합 후보 8개·단일 결함 후보 5개를 만들었고, 기대판정을 보지 않은 독립 감사가 13개 모두 같은 적합/결함 판정을 기록했다. 기대판정·보존 요구 목록은 모델 입력과 별도 파일에 두었다. 이는 평가 세트의 의미 검증이며 실제 서비스의 통과율 측정은 아니다.

수정 전후 고정 후보 비교용으로 production DecisionClient를 직접 호출하는 별도 실행파일과 소스 hash를 동결했다. 1Password 런타임 인증이 시간 초과되어 아직 이 비교의 API 요청은 전송하지 못했다. 문구 수정의 실제 판정 개선은 이 비교가 끝나기 전까지 확정하지 않는다. 기존 실제 관측과 새 비교용 자료를 덮어쓰지 않고 각각 `build/prompt-debug-2026-10-08/`, `build/prompt-held-debug-2026-10-08/`, `build/prompt-debug-formatting-20261008/`에 보관한다.

사용자가 다시 말해 볼 나열형 독서 앱 예시와 보존할 조건은 [사용 안내](../../prompt-composition.md#나열한-발화-테스트)에 추가했다. 실제 음성 인식·녹음 사용성은 별도 장치 확인이 필요하다.
