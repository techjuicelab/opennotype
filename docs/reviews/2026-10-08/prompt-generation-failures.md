# Prompt Test 생성 중단 진단

`codex/voice-prompt-composer`의 `79dee34`를 기준으로, 프롬프트를 만들 때 오류가 뜨거나 생성이 멈추는 보고를 조사했다. 설치된 테스트 앱도 같은 소스 커밋이었다. 현재 작업의 실패 원문·오류 응답은 남아 있지 않아, 아래에서 재현한 코드 결함과 사용자가 겪은 특정 작업의 원인을 구분한다.

네 전문 에이전트가 생성 계약, Provider/Runner, 앱 흐름, 독립 감사를 맡았다. 동시 실행 슬롯은 통합 담당을 포함해 네 개이므로 독립 감사는 선행 담당이 완료된 뒤 투입했다.

## 재현과 수정

완전한 초안이 첫 Jev 검토를 통과해도 Runner는 두 번째 생성을 실행한 뒤 그 결과를 버렸다. 사용하지 않을 응답이 비었거나 JSON 오류·시간 초과를 던지면 최종 검토에 도달하지 못했다. production Runner에 같은 응답 순서를 주입해 실패를 재현했다. 이제 통과한 완전한 초안은 두 번째 생성 없이 원초안 자체를 독립 최종 검토에 보낸다. 첫 검토가 미달하거나 초안이 말줄임표로 끝나면 기존의 한 번 다듬기를 유지한다. 최종 검토의 보류·기준 미달·실패를 승인으로 바꾸지 않는다.

생성은 정상 완료 시 1~2회, Jev 검토는 두 번이다. 처음 또는 필요한 다듬기 요청이 실패하면 여전히 그 단계에서 중단한다. 자동 재시도·모델 교체·검토 임계값 완화는 추가하지 않았다. UI와 사용 안내의 호출 횟수도 실제 흐름에 맞췄다.

출력 구문 검사는 `CREATE TABLE` 또는 `ALTER TABLE`이라는 단어만으로 UI 라벨·파일 참조까지 거부했다. 정상 요청의 draft/final 모두 거부되는 회귀를 먼저 재현하고, 실제 테이블 식별자와 SQL 구문을 확인하도록 바꿨다. 독립 감사에서 문장 끝 UI 라벨의 잔여 오탐과 추가 SQL 구문의 누락을 발견해 회귀 사례를 확대했다. 이 검사는 좁은 구문 검사이며 모든 자연어 설계를 판정하는 SQL 파서는 아니다.

앱의 생성 deadline은 시간 초과 때 `LocalizedError`가 없는 내부 enum을 던졌다. 실제 deadline을 짧게 주입한 시험에서 내부 타입과 `error 0`가 사용자 메시지로 노출됐다. 한국어·영어 시간 초과 안내를 추가하고, 실패 상태·원문 재생성·취소·성공 결과가 유지되는지 검사했다. 시간 초과의 존재를 없애는 변경은 아니다.

## 검증 범위

로컬 Command Line Tools에는 XCTest가 없어 정식 `swift test`는 테스트 모듈 import 단계에서 실행하지 못했다. 대신 production 소스와 저장된 테스트 본문을 직접 컴파일한 별도 하네스로 Runner, Provider 응답 경계, 생성 계약, semantic flow, AppModel 처리·재생성·취소·사용량, deadline을 검증했다. 이 결과를 정식 XCTest 실행으로 집계하지 않는다. Python은 200개 중 197개 통과·환경 의존 3개 건너뜀이다. 정식 전체 XCTest와 패키징은 [PR #28의 CI](https://github.com/techjuicelab/opennotype/pull/28/checks)에서 확인한다.

합성 원문으로 production ProviderClient·DecisionClient·Runner를 사용하는 제한된 실제 API 시험도 실행했다. 기본 모델 `openai/gpt-oss-120b`, 생성 30초·4,096토큰, Jev 10초, 기존 검토 기준을 유지했다. 키는 1Password에서 런타임에만 주입했다. 개인 녹음, 제공자 원 응답, 숨은 추론, 키 값은 시험 자료에 저장하지 않았다.

동일한 메모 앱 합성 요청의 수정 전·후 시험은 각각 네 요청을 6.58초·5.35초에 완료했지만, 두 경우 모두 `unsupportedAdditions`의 신호·확신 기준에 못 미쳐 최종 보류됐다. 두 초안 모두 첫 검토부터 미달했으므로 새로 생략하는 분기의 실제 API 성공 사례가 아니다. API 생성 응답 오류·시간 초과도 이 두 실행에서는 발생하지 않았다. 이 결과를 생성 품질이나 일반적인 지연 개선으로 계산하지 않는다. 별도 회귀 시험에서는 통과 초안의 불필요한 두 번째 호출이 없어졌고, 해당 호출에만 주입한 오류·시간 초과로 작업이 실패하지 않음을 확인했다.

세 번째 합성 요청은 설정 화면의 `Create Table` 버튼을 `새 표 만들기`로 바꾸고 동작을 유지하는 작업이었다. 실제 생성된 후보는 기존 키워드 검사에서 거부되던 명칭을 포함했으나 수정한 구문 검사를 통과했다. 첫 Jev 검토 뒤 다듬기 요청을 생략하고 동일한 후보를 최종 검토해, 생성 1회·검토 2회로 3.97초에 완료했다. 두 검토 모두 네 축의 기존 기준을 통과했고 최종 결과도 원문의 버튼 이름·동작 유지 조건을 보존했다. 이는 합성 한 사례의 관측이며 일반 성공률을 뜻하지 않는다. 세 시험 합계 11개 요청의 응답 보고 비용은 USD 0.007257478, 비용 미확인 요청은 없었다. API 시험 뒤 콜론 뒤 UI 명칭의 로컬 검사만 추가 보완했으며, 이 한 문자 변경은 같은 입력을 포함한 production-source 회귀와 독립 68개 검사로 확인했다. 추가 API 재시험은 하지 않았다.

실측·소스 hash·재현 자료는 로컬 `build/prompt-debug-2026-10-08/`와 `build/prompt-debug-app-20261008/`에 보관한다. 빌드·설치 확인과 후속 실제 API 결과는 같은 자료 및 PR 검사에서 확인한다. 기존의 Jev 과도한 보류와 모델의 의미 누락 가능성은 이번 코드 수정으로 해결됐다고 주장하지 않는다.
