# 실제 모델 비교와 최종 정리 규칙 선택

평가일: 2026-09-12. Groq `openai/gpt-oss-120b`에 고정 합성 문장을 보냈다. **기본 문장 정리 규칙은 Codex `233fd1f`를 그대로 채택했다.** Claude 브랜치의 규칙을 합친 후보와 수정 후보는 이번 비교에서 기존 Codex 규칙보다 나은 결과를 입증하지 못했다. 기록 비교·복사·수동 재처리 UI, 대조 명세와 평가 도구는 별도로 통합했다.

첫 통합 후보는 매출 요청을 두 문장으로 반복했다. “전체 명제를 버릴 때는 명시적인 취소가 필요하다”는 보호가 중복 통합까지 억제할 수 있어, 별개 사건의 삭제와 같은 요청의 통합을 구별했다. 근거 없는 지시 대상을 상정해서 필러를 보존하지 않도록 고치고, 원래 단어를 유지하라는 부가 표현도 뺐다. 고정 평가 문장을 프롬프트에 새로 넣지는 않았다.

수정 후 매출·환불 요청은 한 문장으로 합쳐졌지만 문두 필러와 다른 반복은 남았다. 같은 9사례에서 더 긴 후보가 기존 규칙보다 정리 통과 수가 낮았으므로 기본값에 올리지 않았다. 이는 작은 단회 평가를 근거로 모든 언어와 발화에서 Codex가 우월하다고 선언하는 것이 아니라, **새 후보의 이득이 확인되지 않은 상태에서 기존 규칙을 보존하는 선택**이다.

## 방법과 판정의 경계

- 사용자 음성·기록·개인 자료 대신 [통합 평가 10사례](../../fixtures/integration-cleanup.json)를 사용했다. 전사 이후 문장 정리 비교이며, 마이크·STT·다른 앱 입력·Typeless 앱 자체의 결과는 평가하지 않았다.
- 각 Git 버전의 실제 `ProcessingPrompt.build`와 의존 Swift 소스를 컴파일해 요청을 추출했다. fixture·입력 JSON·모드·프로필·사전·문맥을 동일하게 맞췄다. 채택한 현재 소스는 Codex export의 요청과 일치한다.
- 앱과 같은 strict JSON schema, `reasoning_effort=low`, `include_reasoning=false`를 사용했다. 평가 출력 상한은 1,024토큰으로 앱의 16,384토큰보다 작다. 불완전 응답은 언어 품질 점수에 넣지 않는 기준이었으며 이번 정상 41응답에서 해당 오류는 없었다.
- 두 에이전트가 버전·프롬프트·비용·지연을 숨긴 출력과 보존 조건을 독립적으로 채점했다. 루트가 출력과 판정 근거를 다시 대조했다. 위 표의 의미·정리·주요 손실 판정은 두 평가자가 일치했다. 사람의 독립 평가나 통계적인 인증은 아니다.
- 기대 문장 완전 일치는 점수가 아니다. 동의 표현·구두점 차이를 허용하고, 사실·수량·시각·부정·조건·태도·리터럴·모드와 반복 정리를 별도로 봤다.
- 출력 판독 전에 독립 명세 검토에서 FC04의 `그 자료`가 지시어로도 읽힘을 확인했다. 유지·생략 모두 의미가 맞으면 허용하는 보완을 세 버전에 동일 적용했다. API에 보낸 동결 fixture는 바꾸지 않았고 [판정 보완](integration-evidence/integration-review-policy.json)을 별도로 남겼다. FC01의 `그 배포 일정`도 같은 지시 기능 기준으로 허용했지만 문두 `그 급한 건`은 필러로 판정했다.
- 각 버전·사례당 1회이며 세 버전 단계에서는 사례별 순서를 회전했다. 수정 후보는 먼저 본 실패 사례를 반영한 뒤 같은 세트에서 재평가했다. 독립 holdout이 아니며, 버전 평가 시점·캐시·단회 생성 변동을 통제한 통계 실험도 아니다.
- 최종 블라인드에서 기존 Codex 응답을 새 라벨로 재사용한 것은 검토를 위한 대조군 재표시다. 새 API 호출이나 독립적인 추가 사례로 합산하지 않았다. 일부만 완료한 첫 단계도 완전한 30응답 비교로 제시하지 않았다.

수정 후보의 이 표상 추정 비용은 약 14.0% 높았다. 지연은 HTTP 호출 구간이며 요청 사이 대기·녹음·STT·삽입을 제외한다. 단회 측정만으로 사용자 체감 속도 차이나 실제 청구액 차이를 확정하지 않는다.

전체 승인 예약 한도는 US$0.10이다. 합계 **42회 시도, 41회 정상 응답, 이전 단계의 HTTP 429 1회**였다. 41개 정상 응답의 보고 토큰 기준 비용 추정 합계는 **US$0.01746585**다. 429의 사용량과 실제 청구 여부는 확인되지 않았으며 0으로 취급하지 않았다.

실패·미확인·이미 시도한 요청의 예약액은 환급하지 않았다. 사용자 인터뷰 및 후보 수정으로 명시적으로 취소한 미시작 요청만 재배정했다. 최종 미배정 여유는 US$0.00053155이며 추가 API 호출은 하지 않았다. [예산 원장](integration-evidence/budget-ledger.json).

첫 실행의 6번째 요청에서 429를 받아 중단했다. 이후 요청 시작 사이에 25초 간격을 두었다. Groq의 조직 단위 제한과 실제 헤더를 참고했으며, 공개 Free Plan의 해당 모델 한도는 분당 8,000토큰·30요청이다. 실제 계정 한도가 우선한다. [공식 제한 문서](https://console.groq.com/docs/rate-limits).

GPT-OSS 120B의 공개 입력·출력 단가는 각각 100만 토큰당 US$0.15·US$0.60을 사용했다. 추정값은 실제 청구액·캐시 할인·무료 할당·크레딧·세금과 다를 수 있다. [공식 모델 가격](https://console.groq.com/docs/models).

키는 1Password에서 실행 환경에만 주입했으며 키·인증 헤더·공급자 오류 본문은 증거에 저장하지 않았다. 이 CLI 평가 사용량은 앱 밖에서 발생했으므로 앱 사용량 화면에 자동 수입되지 않는다. 새 기록 재처리 기능의 앱 내 사용량 연결은 별도 회귀 테스트로 검증했다.

## 증거와 재현

[증거 안내](integration-evidence/README.md), [독립 채점·사용량 통합 JSON](integration-evidence/evaluation-summary.json)에 실제 출력과 판정 매핑, 요청 상태, 모델·프롬프트 출처·토큰·지연을 보존했다. 후보 소스도 남겨 기본 코드에 채택하지 않은 실험을 재현할 수 있다.

```sh
python3 scripts/export-cleanup-prompts.py --ref 233fd1f --fixtures docs/fixtures/integration-cleanup.json --output build/quality-eval/reproduced-codex.json
python3 scripts/compare-cleanup-variants.py --variant codex=build/quality-eval/reproduced-codex.json --max-usd 0.03 --output build/quality-eval/new-dry-run.json
```

두 번째 명령은 기본적으로 계획만 만들고 키·네트워크에 접근하지 않는다. 새 `--execute`는 새로운 평가이며 위의 이미 사용한 예산이 초기화되는 뜻이 아니다. 실패·중단 요청은 재개 시 다시 보내지 않으며, 예약 상한 초과나 예상 밖 모델 응답 뒤에는 일반 재개를 막는다.
