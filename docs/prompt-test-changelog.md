# Prompt Test 변경 이력

**OpenNoType Prompt Test**의 이력이다. 개발 브랜치에서 시작한 기능을 0.2.7에서 메인에 채택하며 일반 앱과 테스트 앱의 버전을 맞췄다. 앱 식별자·설정·키·기록은 계속 분리한다. 아래 버전이 공개 다운로드나 운영 앱 교체를 뜻하지 않는다. 사용 방법과 현재 계약은 [음성으로 작업 프롬프트 만들기](prompt-composition.md)를 참고한다. 과거 실험 보고서는 당시의 동작과 관측을 유지한다.

## 0.2.8 (44) 후보 — 2026-10-09

- **입력 준비 경계:** 앱 활성화 뒤 잠시 사라진 접근성 입력창을 제출 전에 한도 내에서 기다린다. 다른 앱·보안 입력·취소·기존 입력창 바인딩 검사는 유지하며, 전송 후 재붙여넣기는 하지 않는다.
- **진단:** 받아쓰기·번역·선택 문장 수정에서 실제 음성 입력의 차단과 내용 검토 보류를 고정 상태 코드로 구분한다. 개인 문장·클립보드 내용·키를 진단에 넣지 않는다. 프롬프트 만들기의 별도 결과·검토 화면은 유지한다.
- **배포 경계:** `codex/insertion-focus-reliability`의 일반/테스트 앱 소스 버전이다. 메인 병합과 공개 릴리스를 뜻하지 않는다. [검증 범위](input-reliability.md)를 참고한다.

## 0.2.7 (43) — 2026-10-09

- **메인 채택:** 0.2.5·0.2.6에서 누적한 프롬프트 생성·내용 검토 참고·새 녹음 자동 입력·저장 복구 보호를 일반 앱에 포함한다. 일반 앱과 진단용 테스트 앱의 소스 버전은 0.2.7(43)이다.
- **기존 환경 보존:** 일반 앱의 모델·키·설정·기록을 유지하며 테스트 앱의 데이터나 키를 자동으로 합치지 않는다. 일반 앱의 프롬프트 기본 단축키는 `⌃⌥⇧Space`이며 다른 기존 단축키는 유지한다.
- **검증 범위:** 직전 기능 소스의 CI에서 XCTest 1,108개 통과·2개 건너뜀, Python 209개 통과와 두 앱 빌드를 확인했다. 버전 승격 후 CI와 로컬 설치·실행 검증은 별도로 기록한다. 실제 음성부터 외부 입력창까지의 통합 동작과 일반적인 의미 품질의 잔여 검증은 유지한다.
- **배포 경계:** 메인 병합과 로컬 설치를 위한 버전이며 공개 릴리스나 `v0.2.7` 태그 발행을 포함하지 않는다.

## 0.2.6 (42) — 2026-10-09

추가 위험 점검에서 재현한 저장·복구 결함을 수정한다.

- **실패 녹음 보존:** 일반 받아쓰기·번역·문장 수정의 실패 녹음을 재처리한 뒤, 요청된 기록 저장이 실패하면 원음과 복구 항목을 유지한다. 기록 보관을 사용하지 않는 경우의 정상 완료 정책은 그대로다.
- **보관 설정 유지:** 기록 재처리는 저장소의 현재 보관 정책으로 만료 여부를 확인한다. 늦은 응답이 시작 당시의 이전 보관 기간을 다시 적용하여 기록을 삭제하지 않게 한다. 보관 기간을 바꾸지 않은 경우의 정상 만료는 유지한다.
- **검토 응답 형식:** 같은 JSON 객체에 중복된 이름이 있으면 해석이 모호한 응답으로 거절한다. 기존 사용량 기록·취소·HTTP 오류 처리를 유지하며 의미 검토 기준이나 API 호출 예산은 변경하지 않는다.
- **독립 비교 하네스:** 새 JSON 검사 소스를 공통 컴파일 목록에 등록한다. 모델·Jev 비교 도구에서도 실제 Core 컴파일과 소스 SHA 추적이 함께 동작한다.
- **검증 범위:** 임시 암호화 저장소·모의 제공자·가짜 시계로 실제 `AppModel`과 `SecureStore` 경로를 재현한다. 실제 사용자 기록·마이크·외부 편집기에는 쓰지 않는다. 추가 위험과 남은 검증 범위는 [추가 위험 점검](reviews/2026-10-09/prompt-risk-audit.md)에 기록한다.

일반 앱의 버전과 공개 릴리스는 변경하지 않는다. 이 버전의 소스 커밋·빌드 여부와 설치된 앱의 버전은 따로 확인한다.

## 0.2.5 (41) — 2026-10-09

초기 테스트 이후 브랜치에 누적된 변경을 테스트 전용 버전으로 묶었다.

- **내용 검토를 참고 표시로 제공:** 의도·임의 추가·누락 검토에 우려가 남아도 프롬프트와 참고 표시를 제공한다. 기존 지침 관련 검토 기준 미달과 형식 오류·요청 실패는 계속 제공을 중단한다. 검토 통과는 의미 보존의 보장이 아니다.
- **미정 상태 보존:** 미정인 선택 때문에 질문이나 결정 작업을 임의로 추가하지 않도록 지시한다. “기능을 추가하되 도입은 미정이라고 명시”처럼 희망을 구현 명령으로 바꾸는 경우도 생성·의도 검토에서 구분한다. 사용자의 명시적인 결정 위임과 도입이 확정된 기능의 on/off 요구는 보존한다.
- **원문과 결과 보존:** 누락 위험이 있는 복구에는 원문 문장에 대응하는 구조 응답을 사용한다. 문장 ID 검사는 의미 보존의 증명이 아니다. 새 녹음 시작 실패·파일 없음·짧음·낮은 음량에는 이전 완료 결과와 원인 안내를 남긴다. 홈에서는 완료 카드를 위쪽에서 확인하고 복사할 수 있다.
- **새 녹음 자동 입력:** 다른 앱에서 단축키로 시작한 새 프롬프트 녹음은 정상 결과와 내용 검토 참고 경고가 있는 결과를 원래 입력창에 자동 입력한다. 성공 시 작업하던 앱을 유지한다. 홈의 복사용 녹음과 기록·실패 녹음 재처리, 원문 수정은 자동 입력 없는 미리보기다. 입력 실패에는 결과와 복사 대안을 제공하며 AI의 제출 버튼이나 Enter를 대신 누르지 않는다.
- **취소·설정 철회 안내:** 취소나 설정 철회 이후 후속 처리와 늦은 결과 게시를 중단한다. 이미 붙여넣기를 요청했지만 반영을 확인하지 못한 경우에는 같은 작업에 한해 안내를 남기며, 새 작업에 이전 안내를 덮어씌우지 않는다.
- **테스트 버전 분리:** `Resources/PromptTestVersion.plist`의 `0.2.5 (41)`을 테스트 번들에만 적용한다. 일반 앱의 `Resources/Info.plist`는 `0.2.4 (40)`을 유지한다. 테스트 번들에 소스 커밋, 미커밋 변경 여부, UTC 빌드 시각을 기록한다.

이 버전 구분을 위해 새 AI 단계나 모델 변경을 추가하지 않는다. 정상 완료의 문장 생성 1~2회·Jev 검토 2회 예산을 유지한다. 실제 제공자 비교, GUI 확인, 모의 입력·취소 회귀는 각 변경의 근거이며, 일반적인 의미 품질이나 물리 마이크 녹음부터 대상 앱 입력까지의 모든 통합 동작은 검증이 완료되지 않았다. 관련 관측과 한계는 [제공 정책](reviews/2026-10-08/prompt-delivery-policy.md), [새 녹음 진단](reviews/2026-10-08/prompt-fresh-recording.md), [미정 기능의 구현 지시 진단](reviews/2026-10-08/prompt-undecided-authority.md)에 기록한다.

### 추가 개선 우선순위

2026-10-09의 사용자 결과와 코드 읽기 검토를 구분한 후속 항목이다. 아래 사례의 실제 제공자 반복 시험은 이번 버전 관리 변경에서 실행하지 않았다.

| 우선순위 | 근거 | 다음 검증과 기대 결과 |
| --- | --- | --- |
| P2 · 의미 보존 대비 시험 | 사용자 결과가 모호한 “문구”를 “요청 문구”로 좁혔다. 생성 지침에는 이미 모호한 대상을 추정하지 말라는 규칙이 있다. | “문구는 짧게”, “앱 버튼 문구는 짧게”, “지금 만들 프롬프트는 짧게”를 따로 시험한다. 명시한 대상만 보존하고 모호한 경우 대상을 새로 정하지 않는다. 지침·모델·검토 수치 변경 전에 실제 결과와 사람의 비교 판정을 남긴다. |
| P2 · 조건과 미정 상태 대비 시험 | “날짜를 안 말하면”이 “날짜를 입력하지 않으면”으로 넓어졌다. 최신 결과는 알림 희망과 도입 미정 상태를 함께 보존했다. | 음성 언급과 일반 입력 조건을 구별한다. 알림의 단순 희망·도입 미정·명시적 결정 위임을 따로 시험하며, 미정인 경우 구현하거나 결정을 요구하는 지시를 추가하지 않는다. |
| P2 · 실제 입력 통합 시험 | 앱의 성공 안내와 기록 저장은 확인할 수 있지만 대상 앱에 반영된 내용까지 별도로 확인해야 한다. AX 요소를 제공하지 않는 앱에서는 앱 수준 확인만 가능하다. | 실제 마이크로 새 녹음 후 대상 편집기에 정확히 한 번 입력되고 기록에 남는지 확인한다. 처리 중 다른 필드로 이동·취소·저장 실패도 함께 비교한다. 홈 녹음·재처리·원문 수정은 미리보기만 제공한다. |

## 0.2.4 (40) — 초기 테스트

별도 앱 이름·식별자·설정·기록과 단축키를 사용하는 초기 Prompt Test 빌드다. 테스트 버전을 따로 관리하지 않아 일반 앱의 버전 값을 상속했다. 이후 같은 표기 아래에서 여러 브랜치 변경을 시험했으므로, 이 버전 번호만으로 특정 코드나 동작을 식별할 수 없다. 당시의 소스 커밋과 실험 기록을 함께 확인해야 한다.

## 버전 관리 규칙

- 사용자에게 전달할 동작 변경마다 테스트 빌드 번호를 증가시킨다. 기능 묶음을 새 버전으로 제공할 때에는 패치 버전도 증가시킨다.
- 동일 소스의 재빌드는 `OpenNoTypeTestBuiltAt`의 UTC 시각으로 구별한다. 빌드 시각 자체가 동작 변경이나 새 공개 릴리스를 의미하지 않는다.
- `OpenNoTypeTestSourceCommit`과 `OpenNoTypeTestSourceDirty`를 함께 확인한다. `SourceDirty`가 `true`인 빌드는 해당 커밋의 소스와 완전히 일치한다고 보지 않는다.
- 일반 앱의 버전·공개 태그·릴리스는 별도 배포 절차를 따른다. 테스트 버전 변경만으로 이를 생성하거나 운영 앱을 교체하지 않는다.
