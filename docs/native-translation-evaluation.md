# 음성 번역 실측 기록

파싱 성공, 입력 전 보존 검사 통과, 의미 보존, 자연스러움은 서로 다른 결과다. 아래 평가는 Codex 에이전트의 합성 발화 판독이며 원어민 사람의 검수가 아니다. 사용자의 실제 녹음·키 값·인증 자료는 포함하지 않는다.

## 2026-10-05 제품 소스 `0ed0594`

Groq `openai/gpt-oss-120b` / `medium`에 고정된 합성 텍스트 32개를 요청했다. 기존 사례 22개와 제품 지침 동결 전에 작성자에게 공개하지 않은 추가 사례 10개를 구별했다. 실제 제품 `ProviderClient`와 보존 검사를 사용했고, 지침·전체 JSON 입력·모델·effort·컴파일된 프로그램의 해시로 요청을 식별했다. 문장에 따라 달라지는 프로필·사전·문맥도 입력 해시에 포함했다.

| 관측 | 결과 |
| --- | --- |
| HTTP 요청 | 32회 모두 HTTP 200, 재시도 없음 |
| 반환 | 29개 |
| 입력 전 시각 보존 차단 | 3개: NT16, HV201, FH301 |
| 반환된 명확한 수행자 추가 | 2개: NT03, HO01 |
| 일반 인용 대사 미번역 | 1개: GC401 |
| 최종 값은 맞지만 정정 흔적 잔존 | 1개: GC404 |
| 날짜 역할 해석 주의 | HO03; 명확한 반전으로 집계하지 않음 |
| 기록된 사용량 | input 81,254 / output 12,450 tokens, 차단 응답 포함 |

NT03과 HO01은 원문에 없는 진행 주체를 `we`로 특정했다. GC401은 일반 대사의 한국어 내용을 일본어 인용문 안에 그대로 남겼다. GC404는 최종 `map_new`와 설명 유지 요청을 보존했지만 `map_old, no, as map_new`라는 말실수 흔적도 남겨 번역의 정리 계약을 충족하지 못했다. 일본어의 availability·다음 기회·자동 테스트 통과 표현 등에는 직역 어감이 남았다. 이들을 HTTP 오류나 단순 파싱 실패로 분류하지 않는다.

차단된 3개는 응답 사용량과 고정 오류 분류만 남기고 출력은 반환하지 않았다. 그 문장 전체의 수행자·자연스러움은 판독하지 않았으며, 차단을 정상 번역 성공으로 집계하지 않았다. 반대로 명시된 `I`/`we`, 24시간 표기에서의 올바른 오후 변환, 코드 식별자와 일반 시각 표기 등 정상 반례도 함께 확인했다.

텍스트 결과 파일 SHA256: `1c61b680cb96b14050d47beec4ce5fd86980cedd488e643c73c11668bda4f0aa`.

## 같은 제품 소스의 합성 음성 3개

한국어·영어·일본어 TTS로 만든 16kHz mono PCM WAV를 실제 `whisper-large-v3-turbo`로 전사하고, 전사 결과를 같은 제품 번역 요청에 넣었다. 세 사례 모두 전사 1회·번역 1회가 HTTP 200으로 완료됐다. 전사는 수사→숫자 표기와 구두점 차이 외에 주요 내용 손실이 없었고, 번역도 요청·비긴급·수치·승인 전 공유 금지·일정 미확정을 유지했다. 일부 한국어·영어 표현에는 경미한 문체 주의가 있었다.

번역 응답에서 기록한 사용량은 input 7,597 / output 1,052 tokens다. 전사 응답의 token 필드는 없어 알 수 없음으로 유지한다. 음성 결과 파일 SHA256: `8e816b45cc749c26512314caa0aceb524e4dac1d9380c377f9f39ed42a2c6c99`.

이는 합성 음성의 API 연결 근거다. 실제 마이크·잡음·대상 앱 삽입·사용자의 자연 발화·원어민 사람 검수를 대신하지 않는다.

## 후속 지침 후보

일반 인용 대사와 명시 코드·표기 보호를 구별하고, 미지정 수행자를 유효한 분석 상태로 두며, 번역의 최종 점검을 프로필·대안 출력 지침 뒤로 옮기는 후보를 별도 소스 사본에서 준비했다. 모델·effort·JSON 형식·보존 검사·기존 API 호출 단계는 바꾸지 않았다. 세 변경을 함께 비교하므로 개별 변경의 인과 효과를 분리하지 않는다.

기존 32개에서 선별한 대응 부분표본 14개, 먼저 공개된 수행자 대조 회귀 2개, 후보 지침 동결 후 공개한 새 합성 사례 6개로 총 22개를 준비했다. 같은 합성 음성 3개도 이어서 전사→번역했다. 앞의 32개와 같은 모집단이나 전체 품질 통과율로 혼합하지 않는다.

후보 소스·프로그램·입력·WAV 해시와 기존 비번역 요청 320개 바이트 동일을 검증했다. 기존 보존 검사·프롬프트 테스트 본문과 새 조립 경계 초안 1개, 총 33개는 로컬 standalone assertion adapter에서 통과했다. 정식 XCTest·실제 모델 품질 검증과 구별한다. 초기 인증 시간 초과 후 Codex가 실제 텍스트 22개·같은 합성 음성 3개 시험을 직접 완료했다.

| 반환된 명확한 수행자 추가 | NT03, HO01, HV201, FC501의 4개 |

HV201은 제품 v3에서는 출력이 차단돼 당시 문장 전체를 볼 수 없었다. 이번에 반환된 문장의 수행자 오류를 이전 출력과 직접 비교한 악화로 단정하지 않는다. 명시된 팀·1인칭·허가 질문·희망 날짜와 결정 계획일을 유지하는 정상 대조도 확인했다. 주요 항목 보존과 전체 자연스러움 통과를 구별하며, 인용문의 공손함 변화와 활동·발표 참조의 해석 주의를 별도로 남겼다. STT token 필드는 여전히 알 수 없음이다.

주어와 정정 흔적 문제가 남아 후보 v5 전체를 제품에 채택하지 않았다. 인용 보호 지침의 충돌만 바로잡는 별도 작은 수정안 v6를 준비했다. 미지정 수행자 규칙과 최종 점검 위치는 제품 그대로 두며, 일반 대사와 명시 코드·표기 보호 정책을 번역 헤더에서 직접 선택한다. 기존 받아쓰기·선택 문장 수정 320개 요청 바이트는 동일했다. 기존 회귀 6개와 수정안 소스·프로그램 동결 후 독립 작성한 새 대조 2개, 총 8개를 별도로 준비했다. v5의 복합 변경 관측을 이 작은 수정안의 효과로 그대로 재사용하지 않는다.

결과 파일 SHA256: `f3e36abca7b5d31a9f7119a8945095dbfbff663e2f1786880c2e1d21153d4a76`.

정적 지침 충돌과 기존 회귀에서 확인한 인용 경계에 한정해 v6의 두 제품 소스 파일을 동결 사본 그대로 반영했다. 새 XCTest 계약은 번역 여부에 따른 정책 선택과 JSON 입력 경계를 검사한다. 수행자 추정·말투 변화·정정 설명 잔존은 해결했다고 주장하지 않는다. 신규 두 사례의 실제 모델 평가는 API 제한으로 미완료이며, 합성 음성 세 사례의 관측은 제품 v3와 미채택 후보 v5에 해당한다. 인용 정책을 반영한 제품의 별도 음성 재시험이나 실제 마이크·입력 검증으로 재분류하지 않는다.
