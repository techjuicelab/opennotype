# 자동 입력 타이밍과 실패 진단

0.2.8 (44)는 `codex/insertion-focus-reliability`의 입력 안정화 후보다. 메인 0.2.7과 공개 다운로드 v0.2.3의 상태를 별도로 유지한다.

## 조사한 증상

Codex에서 음성 처리가 끝난 뒤 글이 들어오지 않고 OpenNoType 창이 앞으로 나오는 간헐적 현상이 보고됐다. 관리 창은 전송 전 입력 차단, 내용 검토 보류, 복사용 재처리에서도 표시될 수 있으므로 창이 나타났다는 사실만으로 붙여넣기 지연 원인을 확정할 수 없다. 조사 당시 수집한 입력 로그에는 성공한 붙여넣기만 남아 있어, 보고된 실사용 실패의 단일 원인은 아직 포착하지 못했다.

## 변경 경계

- 다른 앱으로 제어를 돌려주는 기존 활성화 경로의 고정 50ms 대기를 준비 상태 관찰로 바꾼다. 두 번째 시도의 기존 시간 예산 안에서 OpenNoType 활성화를 확인한 뒤 대상 앱에 제어를 넘기며, 협력 활성화에 필요한 `yieldActivation(to:)`를 먼저 호출한다. Apple도 활성화 요청만으로 실제 활성화를 보장하지 않는다고 설명한다. [Apple의 활성화 API 문서](https://developer.apple.com/documentation/appkit/nsrunningapplication/activate%28from%3Aoptions%3A%29)
- 앱 활성화가 끝나도 접근성 입력창 정보는 잠시 준비되지 않을 수 있다. 녹음 시작 때 입력창을 확인했는데 제출 직전 같은 앱에서 입력창 정보가 사라진 경우에만, 최대 0.3초 동안 준비 상태를 확인한다. 준비된 입력과 접근성 정보를 제공하지 않는 앱에는 고정 지연을 추가하지 않는다.
- 준비 대기 중 다른 앱, 확인되지 않은 입력창 소유자, 보안 입력, 취소를 발견하면 전송하지 않는다. 기존 프롬프트 입력창 바인딩과 선택 문장 수정의 원문·선택 검사를 유지한다.
- 붙여넣기를 이미 보냈거나 접근성 쓰기가 도착했을 수 있으면 자동으로 다시 보내지 않는다. 확인이 늦었다는 이유로 중복 입력하지 않는다.
- 받아쓰기·번역·선택 문장 수정의 실제 음성 입력 진단에서 입력 차단과 내용 검토 보류를 구분한다. 진단은 고정 상태 코드와 대상 앱 식별자만 사용하며, 말한 내용·입력창 내용·선택 문장·클립보드 내용·키를 포함하지 않는다. 프롬프트 만들기는 별도의 결과·검토 화면을 유지하며 이 진단에 포함하지 않는다.

## 검증과 한계

가짜 시계·입력창·활성화 상태로 실제 준비 경계와 AppModel의 입력/관리 창 분기를 검사한다. 로컬의 독립 Swift assertion 하네스와 정식 XCTest/CI 결과는 별도로 기록한다. 이러한 시험은 실제 마이크, Codex의 모든 입력창, 모든 포커스 전환을 재현한 결과가 아니다.

입력 누락이 다시 발생하면 홈의 **입력 준비 상태 → 설치 후 확인 → 최근 입력 진단**에서 같은 작업의 상태를 확인할 수 있다. 내용 검토 보류는 입력 타이밍 실패와 다른 경로이며, 이번 변경에서 모델·검토 정책을 바꾸지 않는다.
