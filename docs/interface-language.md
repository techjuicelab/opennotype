# 화면 언어와 버전 정책

## 설치와 변경

- 0.1.14(16)의 신규 설치는 macOS 언어와 관계없이 **English**로 시작한다.
- **Settings → Mac & general → App language → 한국어**로 바꾸면 화면·메뉴·새 안내 문구가 한국어로 전환된다. 한국어 화면에서는 **설정 → Mac·일반 → 앱 언어**를 사용한다.
- 기존 설정에 언어 필드가 없으면 이전 한국어 화면을 유지한다. 저장된 `en`/`ko` 선택은 재실행과 업데이트 후에도 보존한다.
- 언어 필드만 알 수 없는 값이면 영어로 되돌리고, 다른 제공자·모델·키·단축키 설정은 유지한다. 키는 이 변경으로 읽거나 이동하지 않는다.
- 화면 언어를 바꿔도 받아쓰기 원문·개인 사전·기록·AI 프롬프트·번역 대상 언어는 바꾸지 않는다. 기존 기록과 이미 발생한 오류 내용은 다시 번역하지 않으며, 새로운 안내부터 선택 언어를 사용한다.
- macOS 권한 대화상자는 시스템이 관리한다. 영어·한국어 권한 설명 리소스를 제공하지만 표시 언어는 macOS의 선택을 따른다.

## 구현과 기여

`AppLanguage`는 저장값 `en`/`ko`를 사용한다. `AppLocalization.shared.language`는 관찰 가능한 화면 언어이며 동시 접근을 동기화한다. 표시 문자열은 `L("한국어", "English")`로 두 번역을 함께 관리한다. Swift 보간식을 사용하므로 숫자·이름·모델 ID·사용자 데이터의 형식은 컴파일러가 검사한다. 선택되지 않은 번역의 보간식은 실행하지 않는다.

새 표시 문구는 두 언어를 함께 작성한다. 정적 변수에 번역 결과를 저장하면 전환 전 언어가 남으므로 화면에 쓰는 카탈로그는 계산 속성을 사용한다. 날짜는 선택한 화면 locale로 표시하고, 모델 가격 USD 표기는 명확한 단가 비교를 위해 그대로 유지한다. 모델 ID·프로필 enum·저장 키·URL·정규식·프롬프트·실제 사용자 텍스트를 표시 문구처럼 번역하지 않는다.

`LocalizationTests`, `InterfaceLanguageTests`, `ProviderModelPickerLocalizationTests`는 신규 설치, 기존 설정 이전, 재저장, 관찰 갱신, 언어 전환 후 모델 ID/가격 보존, AI 요청 언어 독립성을 검사한다. 이전 한국어 표시 계약은 명시적인 한국어 테스트 환경에서 유지한다.

## 버전 부여

사용자에게 설치하는 동작·기능이 바뀌면 다음 미리보기 버전과 빌드 번호를 함께 올린다. 영어 기본/한국어 선택은 **0.1.14(16)**에 도입했다. Jev 제안 저장·되돌리기와 명시적 재검토를 추가하는 다음 버전은 **0.1.15(17)**이다. Jev 연결 선택·문장 모델 가격 확장은 0.1.13(15)이다.

모든 커밋에 새 앱 버전을 붙이지는 않는다. 문서·테스트만 바꾸거나 같은 배포 후보를 완성하는 수정은 현재 후보 버전으로 묶는다. 이후 별도로 전달하는 기능·동작 변경에는 다음 버전을 사용한다. `Resources/Info.plist`를 버전의 기준으로 삼고 앱 빌드·설치본·설치 문서를 함께 확인한다. 커밋·푸시, PR 병합, GitHub Release 공개는 서로 다른 상태로 보고한다.
