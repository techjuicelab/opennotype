# 음성으로 작업 프롬프트 만들기

개발 브랜치 `codex/voice-prompt-composer`의 기능이다. 공개 릴리스나 현재 설치본에 포함됐다는 뜻은 아니다.

## 별도 테스트 앱

기존 앱과 나란히 사용할 수 있는 **OpenNoType Prompt Test**를 `scripts/build-prompt-test.sh`로 만든다. 출력은 `build/prompt-test/OpenNoType Prompt Test.app`이며 일반 앱을 교체하지 않고 별도 이름으로 설치한다. 메뉴바 아이콘 옆 `TEST`와 창 제목으로 구별한다. CI에도 별도 테스트 앱 아티팩트를 제공한다.

이 앱은 실제 녹음·생성·Jev 검토를 실행한다. 디자인 샘플 앱과 다르다. 앱 식별자·설정·API 키·암호화 기록·음성 모델·임시 녹음 경로를 분리하며 기존 앱의 데이터를 자동 복사하지 않는다. 자동 업데이트도 연결하지 않는다. 처음에는 한국어 UI, Groq 음성 인식, OpenRouter 문장 생성·Jev를 선택하며 별도 테스트용 키 등록이 필요하다. 마이크 권한은 테스트 앱에 따로 허용한다.

테스트 앱의 기본 단축키는 받아쓰기 `⌃⌥⌘D`, 번역 `⌃⌥⌘T`, 수정 `⌃⌥⌘R`, **프롬프트 `⌃⌥⌘P`**다. 일반 앱의 Space 조합과 겹치지 않으며 설정에서 변경할 수 있다. 아래 사용 설명의 `⌃⌥⇧Space`는 일반 앱의 기본값이다.

중구난방하게 말한 아이디어를 Claude, ChatGPT, Codex, Grok, Gemini 등에 붙여넣을 짧은 작업 요청으로 정리한다. **목표·필요한 맥락·명시한 제약·원하는 결과**를 담으며 코드·의사코드·실행 명령·직접적인 설계안은 결과에 넣지 않는다. 상대 AI에게 코드 작성이나 설계를 요청하는 목표 자체는 표현할 수 있지만 OpenNoType이 그 코드를 작성하거나 설계를 결정하지 않는다.

프로젝트명과 대상 AI는 실제 요청에 명시한 경우에만 포함한다. 예시로 든 앱을 수신자로 고르거나, 말하지 않은 기술·프레임워크·역할·작업 단계·검증 조건·허가를 덧붙이지 않는다. 상대 AI의 기존 시스템·개발자·저장소 지침과 도구 사용 정책은 그대로 존중한다. 사용자가 명시한 새 브랜치·에이전트 수·기한 같은 작업 제약은 보존한다. 미정인 선택을 확정된 요구로 바꾸지 않는다.

## 사용

1. 홈의 **프롬프트 녹음 시작**, 메뉴바의 **프롬프트 만들기**, 또는 기본 단축키 **⌃⌥⇧Space**로 시작한다.
2. 하고 싶은 일과 필요한 조건을 편하게 말하고 같은 버튼이나 단축키로 녹음을 끝낸다.
3. 완성된 내용을 확인한 뒤 **프롬프트 복사**로 원하는 AI의 입력창에 붙여넣는다.

보류되면 시작하기 또는 다시 처리의 **보류된 프롬프트**에서 원문·실제 최종 검토 후보·검토 항목을 확인한다. 초안과 최종 후보가 다르면 구분해 표시한다. 검토의 선택값·통과 신호·모델 확신을 보여 주되 정확도로 해석하지 않는다. 통과 선택도 제공 기준에 못 미치면 보류한다. 보류 후보에는 프롬프트 복사 버튼을 제공하지 않는다. 이 확인 내용은 현재 작업의 화면용 메모리이며 새 작업·앱 종료 시 사라진다. 실패 녹음은 기존의 암호화·최대 24시간 복구 정책을 따른다.

통과 신호는 80% 이상, 모델 확신은 60% 이상이어야 하며 네 항목 모두 이 기준을 충족해야 한다. 화면은 기준 미달 값을 기준값으로 반올림하지 않고 소수 첫째 자리까지 내림해 표시한다. 같은 동작을 기능 구현 요청으로 표현하거나 원문에 명시한 브랜치·에이전트 수·기한을 보존하는 것은 임의 추가가 아니다. 원문에 없는 조건을 만들거나 구체 코드·설계를 포함하는 경우는 여전히 차단 대상이다.

음성이 잘못 인식됐거나 같은 원문을 다시 처리하려면 **원문 수정·다시 만들기**를 펼쳐 확인한 뒤 **이 원문으로 다시 만들기**를 누른다. 편집만으로 전송하지 않는다. 버튼은 현재 문장·Jev 설정으로 문장 생성 1~2회·Jev 검토 2회를 새로 실행하므로 추가 API 비용이 생길 수 있다. 음성 인식을 다시 실행하거나 녹음을 다시 전송하지 않는다. 생성과 검토 모두 편집한 원문을 사용하며, 최초 인식문은 별도로 표시한다. 동일한 원문도 명시적으로 재시도할 수 있지만 자동 반복은 하지 않는다.

수정한 원문과 재생성 결과는 화면용 메모리에만 두며 기록을 추가하거나 기존 기록·실패 녹음을 덮어쓰거나 삭제하지 않는다. 새 작업·앱 종료 시 최초 인식문을 포함한 화면 내용이 사라지고, 저장된 원래 기록과 실패 녹음은 각 보관 정책을 따른다. 빈 원문·허용되지 않은 제어문자·12,000 UTF-8바이트 초과는 전송 전에 거절한다. 처리 중에는 재생성할 수 없으며 취소·연결 설정 변경 이후 늦게 도착한 결과는 게시하지 않는다.

초안이 말줄임표로 끝나도 나머지 형식·코드 검사에 문제가 없으면 원본 그대로 첫 검토와 한 번의 다듬기에 전달한다. 첫 검토가 통과하더라도 이런 초안을 최종 결과로 선택하지 않는다. 다듬은 후보가 말줄임표로 끝나거나 최종 검사에 실패하면 제공하지 않는다. 호출 수를 늘리거나 검사를 건너뛰는 복구가 아니다.

기존 세 단축키는 업데이트 때 유지하며 새 조합만 추가한다. 새 기본 조합을 이미 사용하고 있으면 다른 조합을 선택한다. 실제 설정에서 현재 단축키를 확인할 수 있다. 프롬프트 모드는 OpenNoType 창에서도 녹음을 시작할 수 있고, 다른 앱에 자동 입력하거나 AI에 자동 제출하지 않는다. 마이크 권한은 필요하지만 이 모드에 손쉬운 사용 권한은 필요하지 않다.

받아쓰기 출력 언어·표현 강도·앱별 작성 방식·번역 다듬기는 이 기능에 적용하지 않는다. 기본적으로 발화의 주된 언어를 유지하며, 프롬프트 언어를 말로 명시하면 그 요청을 따른다.

## 처리와 연결

음성 인식 → 프롬프트 초안 → Jev 검토 → 필요 시 한 번 다듬기 → 최종 Jev 검토 순서다. 정상 완료 시 음성 인식 뒤 **문장 생성 1~2회, Jev 검토 2회**를 실행한다. 첫 검토를 통과한 완전한 초안은 생성 1회로 끝내며, 수정이 필요할 때만 두 번째 생성을 실행한다. 빈 생성·요청 실패·취소가 발생하면 해당 단계에서 중단하며 후속 호출을 계속하지 않는다. 자동 재시도나 반복 교정은 하지 않는다. 문장 생성은 현재 선택한 문장 제공자·모델을 사용한다. Jev는 문장을 다시 쓰지 않고 의도·임의 추가·핵심 누락·하네스 침해 여부를 구조화된 값으로 판정한다.

OpenRouter 프롬프트 요청은 선택한 모델을 유지하면서 출력 처리량이 높은 제공자를 우선하고(`sort:throughput`), 요청한 매개변수를 지원하는 다른 제공자로의 대체를 허용한다. 앱이 HTTP 요청을 반복하거나 다른 모델로 바꾸는 방식은 아니다. 계정의 제공자·개인정보 제한은 그대로 적용되며 제공자별 요금 차이가 생길 수 있다. 모든 적격 제공자가 제한되면 여전히 요청이 실패할 수 있다. 받아쓰기·번역·선택 수정의 제공자 대체 정책은 유지한다.

OpenRouter·Groq의 GPT-OSS 120b/20b는 이 모드의 초안·다듬기에서 `medium` 추론을 사용한다. 추론 내용은 출력하지 않으며 요청당 출력 한도 4,096토큰과 30초 제한을 유지한다. 추론 토큰도 비용과 토큰 한도를 사용하므로 기존 `low`보다 비용이나 대기가 늘 수 있다. 다른 모드와 모델의 정책은 유지한다.

Jev는 이 모드의 필수 단계다. 일반 받아쓰기의 자동 검토를 꺼 두어도 프롬프트 만들기에서는 실행한다. 문장 제공자가 OpenRouter이면 저장한 OpenRouter 키를 재사용할 수 있다. 다른 문장 제공자를 사용하려면 Jev의 TypeSafe 직접 연결 키를 설정한다. 녹음 시작 전에 연결 설정을 확인하며, 키를 확인하지 못하면 녹음과 유료 처리를 시작하지 않는다.

첫 검토에서 문제나 불확실성을 알리면 정해진 문제 유형만 최종 다듬기에 전달한다. 자유형 비평을 새 명령으로 전달하지 않는다. 첫 검토를 이미 통과한 완전한 초안은 두 번째 생성 요청을 생략하고, 초안 자체를 최종 Jev 검토에 보낸다. 첫 검토를 통과하지 못했거나 말줄임표로 끝난 초안은 한 번 다듬은 후보를 최종 검토한다. 두 경로 모두 최종 검토를 통과해야 제공하며, 최종 보류 후 초안으로 되돌아가 제공하지 않는다. 최종 검토의 네 축 모두 정책 기준을 통과한 결과만 완성 프롬프트로 제공한다. 검토 실패·시간 초과·불확실한 최종 판정은 보류하고 원문·중간 초안을 구분해 표시한다. 생성 결과가 비었을 때도 완성 프롬프트를 제공하지 않으며, 음성 인식 실패와 구분해 생성 응답 오류를 안내한다. 생성 실패·다듬기 실패·Jev 검토 실패는 실제 최종 검토 보류와 다른 제목으로 표시하고, 해당 단계에서 남은 원문·초안·후보·검토 항목만 안내한다. 프롬프트 모드의 응답 오류는 제공자 응답 JSON, 제공자 본문 추출, 생성 결과 JSON, 출력 형식·길이 검사를 구분한다. 오류에 제공자 본문·생성 내용·키를 넣지 않는다. Jev 판정과 정책 임계값은 정확성이나 코드·설계 완전 배제를 보장하지 않는다. 코드 fence, 명백한 코드·SQL 문법, HTTP 메서드와 경로 조합, 잘못된 응답은 로컬에서도 거부하며, 자연어 설계 등 의미 판단은 모델 검토에 의존한다.

원문과 각 결과는 각각 UTF-8 **12,000바이트**까지다. 긴 발화를 몰래 잘라 보내지 않고 나누어 말하도록 안내한다. 문장 생성은 요청당 최대 30초, Jev는 요청당 최대 10초다. 음성 인식·로컬 저장·처리를 제외한 후속 요청의 대기 상한은 초안을 바로 최종 검토하면 합계 50초, 다듬기가 필요하면 합계 80초다. 응답이 먼저 오면 다음 단계로 진행한다. 실제 호출 비용은 제공자·모델·길이에 따라 달라지고 사용량에 문장 처리/Jev 검토로 기록된다.

실제 합성 시험에서 빈 생성, 언어·수신자 오류, 적합 후보의 보류를 확인해 생성 지침과 오류 안내를 보강했다. 복수 금지를 명확히 쓰고 상대적 제약을 강화하지 않도록 지시하며, 일반 앱 명칭의 고유명 승격과 문장 끝 잘림 표시도 제한한다. 8차 재시험에서는 수량 입력의 실제 제공문이 명확해졌지만, 고정된 모호한 금지 후보와 일부 조건 누락·범위 확장도 JEV가 통과시켰고 적합한 로그인·한국어 후보의 보류도 남았다. 결과를 확인한 뒤 사용해야 하며 검토 통과를 원문 의미의 완전한 보존으로 보지 않는다. 시험 조건과 관측치는 [개발 보고서](reviews/2026-10-07/voice-prompt-composer.md)에 기록한다.

반복 생성 중단에서 재현한 불필요한 다듬기 호출, 출력 구문 오탐, 시간 초과 안내의 수정과 검증 범위는 [생성 중단 진단](reviews/2026-10-08/prompt-generation-failures.md)에 기록한다.

최종 검토에서 등가 요청이 보류된 관측, 검토 지침의 명확화, 보류 수치 표시 수정의 검증과 한계는 [최종 검토 보류 진단](reviews/2026-10-08/prompt-review-holds.md)에 기록한다.

## 전송과 보관

녹음은 선택한 음성 인식 경로를 따른다. 로컬 음성 인식이면 이 단계의 음성은 Mac에서 처리한다. 인식 원문과 생성 결과는 문장 제공자와 선택한 Jev 경로로 전송된다. Jev에 음성·다른 앱의 주변 문맥·개인 사전 전체를 보내지 않는다. 프롬프트 녹음은 다른 앱의 입력창 문맥이나 선택 영역을 캡처하지 않는다.

기록이 켜져 있으면 인식 원문과 최종 검토를 통과한 결과만 기존 암호화 기록에 보관한다. 중간 초안과 판정은 화면용 메모리 상태다. 기록 다시 처리도 동일한 생성·검토 전체 흐름을 거치며 보관 원본을 덮어쓰지 않는다. 처리 실패 녹음은 기존 복구 정책을 따른다. 새 작업·취소·연결/키 변경·기록 해제/삭제는 진행 중인 후속 처리와 늦은 결과 게시를 막는다. 이미 전송된 요청의 제공자 측 삭제를 의미하지는 않는다.

## 출력 예시

아래는 설명용 예시이며 실제 모델의 품질 측정 결과가 아니다.

말한 내용: “FlagQuiz에 아이가 틀렸을 때 바로 다음으로 가지 말고, 좀 기다려 주고 다시 말하게 하고 싶은데, 화면은 복잡해지면 안 돼. Codex에 부탁할 거야. 새로운 브랜치에서 해 줘.”

정리한 요청:

> Codex, FlagQuiz에서 아이가 답을 틀렸을 때 같은 문제에서 충분히 기다리고 다시 말할 수 있도록 개선해 주세요. 화면은 더 복잡해지지 않게 해 주세요. 새 브랜치에서 작업해 주세요.

실제 출력은 말한 요구와 선택한 모델에 따라 달라진다. OpenNoType이 UI 구조·음성 판정 알고리즘·코드를 미리 결정하지 않는다.

## 나열한 발화 테스트

아래 내용을 그대로 말한 뒤 원문 인식과 최종 후보를 비교할 수 있다. 설명용 합성 예시이며 자동으로 통과해야 하는 기준 답안은 아니다.

> 음, 독서 기록 앱을 좀 고치고 싶은데요. 책 제목이랑 어디까지 읽었는지 말로 남길 수 있으면 좋겠어요. 아, 날짜를 제가 안 말하면 오늘 날짜라고 추측해서 넣지는 말아 주세요. 기존 기록은 건드리지 말고요. 화면은 좀 단순했으면 좋겠고, 알림도 있으면 좋겠는데 그건 아직 넣을지 결정은 안 했어요. 그리고 제가 말하지 않은 감상이나 줄거리를 만들어 넣으면 안 돼요. 새 브랜치에서 작업해 주세요. 아까 화면 얘기하다 말았는데, 결과 문구는 과장 없이 짧고 담백하게 해 주세요.

보존할 내용은 책 제목·읽은 위치의 음성 기록, 날짜 추측 금지, 기존 기록 보존, 단순한 화면, 알림을 희망하지만 도입은 미정이라는 상태, 감상·줄거리 창작 금지, 새 브랜치, 짧고 담백한 결과 문구다. 알림 도입을 확정하거나 금지 조건을 빠뜨린 후보의 보류는 타당하다. 인식 원문이 실제 발화와 다르면 먼저 **원문 수정·다시 만들기**에서 고쳐 비교한다.
