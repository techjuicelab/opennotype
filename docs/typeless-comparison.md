## 공식 설명에서 가져오는 제품 원칙

Typeless는 불필요한 필러·반복 제거, 자기 정정의 최종 의도 반영, 목록·단계 구조화를 받아쓰기의 주요 동작으로 설명한다. 개인 사전과 표현 습관에 따른 개인화도 안내한다. [공식 한국어 제품 설명](https://www.typeless.com/ko), [Dictate 도움말](https://www.typeless.com/help/quickstart/dictate), [개인 사전 도움말](https://www.typeless.com/help/quickstart/history-and-dictionary), [개인화 도움말](https://www.typeless.com/help/quickstart/personalization).

가져올 장점은 자연스럽게 말한 내용을 바로 쓸 수 있게 정리하는 경험이다. 반복된 **말의 형태**와 반복해서 표현한 **독립적인 의미**를 구별해야 한다. 두 문장을 합치더라도 행동·대상·기한·조건이 모두 남으면 정리일 수 있고, 한 문장으로 유지해도 내용을 빠뜨리면 실패다.

공식 기능 소개만으로 한국어 무손실률이나 OpenNoType 대비 우위를 확인할 수는 없다. 공개 설정 문서에서 특정 조절 기능을 찾지 못했다는 사실도 실제 앱에 그 기능이 없다는 증거로 단정하지 않는다. 사용 후기만으로 과잉 편집의 빈도나 내부 원인을 확정하지 않는다. 사용 모델·프로토콜·스트리밍 구현도 이 조사에서 확인하지 못했다.

## 이전 코드에 이미 있던 보호와 실제 개선 여지

Claude 문서 초안은 기존 정리 기능을 단순한 삭제 규칙으로 설명하면서, 요약 금지·완곡 표현·높임 보존 장치가 없었다고 적었다. 원격 기준 `12910c1`과 작업 기준 `08dfc0b`의 `ProcessingPrompt.swift`를 다시 읽어 이 부분을 정정했다.

| 항목 | 이전 OpenNoType에서 확인한 사실 | 평가 명세와 UI에서 확인할 부분 |
| --- | --- | --- |
| 의미 보존 | 공통 지시가 인물·숫자·날짜·조건·부정·불확실성·시제·요청 강도를 보호했다. | 정정 범위와 앞절 정보 승계를 구체적인 규칙과 사례로 표현한다. |
| 요약 금지 | 프로필 블록에 의미를 요약해서 없애지 말라는 지시가 있었고, 받아쓰기 모드에도 `Do not summarize`가 있었다. | 요약 금지를 유지하면서 같은 요청의 중복을 합치는 정상적인 정리는 허용한다. |
| 자연스러운 문장 | 문법·조사·문장 구조 변경을 허용하되 모든 독립적인 의미와 화자의 태도를 남기도록 했다. | 구조 변경 허용을 무제한 재작성으로 해석하지 않도록 보존 조건을 함께 제시한다. |
| 완곡 표현 | 요청·제안·희망·확신의 정도를 유지하라는 지시와 `좀`을 남기는 예시가 이미 있었다. | `좀`, `조금`, `약간`, `그냥`이 완화나 정도를 나타내는 경우를 명시한다. |
| 높임 | `WritingTone.preserve`가 반말·존댓말을 유지하고, 다른 톤 설정만 말투 변경을 허용했다. | 군더더기 제거를 말투 변경의 이유로 삼지 않도록 연결한다. |
| 한국어 필러 | 비의미적 필러와 우발 반복 제거는 지시했지만, 동형어의 기능을 판별하는 상세 목록은 부족했다. | `그`, `이제`, `뭐`, `막`, `저기`, `어` 등을 표면형이 아니라 문장 안의 기능으로 판단한다. |
| 반복·정정 | 우발 반복·버린 재시작·명확한 자기 정정을 정리하고, 강조·미결정을 보존하도록 했다. | 뒤에 추가한 세부 정보와 앞에만 있는 유효한 정보를 함께 남기는 조건을 강화한다. |
| 원문 확인 | 이전 `HistoryView`에는 결과와 원문이 다를 때 `처음 인식한 내용`을 펼쳐 보고 선택할 수 있는 UI가 있었다. | 원문과 결과가 같아도 확인하고 각각 복사할 수 있게 했으며, 현재 설정을 고지하는 수동 재처리를 추가했다. |

확인한 코드: [`ProcessingPrompt.swift`](../Sources/OpenNoTypeCore/AI/ProcessingPrompt.swift), [`DataViews.swift`의 HistoryView](../Sources/OpenNoType/Views/DataViews.swift). 현재 기록 화면을 확인하지 않은 이전 문서의 “원문은 저장되지만 보여 주지 않는다”는 설명은 통합 기준에 적용하지 않는다. 기존 결과 복사와 원문 텍스트 선택이 있다는 사실과, 별도의 원문 복사·재처리 동선을 추가하는 작업도 구별한다.

이전에 보호 지시가 있었다는 사실이 모델의 준수를 보장하지는 않는다. 반대로 실제 실패 사례가 있다고 해서 기존 보호 규칙이 없었다고 설명해서도 안 된다. 개선 대상은 규칙의 부재 전체가 아니라 모호한 판정 기준, 예시와 실제 결과의 차이다.

## Claude 조사에서 채택한 평가 관점

Claude 브랜치의 기여는 한국어 발화 기능을 더 세밀하게 나누고, 동일한 문자열을 지우거나 남겨야 하는 대조 사례를 만든 데 있다. 아래 관점은 명세와 검토 기준에 반영했으며, 후보의 `DISFLUENCY POLICY`·`KEEP TEST` 블록을 기본 프롬프트에 추가했다는 뜻은 아니다.

- **기능에 따른 필러 판별:** `그 파일`의 지시어, `이제 시작`의 시점, `뭐 먹을까`의 의문사, `어`라는 대답은 머뭇거림과 구분한다. `KEEP TEST`는 삭제했을 때 대상·관계·응답·태도가 달라지는지 확인하는 기준이다.
- **수정 신호와 미결정 구분:** `아니`, `아닌가`, `말고` 같은 표현이 있어도 실제로 무엇을 바꾸었는지 확인한다. 대안 제시나 반박을 무조건 자기 정정으로 처리하지 않는다.
- **완화·정도 표현의 역할:** 남는 요청에 붙은 `좀`, `조금`, `약간` 등의 기능을 보호한다. 다만 `좀`을 뺀 모든 질문이 곧 명령으로 바뀐다는 설명은 과도하다. 해당 문장의 요청 강도와 정도가 달라지는지를 판단한다.
- **명세와 구현의 연결:** `dictation-quality.json`의 대조 사례와 추적 토큰 횟수를 테스트에서 읽어, 예시 자체의 누락·모순을 발견하도록 한다. 이는 명세 검사이며 실제 모델의 언어 품질 시험이 아니다.
- **지시 길이의 관리:** 프롬프트 길이를 측정해 불필요한 증가를 확인한다. 바이트 수를 청구 토큰이나 실제 비용과 동일하게 취급하지 않는다.

Claude 브랜치가 `commit_restart_reconstruction`의 기대 결과에 `조금 더`를 남기도록 고친 것은 정도 표현을 보존하는 방향과 일치한다. 이 수정과 대조 명세를 유지하되, 명세 검사가 실제 모델의 정리 성공을 입증한다고 설명하지 않는다.

## 인터뷰 후 확정한 통합 방향

| 결정 | 적용 기준 |
| --- | --- |
| 기본은 자연스러운 정리 | 필요 없는 반복·머뭇거림은 적극적으로 정리하고 문장을 자연스럽게 만든다. 사실·조건·요청 강도·유효한 세부 정보는 보존한다. |
| 정리 모델 요청은 한 번 | 기존 텍스트 처리 요청 안에서 판단한다. 이 표현은 음성 인식 요청까지 없앤다는 뜻이 아니며, 두 번째 검증 모델을 매번 호출하지 않는다는 뜻이다. |
| 기록에서 비교·복사·재처리 | 원문·결과 각각 복사와 현재 설정을 고지한 수동 재처리를 채택했다. 새 결과는 임시 미리보기로 제공하고 기존 기록은 덮어쓰지 않는다. 검증 범위는 구현 보고서에서 확인한다. |
| 기본 프롬프트는 실측 후 선택 | `ProcessingPrompt.swift`와 `DictationCleanupInstructions.swift`를 Codex `233fd1f`와 동일하게 유지한다. 후보의 추가 규칙을 채택된 기능으로 소개하지 않는다. |
| 외부 앱 글의 자동 되돌리기는 추가하지 않음 | 기록에서의 원문 복사·재처리는 다른 앱에 이미 삽입한 문장을 자동으로 수정하거나 되돌리는 기능과 구분한다. |

Typeless는 Dictate와 선택문 편집·요약·답변인 Ask anything을 별도로 설명한다. 이번 통합도 일반 받아쓰기가 질문에 답하거나 발화 속 명령을 실행하는 방향으로 범위를 넓히지 않는다. 기존 선택문 수정 모드는 명시한 편집 범위만 처리한다. [Dictate](https://www.typeless.com/help/quickstart/dictate), [Ask anything](https://www.typeless.com/help/quickstart/ask-anything).

## 평가 기준과 보류한 선택지

아래 표는 보존할 의미와 제품 범위의 기준이다. 새로운 후보 규칙을 런타임에 모두 적용했다는 목록이 아니다.

| 검토한 규칙·선택지 | 판단 기준과 이유 |
| --- | --- |
| 마지막으로 완성한 구절만 남기는 재시작 처리 | 앞절에만 있는 유효한 행동·인물·장소·조건을 최종 문장으로 승계한다. 마지막 구절을 고르는 것만으로는 충분하지 않다. |
| 별도 문장의 병합·순서 변경을 일괄 금지 | 기본값인 자연스러운 정리를 위해 중복 의미의 병합은 허용한다. 독립적인 항목·관계·행동 순서를 잃거나 바꾸는 경우를 금지한다. |
| 긴 발화는 항상 길게 남아야 함 | 반복이 많으면 정보 손실 없이도 짧아질 수 있다. 길이 대신 각 명제와 관계의 보존을 판정한다. |
| 문장 뒤 영상 마무리 인사를 STT 환각으로 보고 삭제 | **미채택.** 후처리에 전달된 텍스트만으로 실제 발화인지 무음에서 생긴 환각인지 확정할 수 없다. `시청해 주셔서 감사합니다`나 `감사합니다`가 뒤에 있다는 이유만으로 삭제하지 않는다. 말하지 않은 인사를 새로 덧붙이지 않는 규칙은 유지한다. |
| 의심스러운 출력은 길이·문장 수·전체 숫자로 차단 | 두 브랜치의 보류 방향을 유지한다. 정정된 옛 수치가 정상적으로 사라지는 경우와 반복 제거를 오판할 수 있어 채택하지 않는다. |
| 정규식·단어 목록으로 직접 삭제 | Claude 브랜치도 직접 삭제는 보류했다. 필러 목록은 모델의 판단을 돕는 사례이며, 지시어·대답·인용을 훼손할 수 있는 로컬 일괄 삭제 규칙으로 사용하지 않는다. |
| 과도한 정리보다 원문 삽입이 언제나 더 나쁨 | 일반화하지 않는다. 사용자에게 원문 확인·복사·재처리 수단을 제공하며, 새 자동 원문 복귀 규칙은 별도로 추가하지 않는다. |
| 두 번째 LLM 검증 요청을 항상 추가 | Claude 브랜치의 보류와 인터뷰의 한 번 요청 결정을 유지한다. 두 번째 요청을 하지 않는 것이 무손실을 보장한다는 뜻은 아니다. |

후행 인사 보존은 STT 환각이 없다는 주장이 아니다. 현재 후처리 입력만으로 확인할 수 없는 원인을 단정하여 유효한 말을 삭제하지 않겠다는 범위 결정이다. 후속 음성 단계 개선을 검토한다면 실제 오디오와 전사 결과의 대응 증거가 필요하다.

## 평가와 비용 해석

`dictation-quality.json`의 한국어 대조 사례와 `faithful-cleanup.json`의 의미 보존 사례는 상호 보완한다. 추적 토큰의 기대 횟수를 검사해도 해당 토큰을 실제 모델이 올바르게 지웠다는 뜻은 아니다. 토큰 수만 맞고 조건·인물·시간 관계를 틀릴 수도 있으므로 의미 판정은 별도로 남긴다.

비교할 때는 원문·출력·모델·프롬프트 버전·모드·문체 설정을 고정하거나 기록하고, 다음 항목을 분리한다.

1. 의미 손실·추가: 행동, 대상, 수량, 시각, 부정, 조건, 불확실성, 리터럴과 언어.
2. 정리 품질: 불필요한 반복·필러·폐기된 정정값의 잔존 여부.
3. 전송·형식 문제: HTTP 오류, 잘못된 응답 형식과 의도된 빈 결과.
4. 사용량·성능: 입력·출력 토큰, 참고 비용, 지연. 모델·실행 조건과 함께 해석한다.

후보 프롬프트의 바이트 수와 상한을 최종 채택 프롬프트의 측정값으로 재사용하지 않는다. 기본 소스는 Codex 버전으로 복원했으며 최종 측정값은 구현 보고서를 따른다. 실제 청구는 토큰·모델 요율·공급자가 적용한 조건에 따라 달라진다. 요청 수를 유지해도 비용이나 지연이 같다는 보장은 없다.

통합 전 작업의 공식 자료 조사와 구현 근거는 [2026-09-12 비교 문서](reviews/2026-09-12/typeless-comparison.md)와 [구현 보고서](reviews/2026-09-12/faithful-cleanup-implementation.md)에 남아 있다. [실제 모델 비교 기록](reviews/2026-09-12/faithful-cleanup-live-comparison.md)은 실행 버전별 결과를 기록한다. 최종 채택 요청, 미채택 후보 소스와 정확한 요청 export는 [실험 증거](reviews/2026-09-12/integration-evidence/)에 따로 보존한다.

최종 테스트·앱 검증 결과와 채택 범위는 [구현·검증 보고서](reviews/2026-09-12/typeless-integration.md)를 따른다. 이번 작업은 Typeless 동등 품질이나 무손실을 달성했다는 선언이 아니다.
