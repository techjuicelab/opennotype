# OpenNoType UI/UX 시각·문구 가이드

- 작성일: 2026-10-15
- 목적: 기능 개선 작업과 충돌하지 않게, 현재 기능을 더 쉽게 이해하는 화면 구조·표현 규칙을 정한다.
- 범위: 디자인 방향, 타입·간격·색상, 명명, 상태 문구, 키보드·VoiceOver 계약.
- 상태: 소스 기반 제안. 앱 실행, 화면 렌더링, 색상 대비 실측, 사용성 테스트를 수행하지 않았다.
- 소스 기준: 문서 작성 당시 체크아웃. 다른 에이전트가 수정 중이므로 행 번호·상태 계약은 구현 직전에 다시 확인한다.
- 작업 경계: 이 문서는 앱 동작을 변경하거나 신규 기능을 추가하는 구현 승인이 아니다.

## 1. 방향

**말하기 바로 전의 한 동작만 크게 보이는 Mac 유틸리티.**

사용자는 기능 목록을 배우기보다 지금 어느 입력 방식을 쓰는지, 어떤 단축키를 누르면 되는지, 결과가 입력되었는지를 먼저 알아야 한다. 기존 녹색 강조와 시스템 서체를 유지하고, 장식보다 정보 순서·문구·여백을 정돈한다.

차별점은 **홈에서 크게 보이는 단축키 한 줄**이다. 단축키 캡슐의 모양과 표현을 홈·설정·도움말에서 일관되게 쓴다. 웨이브·그라데이션·큰 통계 숫자를 별도의 장식으로 추가하지 않는다.

이번 시안의 내비게이션은 다음 네 항목으로 고정한다.

| 내비게이션 | 첫 목적 | 기존 기능 연결 원칙 |
|---|---|---|
| 받아쓰기 | 현재 방식·단축키·최근 결과 확인 | 기존 홈 기능을 재배치한다. 홈에 없던 자동 입력 시작 행동을 조용히 추가하지 않는다. |
| 기록 | 이전 결과 찾기·복사·다시 처리 | 기존 기록 기능과 보관 계약을 유지한다. |
| 개인 사전 | 자주 쓰는 이름과 표기 관리 | 기존 자동 학습·교정 검토의 차이를 유지한다. |
| 설정 | 입력 방식·모델·권한·보관 관리 | 음성 모델·모델 비교·사용량·녹음 복구의 진입점을 잃지 않게 재배치한다. |

네 항목으로 줄이는 것은 기존 화면을 삭제하는 뜻이 아니다. 복구가 필요한 상태에서는 받아쓰기 화면에 복구 진입점을 보여 주고, 평소에는 설정의 관련 도구에서 찾게 한다. 정확한 이동 경로는 전체 정보구조 문서와 맞춘다.

### 정상 상태의 받아쓰기 화면

1. 현재 입력 방식의 짧은 요약과 준비 상태.
2. 가장 눈에 띄는 단축키 한 줄과 눌렀을 때의 동작.
3. 최근 결과가 있으면 결과와 복사 행동.
4. 번역·선택 문장 수정·프롬프트 만들기는 보조 작업으로 묶는다.
5. 모델 ID·전송 정책·검토 세부·진단은 관련 설정 또는 펼치기에서 확인한다.

### 결과 확인이 필요한 상태

보류된 결과는 정상 상태의 안내보다 먼저 표시한다. 제목, 보류 이유, 결과·원문, 가능한 다음 행동 순으로 읽힌다. 녹색 준비 표시를 결과 보류보다 강하게 보여 주지 않는다. 자동 입력 여부는 실제 상태가 확인한 사실만 표시한다.

## 3. 타입·간격·컴포넌트

### 서체와 크기

| 역할 | 규칙 |
|---|---|
| 기본 서체 | SwiftUI `.system`, macOS의 SF Pro |
| 페이지 제목 | 24pt semibold |
| 섹션 제목 | 14pt semibold |
| 본문·설정 라벨·주요 상태 | 13pt regular 또는 medium |
| 설명·날짜·부가 정보 | 12pt regular |
| 키 조합·모델 ID | SF Mono, 기본 12pt |
| 시간·사용량·측정치 | `monospacedDigit()`로 자리 이동을 줄인다. |

10pt 설명은 제거한다. 화면마다 23·25·30pt 제목을 따로 쓰지 않는다. 한국어 제목의 음수 자간은 일괄 적용하지 않고 실제 렌더링에서 읽기 편한지 확인한다. 큰 타입이 길어진다고 문구를 잘라 의미를 없애지 않는다.

### 간격과 레이아웃

- 간격 단계: 4, 8, 12, 16, 24, 32pt.
- 화면 좌우 여백: 28~32pt. 서로 다른 화면에서 시작선을 맞춘다.
- 섹션 사이: 24pt. 라벨과 설명: 4~8pt. 행 내부: 8~12pt.
- 콘텐츠 폭: 약 720~800pt를 디자인 기준으로 검토하되, 긴 모델명과 한국어 문장이 잘리지 않게 한다.
- 설정은 `라벨 + 현재값 또는 컨트롤 + 필요한 한 줄 설명`의 행을 기본으로 한다.
- 배경 카드 안에 다시 배경 카드를 넣지 않는다. 일반 설정은 구분선과 여백으로 나눈다.
- `Surface`는 결과·주의·설치 후 준비처럼 묶음 경계가 필요한 곳에 제한한다.
- 화면당 강한 강조 버튼은 한 개를 기준으로 한다. 삭제는 보조 위치와 파괴적 역할을 유지한다.
- 상태 배지의 색은 현재 페이지 선택·주요 실행 버튼의 강조와 구별한다.
- 기본 동작은 macOS 컨트롤을 우선한다. 라벨·입력창·버튼의 세로 정렬을 일관되게 맞춘다.

### 색상

앱 구현은 `windowBackgroundColor`, `controlBackgroundColor`, `primary`, `secondary` 등 시스템 의미색을 우선한다. 기존 [AppTheme](../../../Sources/OpenNoType/Views/MainView.swift#L5-L14)의 녹색 계열을 이어가며 라이트·다크에 맞춰 검증한다.

HTML 시안의 참조값은 다음과 같다. **실측한 대비 통과 값이 아니다.**

| 역할 | 라이트 시안 참조값 | 사용 |
|---|---|---|
| 창 배경 | `#F3F4F4` | 넓은 바탕 |
| 콘텐츠 배경 | `#FFFFFF` | 필요한 결과·주의 Surface |
| 주요 글자 | `#202625` | 본문·제목 |
| 보조 글자 | `#59635F` | 설명·메타데이터 |
| 강조 | `#406954` | 현재 선택·주요 동작·단축키 표식 |
| 경고 | `#8B5A22` | 주의가 필요한 상태 |

오류는 시스템 의미색을 우선한다. 경고·오류·정상 여부를 색만으로 표현하지 않고 아이콘과 명시적인 상태 제목을 함께 둔다. 라이트·다크, 비활성화, 선택, 키보드 포커스 상태를 각각 확인해야 한다.

## 4. 명명과 설명

사용자는 결과와 제어 대상을 알아야 한다. `로컬`, `Jev`, 모델 이름은 필요한 위치에 남기되 핵심 행동의 이름을 기술 구조로 대체하지 않는다. 화면 라벨 변경과 저장된 설정 식별자 변경을 분리한다.

| 대상 | 권장 문구 | 주의 |
|---|---|---|
| 기본 입력 방식 | `바로 입력` | 설명: `이 Mac에서 인식한 문장을 AI 정리 없이 입력합니다.` |
| AI 문장 처리 방식 | `정리해서 입력` | 설명: `말실수와 추임새를 정리해 입력합니다.` |
| 음성 처리 위치 | `이 Mac에서 처리` | 현재 유효 경로에만 표시한다. |
| 외부 전송 요약 | `음성·문장을 [제공자]로 전송` | 음성과 문장 제공자가 다르면 따로 표시한다. |
| 음성 모델 관리 | `음성 인식` | 기존 기능을 찾을 수 있게 모델 이름은 현재값에 표시한다. |
| 음성 비교 | `음성 모델 비교` | 문장 모델 비교와 구분한다. |
| 텍스트 비교 | `문장 모델 비교` | 실제 API 사용·비용 고지를 유지한다. |
| 검토 기능 | `문장 검토 (Jev)` | 공급자·검토 방식은 상세 설정에 표시한다. |
| 실패 녹음 화면 | `녹음 복구` | 일반 결과 다시 처리와 구분한다. |
| 보조 모드 | `번역`, `선택 문장 수정`, `프롬프트 만들기` | 화면·단축키·기록에서 같은 이름을 쓴다. |
| 녹음 동작 | `한 번 눌러 시작·종료`, `누르는 동안 녹음`, `짧게 누르거나 길게 누르기` | 선택값별 설명을 제공한다. |
| 실험 상태 | `실험 기능` | `실험`, `실험 단계`, `실험 기능` 혼용을 줄인다. |

**바로 입력의 원문은 ASR이 인식한 문장이다.** 원음 자체나 발화를 완벽하게 보존한 글이라는 뜻이 아니다. `원음 그대로`, `말한 그대로 정확하게`, `정확한 원문`처럼 정확도를 보장하는 표현을 쓰지 않는다.

`바로 입력`을 선택했더라도 번역 출력이면 실제로 AI 처리를 사용한다. 저장된 선택값만 보여 주지 말고 `번역 · AI 처리 사용 중`처럼 현재 유효 경로를 함께 보여 준다. [현재 예외 처리 안내](../../../Sources/OpenNoType/Views/VoiceInputOptionsView.swift#L8-L15)

`모델 준비됨`을 누를 수 없는 버튼처럼 표현하기보다 상태로 읽히게 한다. 다운로드·메모리 준비·현재 사용 중은 서로 다른 상태다. 그 차이는 현재 모델 관리 경로를 기준으로 유지한다. [모델 관리](../../../Sources/OpenNoType/Views/VoiceInputOptionsView.swift#L57-L84)

## 5. 옵션 옆 도움말

사용자의 추가 방향에 따라, 설정의 긴 설명 문단은 **옵션명 옆 `?` 버튼을 눌러 보는 도움말**로 옮긴다. 기본 화면은 `라벨 + 현재값 또는 컨트롤 + 실제 적용 상태`를 읽는 데 집중한다.

도움말로 옮기는 것은 정보를 없애는 일이 아니다. 추가 비용·전송, 실험 여부, 적용되지 않는 상태, 자동 입력 보류처럼 선택에 영향을 주는 조건은 기본 화면에도 짧은 표식으로 남긴다.

### 도움말 버튼과 팝오버 규칙

| 항목 | 규칙 |
|---|---|
| 버튼 위치 | 설명할 옵션명 바로 옆. 현재값·토글·슬라이더와 구별되는 독립 버튼. |
| 버튼 영역 | HTML 시안은 28~32px 정사각형, 네이티브 구현은 28~32pt를 기준으로 검토. `?`는 13~14pt로 가운데 배치. 작은 글자 크기와 클릭 영역 크기를 혼동하지 않음. |
| 키보드 표시 | 실제 버튼으로 만들고 `Tab`으로 도달. 명확한 포커스 테두리를 유지하며 `Enter` 또는 `Space`로 열림. |
| 접근성 이름 | HTML `aria-label="받아쓰기 출력 언어 도움말"`, 네이티브 `.accessibilityLabel("받아쓰기 출력 언어 도움말")`처럼 옵션명과 목적을 포함. `도움말`만 반복하지 않음. |
| 열린 상태 | HTML은 `aria-expanded`·`aria-controls`로 연결. 네이티브에서도 현재 열린 상태와 팝오버 내용이 접근성 트리에서 파악되는지 실제 확인. |
| 팝오버 크기 | 목표 폭 320~360px 또는 pt. 화면 가장자리에서 12~16 여백을 남기며 가용 폭 안으로 제한. 기준 버튼에서 멀리 떨어진 중앙 모달로 만들지 않음. |
| 글자 | 제목 14pt semibold, 본문 13pt, 줄 높이 약 1.6. 긴 문단을 작게 축소하지 않음. |
| 내용 순서 | 무엇을 하는지 → 어디에 적용되는지 → 추가 전송·비용 → 실패·보류 조건. 관련 없는 항목은 생략하고 새로운 보장이나 실패 정책을 만들지 않음. |
| 동시 열기 | 한 번에 도움말 하나. 다른 `?`를 누르면 기존 도움말을 닫고 새 항목을 표시. |
| 닫기 | 같은 버튼 다시 누르기·바깥 클릭·명시적인 닫기 버튼·`Escape` 지원. 키보드로 닫으면 호출한 `?`로 포커스 복귀. |
| 포커스 이동 | 도움말 안의 닫기·링크에 도달 가능. 기존 설정 컨트롤을 뜻하지 않게 변경하거나 녹음을 시작하지 않음. |
| Hover | Hover는 짧은 보조 안내로만 사용. 본문은 클릭·키보드·VoiceOver로 열 수 있어야 하며 Hover만으로 정보를 제공하지 않음. |
| 비활성 옵션 | 컨트롤이 비활성화되어도 그 이유를 읽는 도움말은 사용할 수 있도록 검토. 비활성 Surface 전체가 도움말까지 차단하지 않게 함. |

시안에서는 버튼으로 열리는 도움말이 실제 상호작용임을 보이되, 도움말을 여는 것만으로 설정 저장·API 호출·다운로드가 실행되지 않는다.

아래 문구는 현재 소스에서 확인한 의미를 짧게 나눈 초안이다. 기능 담당자가 계약을 변경했다면 문구부터 최신 계약과 맞춘다.

| 옵션·접근성 이름 | 기본 화면 | `?`에서 읽는 문구 |
|---|---|---|
| **받아쓰기 출력 언어** / `받아쓰기 출력 언어 도움말` | `말한 언어 유지` + `언어 선택·예시 보기…`. 변경 적용 시 `다음 녹음부터`. | `평소 받아쓰기 단축키로 입력할 언어를 정합니다. ‘말한 언어 유지’는 인식한 언어를 유지하며, 다른 언어를 선택하면 AI로 번역합니다. 예시를 보는 것만으로 설정은 바뀌지 않습니다. 번역 결과는 모델에 따라 달라질 수 있습니다.` |
| **번역 문장 다듬기** / `번역 문장 다듬기 도움말` | 토글 + `실험 · 추가 요청 1회`. 켰을 때 `실패 시 입력 보류`. | `받아쓰기 번역과 번역 단축키의 초안을 한 번 더 다듬습니다. 원문·초안·목표 언어·말투·사전 힌트를 현재 문장 서비스로 추가 전송하며 시간과 API 비용이 늘 수 있습니다. 다듬기를 끝내지 못하면 초안을 대신 입력하지 않고 보류합니다. Jev 검토와 별개이며 의미 보존을 보장하지 않습니다.` |

| **AI 편집 강도** / `AI 편집 강도 도움말` | 슬라이더 + `현재 그대로 · 0`. 기본 표현에서 비활성화되면 이유 표시. | `선택한 표현 방향으로 AI가 편집하는 정도입니다. 0이거나 ‘현재 받아쓰기’이면 기존 문장 정리 방식을 유지하며, AI 정리가 꺼지는 뜻은 아닙니다. 말한 언어 유지 받아쓰기에만 적용하고 번역 출력·선택 문장 수정에는 적용하지 않습니다. 숫자·이름·조건·부정·의도를 보존하도록 요청하지만 결과 확인이 필요합니다.` |

### Jev 모드별 실패의 의미

화면 이름을 단순하게 만들더라도 아래 차이는 반드시 유지한다. 특히 `입력 전 보호`라는 이름만 보고 모든 검토 실패가 자동 입력 보류라고 설명하면 현재 구현과 어긋난다.

| 상황 | 현재 코드에서 확인한 동작 | 맞는 설명 |
|---|---|---|
| 말한 언어 유지 받아쓰기 `.protect`, 검토 오류·확인 불가능한 응답 | `reviewDecision`은 보류를 뜻하는 값을 반환하지 않는다. 다른 보류·취소 사유가 없다면 기존 문장 결과의 입력 경로가 이어질 수 있다. | `검토를 완료하지 못했습니다. 기존 결과를 유지합니다.` 입력 상태는 별도로 표시한다. |
| 말한 언어 유지 받아쓰기 `.protect`, 강한 의미 위험 신호 | 자동 입력을 보류한다. | `의미가 달라졌을 가능성이 있어 자동 입력을 보류했습니다.` |

| 번역 입력 전 검토를 켠 `.protect`, 검토 불가·실패 | 번역은 별도 경로에서 자동 입력을 보류한다. | `번역 검토를 완료하지 못해 자동 입력을 보류했습니다.` |

## 7. 키보드·VoiceOver·상태 표시 계약

- macOS 기본 키보드 포커스 표시를 제거하지 않는다. 마우스 선택과 키보드 포커스를 강제로 동일하게 만들지 않는다.
- 내비게이션 행은 아이콘·글자·오른쪽 여백 모두 같은 이동 행동을 가져야 한다. 실제 `Tab → Space`로 선택·실행을 검증한다.
- 단축키 캡슐은 안내이면 텍스트, 변경 행동이면 버튼으로 만든다. 안내를 가짜 버튼처럼 보이게 하지 않는다.
- 아이콘 전용 취소·삭제·복사에는 작업 대상이 포함된 접근성 이름을 제공한다. 기존 `accessibilityLabel`·`accessibilityValue`를 보존한다.
- 파형은 장식·수준 표시로 접근성 트리에서 숨긴다. 현재 단계의 전이는 한 번씩 알리고, 시간·레벨이 매번 갱신될 때마다 읽지 않는다.
- 비차단 경고가 표시되어도 녹음·인식·입력의 주 단계는 사라지지 않는다.
- `VoiceBar`는 비활성 패널을 유지한다. 화면 재정비 때문에 전면 앱의 포커스를 가져오면 외부 입력 경로에 영향을 준다.
- Reduce Motion을 존중한다. 기존 파형의 접근성 처리를 유지하고 장식용 등장·반복 애니메이션을 추가하지 않는다.
- 비활성 설정에는 가능한 경우 바로 옆에 이유를 표시한다. 선택되어 있지만 현재 적용되지 않는 옵션도 명시한다.
- 실험 여부·추가 전송·비용·입력 보류 조건은 해당 컨트롤 옆 짧은 표식과 옵션명 옆 도움말로 제공한다.
- 새 화면·모달을 닫으면 호출한 컨트롤로 키보드 포커스가 돌아가도록 검증한다.
- 긴 한국어, 영어 UI, 긴 모델 ID, 시스템 대비 증가·다크 모드에서 잘림·구분 가능성을 확인한다.

## 8. 클릭 시안과 구현의 경계

클릭 시안은 화면 구조와 문구를 검토하는 자료다. 앱 소스·설정·Keychain·음성·파일·외부 API·클립보드·외부 앱 입력을 조작하지 않는다.

- 모달은 시안임을 명시한다. 연결 확인·다운로드·저장 버튼이 성공한 것처럼 응답하지 않는다.
- 상태 예시는 사용자가 명시적으로 선택하는 시나리오로 보여 준다. 실제 녹음·통신이 진행되는 것처럼 연출하지 않는다.
- 기존 모델·제공자 이름은 실제 샘플 데이터로 사용할 수 있지만 현재 사용자의 저장 상태라고 주장하지 않는다.
- 외부 링크가 있는 경우 시안 검토에 필요한 문서 링크인지 분명히 한다.
- 상태 보류·결과 복사처럼 실제 행동과 연결되는 컨트롤은 시안에서 어떤 범위까지만 작동하는지 표시한다.
- 시안에서 새 내비게이션으로 이동하는 것은 앱의 라우팅이 바뀌었다는 증거가 아니다.

## 9. 병행 개발 시 적용 순서

1. 이 가이드와 화면 시안에서 명칭·위계·상태 의미를 먼저 맞춘다.
2. 기능 담당자가 수정 중인 `AppModel`, 오디오·추론·입력 상태 계약을 확인한다.
3. 공통 타입·간격·색상과 화면 조립을 작은 범위로 적용한다. 동작 변경은 함께 섞지 않는다.
4. 토큰 변경과 문구 변경 후, 단축키·결과 보류·복구·기록 비활성 상태를 우선 검증한다.
5. 실제 실행 앱에서 키보드·VoiceOver·외부 입력·라이트·다크를 확인한 뒤 완료를 판단한다.

현 단계에서 보장할 수 있는 것은 소스 기반 디자인 제안과 시안의 일관성이다. 인식 정확도·입력 성공률·성능 개선은 UI 시안으로 입증할 수 없다.
