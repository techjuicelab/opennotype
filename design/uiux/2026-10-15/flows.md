# OpenNoType 핵심 작업 흐름 설계

작성일: 2026-10-15. 담당: 4개 에이전트 병렬 설계팀의 핵심 흐름 담당.

이 문서는 현재 기능을 유지하며 홈·기록·복구·프롬프트의 배치와 이름을 정리하는 설계안이다. 앱 구현 변경을 승인하거나 완료했다고 의미하지 않는다. 앱 소스·설정·테스트·커밋·설치·앱 실행은 수행하지 않았다.

## 검토 기준과 현재 증거

- 코드 관찰 기준: 2026-10-15 06:47 KST 전후의 현재 작업 디렉터리. HEAD는 `f223adc544dc9e69dbb91e10627782538054d29b`이나 미커밋 변경을 포함해 읽었다.
- 다른 에이전트의 기능 개발이 병행 중이다. 실제로 관찰 중 `AppModel.swift`의 행 번호가 이동했다. 구현 전에 아래 함수·분기와 최신 행 번호를 다시 확인해야 한다.
- 실행 중 화면을 관찰하지 않았다. 카드의 구조·강조 방식·배치 순서·클릭 연결을 소스에서 확인한 결과이며, 실제 화면의 스크롤 위치·대비·시각적 밀도는 이후 미리보기에서 확인해야 한다.
- `frontend-design`와 `design:design-critique`를 참고했다. macOS 시스템 배경·기본 서체·기존 녹색 강조를 기반으로, 단축키와 확인할 결과를 선명하게 구분한다.

## 설계의 중심

사용자가 반복하는 일은 **입력할 앱에서 말하기 → 입력 또는 보류 여부 확인 → 필요하면 결과 복사·원문 확인**이다.

최상위 내비게이션은 `홈 / 기록 / 개인 사전 / 설정` 4개로 정리한다. 번역·선택 문장 수정·프롬프트 만들기는 홈의 보조 작업이며, 실패 녹음 복구는 기록 안에서 이어가는 작업이다. 저장 구조와 데이터의 수명을 합친다는 의미는 아니다.

일반 받아쓰기의 홈 녹음 버튼은 추가하지 않는다. 현재 `toggle()`은 OpenNoType 자체가 전면인 상태의 일반 녹음을 막고 외부 앱의 입력창을 클릭하라고 안내한다. 이 대상 보호를 유지한 채, 홈에는 실제 단축키와 외부 앱에서 시작하는 방법을 보여준다. 근거: [AppModel.swift](../../../Sources/OpenNoType/App/AppModel.swift), `toggle()`, 982–990행.

## 홈의 우선순위

### 일반적인 준비 완료 상태

1. 실제 받아쓰기 단축키와 외부 앱에서 시작하는 안내.
2. 최근 결과와 복사. 결과가 없으면 빈 결과 카드를 두지 않는다.
3. 번역·선택 문장 수정·프롬프트 만들기를 보조 작업 한 줄로 표시.
4. 보관된 실패 녹음이 있을 때만 건수와 확인 진입점.
5. 현재 처리 설정의 짧은 요약과 변경 위치로 이동하는 링크.

### 입력 보류·미전달 상태

1. 해당 결과와 “입력하지 않았어요”, 그 이유, 기존 복사 동작.
2. 원문 비교·검토·재처리는 해당 결과의 상세에 둔다.
3. 새로 말하는 방법과 다른 작업은 그 아래에 둔다.

### 첫 사용·준비 미완료 상태

기존 연결·권한·모델 준비·입력 연습 중 미완료 항목과 다음 행동 하나를 먼저 보여준다. API 키 저장과 실제 연결 확인을 같은 의미로 표시하지 않는다. 준비 상세는 계속 열어 볼 수 있게 한다.

```text

│                                              │
```

## 작업별 흐름

### 첫 사용과 일반 받아쓰기

`홈의 미완료 준비 확인 → 기존 연결/권한/모델 준비 → 기존 입력 연습 → 입력할 외부 앱 클릭 → 실제 단축키 → 준비 중 → 듣는 중 → 처리 중 → 기존 입력 결과에 맞는 안내`

- 홈에서 키만 저장됐으면 실제 서비스 연결이 확인됐다고 표시하지 않는다.
- 입력 연습이 음성·API 호출 없이 시험 문구만 넣는다는 현재 의미를 유지한다.
- 단축키가 hold/toggle/혼합 중 어느 방식인지 설정값에 맞춰 안내한다. 정적인 “다시 눌러 종료”로 통일하지 않는다.
- 정상 입력 시 사용 중인 앱의 포커스를 유지한다. 성공 때마다 홈 창을 여는 흐름으로 바꾸지 않는다.
- 보류·미전달 때문에 홈을 열 때는 해당 결과가 먼저 보이게 한다.

근거: [MainView.swift](../../../Sources/OpenNoType/Views/MainView.swift), `inputReadiness`·`shortcutInstructions`, 249–332행. [AppModel.swift](../../../Sources/OpenNoType/App/AppModel.swift), `toggle()`, 955–1093행; `process()` 전달 결과 분기, 1747–1773행.

### 기록

`기록 목록 → 기존 검색 → 항목 선택 → 보관된 결과 확인·복사 → 필요하면 인식 원문 비교 / 기존 검토 / 원문 다시 처리`

목록은 시간·작업 이름·결과 일부를 중심으로 스캔하게 한다. 선택한 항목 상세에서 현재 제공하는 모든 행동을 유지한다. `전체 삭제`는 일반 탐색·복사와 동등하게 강조하지 않는다.

다시 처리한 결과는 기존 기록을 바꾸지 않는 미리보기다. 상세 화면에서 기존 결과와 새 결과를 혼동하지 않게 구분하고, 미리보기가 따로 저장되지 않는 현재 안내를 유지한다. 당시 번역 언어를 확인할 수 없어 직접 검토할 수 없는 경우도 숨기지 않는다.

근거: [DataViews.swift](../../../Sources/OpenNoType/Views/DataViews.swift), `HistoryView.matches`·`HistoryView.body`, 12–40행; `HistoryEntryCard.body`, 77–175행.

### 실패 녹음 복구

`홈의 보관 녹음 안내 또는 기록 안의 복구 진입 → 실패 녹음 목록 → 당시 설정으로 다시 처리 → 결과 확인·복사`

보조 경로는 `설정 바꿔 다시 처리… → 기존 현재 설정 확인 → 재처리 → 결과 확인·복사`다.

- 상위 내비게이션에서는 기록에 접근 경로를 모으되 `HistoryEntry`와 `FailedRecording` 저장 의미를 합치지 않는다.
- 일반 기록과 다른 “최대 24시간 / 성공하거나 만료되면 삭제” 규칙은 복구 화면에서 유지한다.
- “당시 설정”은 음성·문장 모델, 언어·말투를 뜻하며, 번역 다듬기·Jev·사전은 현재 설정이라는 기존 예외를 정확히 설명한다. 이름만 바꾸고 완전한 과거 설정 재현을 약속하지 않는다.
- 음성 수정 복구에는 원문을 저장하지 않으므로 사용자가 원문을 다시 제공하는 기존 동작을 유지한다.
- 복구는 자동 재입력으로 바꾸지 않는다. 결과를 확인하고 복사하는 현재 계약을 지킨다.
- 녹음 저장에 실패한 경우에는 “보관된 녹음 확인”을 성공한 것처럼 안내하지 않는다.

근거: [DataViews.swift](../../../Sources/OpenNoType/Views/DataViews.swift), `RecoveryView.body`, 421–460행; `recoveryCard()`, 471–520행. [AppModel.swift](../../../Sources/OpenNoType/App/AppModel.swift), `recordingFailed()`, 1257–1298행.

### 프롬프트 만들기

홈의 보조 작업에서 기존 프롬프트 구역을 연다. 일반 받아쓰기와의 차이는 `복사용 프롬프트 녹음`이라는 실제 행동 이름으로 먼저 설명하고, 비용·단계·제한은 관련 상세에 유지한다.

```text
홈에서 복사용 녹음
  → 인식 → 초안 생성 → 초안 검토 → 필요 시 다듬기 → 최종 검토
  → 복사 가능한 결과: 프롬프트 복사
  → 차단/오류/취소: 해당 단계와 남은 원문·후보를 확인

외부 앱에서 프롬프트 단축키
  → 동일한 생성/검토 → 기존 전달 판정에 따라 원래 입력창에 입력
  → 미전달: 결과 확인·복사

원문 수정·다시 만들기
  → 현재 원문 편집 → 기존 재생성 → 복사용 미리보기
```

- 홈 녹음과 원문 재생성은 AI에 자동 제출하거나 외부 앱에 자동 입력하는 동작으로 바꾸지 않는다.
- 내용 검토의 참고 사항과 기존 지침 관련 차단·오류를 합치지 않는다. 참고 사항이 있어도 전달 가능한 현재 판정을 유지한다.
- `canCopyOutput`이 false인 차단 결과에 일반 완료 결과의 복사 버튼을 붙이지 않는다.
- 중간 초안·최종 검토 후보를 검토 통과한 결과처럼 부르지 않는다.
- 원문 편집·재생성이 기존 보관 기록이나 실패 원음을 덮어쓰지 않는 현재 의미를 유지한다.
- 프롬프트의 임시 결과가 다음 처리나 앱 종료 시 사라지는 규칙을 숨기지 않는다.

`AppModel.Phase`는 `idle / starting / recording / enrolling / processing`이다. 시작 준비는 별도 `StartupState = loading / ready / failed`이며, 처리 단계는 `audioPreparation / transcription / textProcessing / translationRefinement / decisionReview / insertion / storage`다.

| 준비 필요 | 저장소/키/권한/모델 등의 미완료 조건 | 구체적인 첫 미완료 항목 | 해당 기존 해결 버튼, 상세 점검 열기 |
| 시작 준비 | `phase == .starting` | “마이크 준비 중” | 취소, 듣는 중과 시각적으로 구분 |
| 듣는 중 | `phase == .recording` | “듣고 있어요”; 번역은 실제 출력 언어 반영 | 시간·자동종료·종료·취소 유지 |
| 목소리 등록 | `phase == .enrolling` | 현재 목소리 등록 안내 | 일반 받아쓰기와 구분, 기존 녹음 제한 유지 |
| 처리 중 | `phase == .processing` + 실제 Stage | “음성 인식 중 / 문장 정리 중 / 입력 확인 중” | 실제 진행만 표시, 취소 보존 |
| 입력 보류 | 기존 검토/다듬기/재인식 보류 판정 | “입력하지 않았어요” + 구체 이유 | 홈 최상단 결과, 허용된 복사·원문 비교·검토 |
| 입력 확인 필요 | 실제 `InsertionOutcome`이 제출 후 미확인 등 | 기존 `InsertionFeedback`의 의미 유지 | 확인 필요 안내와 결과 복사, 성공 단정 금지 |
| 복사용 완료 | 기존 target nil 결과 | “결과가 준비됐어요” | 결과 복사, 자동입력으로 바꾸지 않음 |
| 실패·원음 보관됨 | 실제 실패 원음 저장 성공 | “처리하지 못했어요. 녹음은 보관했어요” | 기존 실패 녹음 확인 |
| 실패·원음 미보관 | 실제 원음 저장 실패 | 저장 실패를 명확히 안내 | 가능한 기존 해결 안내, 복구 가능하다고 단정 금지 |
| 프롬프트 차단 | `deliveryDisposition == .blocked` 또는 held | 실제 중단/검토 보류 단계 | 통과 결과의 복사 동작 금지, 원문·후보 확인 유지 |

`idle`을 항상 “준비됨”으로 해석하면 안 된다. 앱의 시작 실패·설정 복구·연결 문제·결과 보류는 phase와 별개의 근거를 가진다. 표시 우선순위는 기존 기능 담당자와 계약을 맞추며, UI 작업에서 `generation`·검토 epoch·취소·대상 추적을 변경하지 않는다.

VoiceBar는 기존 비활성 패널을 유지한다. 경고가 와도 주 상태·종료 제어가 사라지지 않게 하고, 미리보기는 확정 결과가 아니라는 접근성 설명과 의미를 유지한다. 근거: [VoiceBar.swift](../../../Sources/OpenNoType/Views/VoiceBar.swift), 패널, 9–23행; 취소·상태·종료·미리보기, 39–78행.

## 기능 개발과 충돌하지 않는 적용 순서

1. 최신 소스에서 각 기능의 실제 연결과 미커밋 변경 소유자를 다시 확인한다. `AppModel`·`Preferences`·녹음·입력·AI 처리 코드는 기능 담당자가 계속 소유한다.
2. 기능 담당자와 각 결과의 표시 계약을 먼저 합의한다. 문자열·phase만으로 held/failed를 추측하지 않고, 이미 있는 결과·판정 값을 사용한다.
3. 홈의 순서·라벨·접기·상세 이동부터 별도 UI 범위에서 적용한다. 먼저 기존 동작을 그대로 연결한 레이아웃을 확인한다.
4. 기록·복구·프롬프트의 기존 동작을 새 배치에서 하나씩 확인한다. 준비됨·녹음 중·처리 중·보류·미전달·실패 원음 저장 실패까지 상태별 미리보기를 검토한다.
5. 실제 앱의 핵심 외부 입력을 확인한 뒤 통합한다. 정적 시안만으로 포커스·음성·실입력 성공을 입증했다고 보고하지 않는다.

이 문서는 UI/UX 설계와 인계 범위다. 녹음 알고리즘·추론·후처리·입력 안전장치·저장 정책의 변경은 포함하지 않는다.

## 옵션별 도움말과 오류 표시

설정의 받아쓰기 화면은 간결한 그룹별 행으로 구성한다. 각 행은 `옵션 이름 [?] — 현재 값/조절`을 기본으로 하고, 긴 설명·예시·선택 기준은 이름 옆 `?` 버튼을 누르면 popover로 연다. 버튼의 접근성 이름은 “{옵션 이름} 도움말”로 지정하고 키보드로 진입할 수 있게 한다.

도움말은 제목과 설명, 닫기 버튼을 제공한다. 같은 `?`를 다시 누르거나 닫기 버튼·Escape·popover 밖 클릭으로 닫을 수 있고, 다른 옵션의 `?`를 누르면 해당 도움말로 바뀐다. `?`로 열었을 때 포커스를 도움말 안으로 옮기고, 닫기 버튼·Escape로 닫으면 원래 `?`로 돌려준다. 바깥 컨트롤을 클릭해 닫은 경우는 그 컨트롤의 포커스를 존중한다. 열기·읽기·닫기는 설정 변경이나 연결 시험으로 취급하지 않는다.

일반적인 기능 설명만 도움말에 둔다. 현재 키 미저장·권한 거부·모델 준비 실패·진행 중 작업 오류는 해당 행 또는 작업 결과에 이유와 기존 해결 행동을 계속 표시한다. 녹음 중 상태·단축키 충돌 경고·자동종료 안내·중단 알림, 입력 보류와 미전달 여부를 `?`에 숨기지 않는다. 도움말을 열어야 현재 실패를 알 수 있는 구성을 만들지 않는다.

## 클릭 시안의 실행 경계

클릭 시안의 초기 화면은 `설정 → 받아쓰기`다. 옵션 값 변경은 시안의 임시 화면 상태에만 반영하며, 도움말을 열어 둔 상태에서 바꾸거나 닫더라도 실제 앱 설정·Keychain·파일에 자동 저장하지 않는다. 실서비스 연결·API 요청·모델 다운로드·녹음·외부 앱 입력도 실행하지 않는다. 도움말 닫기를 저장 또는 실행 승인으로 사용하지 않는다.

이는 독립 시안의 조건이다. 실제 앱은 현재 `preferences.didSet`에서 저장과 기능별 후속 처리를 수행하므로, 기능 통합 때 기존 저장 의미를 별도로 검토해야 한다. 시안의 임시 상태를 이유로 앱 저장 동작을 바꾸거나, 도움말 조작이 실제 연결 성공을 증명한다고 표시하지 않는다. 근거: [AppModel.swift](../../../Sources/OpenNoType/App/AppModel.swift), `preferences.didSet`, 43–135행.
